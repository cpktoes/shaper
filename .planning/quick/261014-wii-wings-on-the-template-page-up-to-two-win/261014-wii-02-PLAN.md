- **P11 — The wing solve sits beside the outline's own in `outline-drag.ts` (the brief's "through outline-drag.ts"),
  with its own target type.** The VIEWER's five-target union `OutlineDragTarget` is switched exhaustively in
  `outline-viewer.tsx`, and the phone specs count `[data-drag-target]`. So the wing points are
  `WingDragTarget = { wing: number; point: "outer" | "inner" }`, hooked as `data-wing-grab`, and the VIEWER's
  points are untouched. The solve follows the file's two rules: one definition per formula (it imports the wing
  maths, never restates it), and every result slider-representable.
- **P12 — The snap grid is the slider's: `roundToSixteenthInch` in Imperial, `roundToWholeMm` in Metric.** These are
  what the sidebar's sliders write. A drag that changes depth or run also clamps the radius to the new
  `wingRadiusTop` (P8).
- **P13 — The close-up chooses a compact frame by its own room, not by width or pointer.**
  - When the full frame's fit (`min(box width / full width, box height / 620)`) would fall below
    `MIN_PINNED_FIT_SCALE` (0.66), it draws compact: top pad 16, left gutter 180, right rail 190, read-out values 96
    past the widest half-width, no station dimensions.
  - The decision reads the FULL frame's width, a fixed number per window, so there is no frame → fit → frame loop
    (the VIEWER's own T-VOT-04 rule).
  - The sketch's compact gutter (150) is too narrow for the app's pinned chip: 157.6 units at the floor, its left
    edge at −21.6 (measured F27). So it is 14 + 158 + 8 = 180.
  - This is the drawing fitting itself, like RAILS' plot fit. It never picks a layout, so CLAUDE.md's three
    switches stay separate.
- **P14 — Touch.** The close-up's svg is `touch-none select-none`, like TEMPLATE's VIEWER svg, so a thumb on a grab

  VIEWER's own `OUTLINE_DRAG_HIT_COARSE_PX` and `OUTLINE_DRAG_HIT_PX`. A touch is a direct drag only. The VIEWER's
  pick-then-drag-from-afar is not carried over: two small points per wing need no remote drag.
- **P15 — The desktop baselines.** Plan 01 re-recorded `outline-desktop-desktop-darwin.png` (its P7). This plan

<interfaces>
`lib/geometry/outline-drag.ts` (new exports; everything existing untouched):
- `type WingDragPoint = "outer" | "inner"`; `interface WingDragTarget { wing: number; point: WingDragPoint }`.
- `WING_GRAB_DROP_PX = 22` — the inner point's drop below the inner corner, in screen pixels. The caller converts it
  to millimetres at the live scale, exactly as it converts the hit radius.
- `wingDragPoints(geometry, wings, dropMm): { target: WingDragTarget; point: OutlineDragPoint }[]`.
  - Outer: at the station, the rail just nose-ward of the step (`wingReadouts`' width ahead / 2).
  - Inner: at the inner corner's station (station − run) − `dropMm`, the rail just tail-ward of the step (width
    behind / 2).
- `solveWingDrag(geometry, wings, target, point, dropMm, edges: FrontFinEdges | null, system): Wing[]` — F29 and P12.
  It returns the whole new wings array with only the dragged wing changed. Its radius is clamped to `wingRadiusTop`.
- `nearestWingDragTarget(points, touch, hitRadiusMm): WingDragTarget | null` — closest within reach. Ties go to the
  earlier entry, as `nearestOutlineDragTarget`.
