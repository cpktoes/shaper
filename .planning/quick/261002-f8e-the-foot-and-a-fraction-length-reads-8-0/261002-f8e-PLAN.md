<objective>
Fix one reading: a length whose inch part is only a fraction was written without its zero, so 96 1/8" read `8'1/8"`
— the fraction standing where the inches go, which reads like a misprint (eight foot one... eighth?). It was seen on
the ROCKER blank list for the US Blanks 8'0"H (`US Blanks · 8'1/8" · 3 5/16" center`). The same formatter writes a
board's own length everywhere, so the fix is one place: `formatFeetInches` in `lib/geometry/units.ts` (CLAUDE.md
Rule 2 — every format of a design value lives there).

After this plan it reads `8'0 1/8"` — eight foot and an eighth, the way a shaper writes it. A whole number of feet
stays `8'0"` exactly as today, and a length with whole inches is untouched.

Purpose: a number a shaper reads off the blank list, a card or a printed sheet is written the way they would write
it themselves, so nothing has to be re-read twice.

Output: one code commit on the main checkout plus this record. No new package, no geometry change, no database
change, no change to what any saved board holds, no push without the founder's go.
</objective>

<decisions>
Founder decision, to be confirmed at the go (the question this task was opened to settle):

- **F-1 — `8'0 1/8"`, not `8'1/8"`.** A shaper writes eight-foot-and-an-eighth with the zero. A whole number of feet
  stays `8'0"`. The work below is built on a yes; the push waits for the founder's word, which is where a no lands.

Planner rulings:

- **O-1 — One file, one function.** The change is inside `formatFeetInches` alone. `formatInchesFraction` is not
  touched: a bare `1/8"` is the right reading for a mark standing on its own (a rail band mark, a deck skin, a fin
  measurement), and its output is pinned by golden tests across the RAILS, FINS and VOLUME screens. The zero is added
  from the number (the inch remainder is under one inch but not zero), not by reading the formatted string back.
- **O-2 — Both spellings read.** `parseImperial` already reads `8'1/8"` (a bare fraction after the feet) and `8'0 1/8"`
  (a whole then a fraction); this task proves it with tests rather than changing it, so a length typed either way,
  before or after this change, is the same length.
- **O-3 — Everything else follows.** `formatLength` (`lib/geometry/measure-display.ts`), the one place a board's length
  becomes text, has `formatFeetInches` as its imperial branch, and every screen and print reads through it (enforced
  by `lib/units-isolation.test.ts`). No component changes.
- **O-4 — Records that quote the old reading stay as they were.** Phase 11's archived UI spec and summary quote
  `6'1/16"` as the reading of their day and even note that `6'0 1/16"` would be "a one-line change in
  `formatFeetInches` plus its tests, app-wide, and [the founder's] decision, not the planner's" (11-UI-SPEC.md, line
  377). They are the record of what was true then and are not edited.
</decisions>
