# Revert the colour palette to the currently published version

## Why

The five-colour brand palette (quick task 260823-t8j) was built, committed, and
never pushed. Production at https://shaper-coral.vercel.app deploys from every
push to `main`, so the live site never received it — the published site has been
running the previous palette the whole time.

The founder reviewed the five-colour scheme and decided against it. The ask is to
return `main` to exactly the published state, discarding the new palette rather
than parking it.

## What "published" is

`origin/main` at `12b6023`. The palette work sat in five unpushed commits on top
of it:

| commit | subject |
|--------|---------|
| `d11ecc0` | plan the new five-colour brand palette |
| `8d13ec9` | repoint palette tokens and lock the contract with a test |
| `4ba04a3` | split the one white surface into paper, chrome and mount |
| `f27a495` | move drawing strokes to blue and rescue two AA failures |
| `7665f23` | record the new five-colour palette |

No other branch contained them, so the reset makes them reachable only via the
reflog (`7665f23` was the tip).

## Decisions taken

Both were put to the founder before any change was made:

1. **Discard entirely**, rather than parking the work on a branch or reverting on
   top. `main` is hard-reset to `origin/main`.
2. **The AA test goes with it.** `lib/design/contrast.ts` and
   `lib/design/palette.test.ts` were born in `8d13ec9` and do not exist on
   published `main`. They were offered as keepable — the published palette does
   clear the AA bar (ink 18.88:1, muted 5.33:1, accent-ink 5.39:1, black on cyan
   12.28:1, construction stroke 5.18:1 on the board fill) so a retargeted test
   would have passed — but the founder chose to remove them.

## Task

Hard-reset `main` to `origin/main`, then verify the tree is healthy and the
published colours actually render.

## Ordering deviation from the standard quick flow

The usual flow commits planning artifacts *before* execution. That is impossible
here: the reset deletes every commit above `origin/main`, which would include its
own planning commit. So this PLAN.md and the SUMMARY.md are written *after* the
reset and committed on top of it. This is the only way the ledger survives the
operation it describes.

## Verification

- `git diff origin/main` is empty
- `lib/design/` no longer exists
- no dangling references to `surf-chrome`, `surf-sand`, `surf-accent-blue`
- `npm test` passes
- `npm run build` passes
- browser review confirms the published token values are live
