# Quick Task 260908-b35: Rail Example Callouts Never Crop Or Sit On A Line Summary

**Three small, independently-reviewable fixes to the INSTRUCTIONS tab's "Understanding Rail
Markings" figure: an opt-in 96-unit width pad so the apex-column names stop clipping, a restored
prototype axis-ceiling so no name lands in the tick-number row, and a per-anchor 8-unit lift so
four names stop printing through their own line and dot.**

## Performance

- **Tasks:** 3 of 3 completed
- **Files modified:** 5 (exactly the plan's `files_modified` list)
- **Commits:** 3 task commits + this docs commit

## Accomplishments

- All ten mark names on the example rail are now fully readable: the four apex-column names
  (Apex, Domed Taper, Rail Mk1, Tuck 1) read as whole words instead of being cut to a single
  letter by the SVG's own overflow clip.
- Bottom Tuck 1 and Bottom Tuck 3 stack above the x-axis with a real gap, restoring a rule the
  prototype had (`maxAllowedY`, Rails.dc.html line 1113) that the port had dropped.
- Deck 3, Deck 1, Bottom Tuck 1 and Bottom Tuck 3 — the four names anchored exactly on a drawn
  line — now read just above that line instead of straddling it and its own coloured dot.
- The VIEWER tab, the order form's first sheet and the View Full Sized dialog are provably
  unchanged at the geometry level: `computeRailPlotBounds` returns byte-identical bounds with no
  option or an explicit `calloutRoom: false`, and none of those three call sites was edited.

## The Three New Constants

| Constant | Value | Where it came from |
|---|---|---|
| `CALLOUT_RIGHT_PAD` (`components/rails/rail-section-plot.tsx`) | `96` viewBox units | Measured on the INSTRUCTIONS card: the widest right-hand name (Domed Taper) ended 79 units past the box's 486.8-unit right edge, so 96 clears that worst case with ~17 units to spare. Cross-checked against the prototype's own comparable allowance (120px of label extent budgeted right of the apex column when centring its scroll view, Rails.dc.html line 1141). |
| `RAIL_CALLOUT_AXIS_CLEARANCE` (`components/rails/rail-callouts.ts`) | `10` | The prototype's own `maxAllowedY = py(0) - 10` (Rails.dc.html line 1113) — ported verbatim, not re-derived. |
| `RAIL_CALLOUT_EDGE_LIFT` (`components/rails/rail-callouts.ts`) | `8` viewBox units | New, not from the prototype — a small offset sized to clear a drawn line and the dot sitting on it, applied only to the four anchors that sit exactly on a line. |

## Exact Signature Changes

**`computeRailPlotBounds(output, xAxisMin, options?)`** — added a third, optional parameter typed
`{ calloutRoom?: boolean }`, defaulting to the room being off:
- No third argument, or `{ calloutRoom: false }`: returns exactly today's box — `minX`, `minY`,
  `maxY`, `width` and `height` all unchanged, pinned by a test that asserts the two are `toEqual`.
- `{ calloutRoom: true }`: adds `CALLOUT_RIGHT_PAD` to `width` only. `minX`, `minY` and `maxY`
  never move — no drawn coordinate shifts, only the box grows to the right of the apex.

**`deOverlapCallouts(callouts, minGap, maxY?)`** — added a third, optional parameter, the lowest y
a label may occupy. Absent, the pass behaves exactly as it always has (all four pre-existing test
cases pass unedited). Supplied, after a cluster is stacked, if its lowest (largest-y) entry falls
past `maxY`, the **whole cluster** is shifted up by that overflow — never an individual label,
which would re-collapse the minimum-gap stacking that just ran.

**`RAIL_CALLOUT_ANCHORS`** — element type gained an optional `dy` (viewBox units). Set to
`-RAIL_CALLOUT_EDGE_LIFT` on exactly `deck3`, `deck1`, `bottomTuck1` and `bottomTuck3`; every
other entry carries no `dy`. The table's ten `key`/`name`/`side` values and their order are
byte-for-byte unchanged — the existing anchor-order test still passes unedited.

**`buildRailCallouts`** — the closing map now computes `y: py(pos.y) + (anchor.dy ?? 0)` instead
of `y: py(pos.y)`. Nothing added to `x`. The lift runs before `deOverlapCallouts`, so the restored
axis ceiling has the final say on where the two lifted bottom-edge names land after clustering.

## Files Confirmed Untouched (and why it matters)

- **`railPlotProjection`** (`rail-section-plot.tsx`) — its own line,
  `const { minX, maxY } = computeRailPlotBounds(output, xAxisMin);`, is byte-for-byte unchanged.
  It reads only `minX`/`maxY`, which `calloutRoom` never touches, so passing the option there
  would have been harmless but misleading — every rail-drawing anchor position (dots, segment
  lines, grid) stays exactly where it was.
- **`components/rails/rail-band-editor.tsx`** — the VIEWER tab's shared viewBox width and summed
  height come from `computeRailPlotBounds` with no options object, so its three stacked plots stay
  pixel-identical; a padded width here would have silently rescaled all three.
- **`components/rails/view-full-sized-dialog.tsx`** — divides the returned `width` by `SCALE` to
  print the rail at its TRUE physical size. It draws no callouts, so it never asks for the room,
  and an unconditional pad would have printed a board a shaper cuts foam to at the wrong scale.
- **`components/summary/rail-instructions-sheet.tsx`** — renders `ExampleRailFigure` for the order
  form's printed third sheet. Left untouched, it inherits all three fixes automatically, and its
  own source-contract test (`rail-instructions-sheet.test.ts`) stays green unedited.

## Did widening the box make the drawing render smaller?

Yes, and this is expected — it is the trade-off the plan's own design notes called out ahead of
time. `RailSectionPlot` renders with `fit="height"` on the INSTRUCTIONS card
(`height: 100%; width: auto; maxWidth: 100%`). Making the box 96 units wider (only when callouts
are drawn) means the same on-screen column now has to fit a wider box, so `maxWidth` clamps it and
the whole drawing shrinks a little to fit. A smaller drawing means a lower fit scale, and because
the callout font is pinned to a fixed screen-pixel size, the names themselves grow slightly in
viewBox units as the drawing shrinks — which is exactly why 96 units (not a tighter number) was
chosen: it clears the widest name down to a fit scale of roughly 0.78, well below the ~0.89 the
INSTRUCTIONS card measured at before this change. In plain English: the example rail drawing is a
touch smaller on screen than it was, so that its own labels have room to be read in full.

## Decisions Made

- The room is opt-in (an options object, `{ calloutRoom?: boolean }`) rather than a bare boolean,
  so a reader of `rail-band-editor.tsx`/`view-full-sized-dialog.tsx` can see at a glance those call
  sites ask for nothing extra.
- The axis-ceiling restoration and the line-lift are separate commits (Tasks 2 and 3): the ceiling
  is a parity fix (the prototype's own rule, ported verbatim), the lift is genuinely new design
  applied per-anchor rather than as a blanket offset — they are independently reviewable, and the
  lift is deliberately applied before the ceiling so the ceiling still has the final say on the two
  lifted bottom-edge names.
- No leader line was added when lifting a name off its line: the plot's `DimensionTick` moves with
  the name (intentional), and the mark's real position is already drawn as the coloured dot at
  every segment endpoint.
