# Quick 261006-v20: ROCKER's sidebar controls follow the tab in view — Summary

**On ROCKER, the sidebar now offers only what the tab on screen is about: on DATASHEET just Center
Thickness and the two tip thicknesses, on a phone's TOP VIEW just the blank picker and Placement, and on
VIEWER everything as before — every other control stays in its place, dimmed and locked.**

The founder's words, 2026-10-06: "we also need to limit some controls. For all screens, when on the
datasheet tab, only make live the 3 thickness values you can edit. WHen on the top view tab, only make
the placement slider and blank picker live."

## What a shaper now sees

- **VIEWER (computer and phone):** exactly as before. Every sidebar control works; the desktop reference
  picture of ROCKER is pixel-identical.
- **DATASHEET (computer, upright phone, phone held sideways):** the sidebar's Center Thickness (typed box
  and slider) and THICKNESS's Nose Tip and Tail Tip sliders work. Everything else in the sidebar — the
  blank card and its Change Blank / Remove This Blank, Placement, Deck Skin, the hand-set ROCKER lifts
  (no blank), the 12" rows, Fine-tune off, Reset Fine-Tune, Tip Style and both Thinning Starts — is
  dimmed and can't be clicked, tapped, dragged or reached with the keyboard. The table's own typed cells
  keep working, and typing Center Thickness in the sidebar changes the table's Center cell.
- **TOP VIEW (only on an upright phone, a phone held sideways, or a narrow or short window):** the whole
  BLANK section and the Placement slider work; Center Thickness, Deck Skin, ROCKER and all of THICKNESS are
  dimmed and locked.
- Nothing moves when the tab changes (dimmed, never hidden). BOARD ON BLANK's readouts and planer-passes
  line are text and stay undimmed. A window widened while on TOP VIEW lands on VIEWER with every control
  working again. Nothing is saved; no board value changes.

## Two places the founder may want to overrule

1. **D-12 — the hand-set 12" rows with no blank.** With no blank picked, the DATASHEET table types all
   five thicknesses, but the sidebar's own Nose @ 12" / Tail @ 12" rows are dimmed on DATASHEET, because
   the founder said "only make live the 3 thickness values". Changing that is one value in
   `components/rocker/rocker-live-controls.ts`.
2. **D-09 — a control that was already dimmed looks one shade fainter.** The "Placement — pick a blank
   first" row (DATASHEET, no blank) and "↺ Reset Fine-Tune" when there is nothing to reset were already
   dimmed for their own reasons, so on DATASHEET they read one shade fainter than the other dimmed rows
   (visible in `rocker-desktop-datasheet-thickness.png`). The plan named the Placement case; the Reset
   Fine-Tune case is the same effect, noted here for completeness.

## Deviations from Plan

1. **[Test value] Tail Tip typed as 7/8" instead of 5/8".** Found while writing the DATASHEET test: 5/8" is
   the default board's own tail tip (`lib/geometry/foil.ts`), so typing it would prove nothing. The test
   first asserts the sidebar does not read 7/8", types 7/8" into the table's Tail Tip cell, and checks the
   sidebar's label reads `Tail Tip — 7/8"`. Commit b021b9b.
2. **[Pictures] The iPhone pictures use a 390 × 2000 window.** At the iPhone 14's own 390 × 844, the
   sidebar's window under the pinned drawing (and over the development-only footer) is about 120 dots tall,
   so the first takes showed one heading and almost no controls. A taller window at the same width keeps
   the same layout rules (width picks the layout, pointer the sizing, and 2000 tall is not a short screen)
   and shows the controls the plan asked for.
3. **[Commits] Task 1's table and its wiring went into one commit (f5296de)** rather than two, as the plan
   allowed ("commit the wiring if it was not part of the previous commit").

No Rule 1–4 code deviations: the code matches the plan's decisions as written.
