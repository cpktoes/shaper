<objective>
Make ROCKER's sidebar follow the tab in view: on DATASHEET only the three thicknesses a shaper can type into the table
(Center, Nose Tip, Tail Tip) stay live in the sidebar; on TOP VIEW only the blank picker and the Placement slider; on
VIEWER everything, as today. Every other control stays where it is, dimmed and inert. The rule is the same on a
computer, an upright phone and a phone held sideways.

The founder's words, 2026-10-06: "we also need to limit some controls. For all screens, when on the datasheet tab, only
make live the 3 thickness values you can edit. WHen on the top view tab, only make the placement slider and blank picker
live."

Today every sidebar control works on every tab. On a phone the sidebar sits under the drawing, so a shaper reading the
DATASHEET or the blank from above can scroll into a slider that changes something the tab in view doesn't show. After
this task the sidebar offers only what the tab is about, and the rest stays visible but quiet.

Purpose: the tab in view decides what the shaper can change, so a change always lands where they are looking.
Output: one pure table and its unit test; one small wrapper; edits to three ROCKER files; one new browser spec; four
pictures for the founder; the SUMMARY.

D-01 to D-07 are the orchestrator's locked decisions, numbered as it gave them. Do not reopen them. D-08 to D-15 are the
planner's, from reading the code.

- **D-01 Which controls are live, by the tab in view.** The tab is `activeTab` in `rocker-editor.tsx`, the DERIVED one,
  never `requestedTab`.
  - VIEWER: everything, exactly as today.
  - DATASHEET: live = the Center Thickness section (its typed field and slider) and the THICKNESS section's `Nose Tip`
    and `Tail Tip` `ThicknessRow`s. Not live = the BLANK section (the whole `BlankPicker`), BOARD ON BLANK's Placement
    and Deck Skin sliders, the ROCKER section (the four hand-set lifts, shown only without a blank), and within THICKNESS
    the two `FineTuneRow`s, the Reset Fine-Tune button, the Tip Style toggle and the two `ThinningStartRow`s. The
    DATASHEET table in the panel is untouched; its own typed cells keep working.
  - TOP VIEW (small screens only; the tab exists only there): live = the whole BLANK section (search, list, Show all,
    Change/Keep, Remove, the flag's Switch to This Blank) and the Placement slider. Not live = Center Thickness, Deck
    Skin, ROCKER, and all of THICKNESS.
  - "On every screen size": the same rule wherever the tabs exist: a computer, an upright phone, a phone held sideways.
- **D-02 Not live means dimmed and inert, never hidden.** The controls stay on the page at their size, so nothing shifts
  when a shaper switches tabs and they can still see what is there. They dim to the app's own `opacity-40` (the dimming
  that Reset Fine-Tune and `SliderRow`'s `disabled` use) and are made inert with the HTML `inert` attribute: no focus, no
  clicks, no keys, out of the accessibility tree. React 19.2 renders the boolean `inert` prop (`@types/react` 19.2
  types it `inert?: boolean`); Safari 15.4+, Chrome 102+ and Firefox 112+ honour it. Implement it once as a tiny
  wrapper and wrap each group. No per-control `disabled` threading, and no change to `SliderRow` or `Slider`.
  - A section's heading (its collapse toggle) goes inside the wrapper when the WHOLE section is not live: BLANK, ROCKER,
    Center Thickness, and all of THICKNESS on TOP VIEW.
  - Where only part of a section is not live (THICKNESS on DATASHEET; BOARD ON BLANK on either tab), the heading stays
    live and the wrappers go round the rows.
  - BOARD ON BLANK's readouts and planer-passes line are text, not controls: they stay undimmed.
  - Read-only text inside a dimmed section (hints, the catalogue note) dims with its section.
- **D-03 Plumbing.** `RockerControls` gains one prop, `tab: "viewer" | "datasheet" | "topView"` (the editor passes
  `activeTab`), and derives every flag from it through one pure helper, `liveControls(tab)`, in a new UI-state module,
  `components/rocker/rocker-live-controls.ts` (pure, no React import; it is UI state, not geometry, so it does not
  belong in `lib/geometry/`). Its unit test, `rocker-live-controls.test.ts`, pins the three tables exactly.
  `BoardOnBlankSection` gains `live: { placement: boolean; deckSkin: boolean }` (default both true, so the existing call
  shape still works) and wraps its two sliders. Its no-blank and no-room branches already render a `disabled` Placement
  slider; wrapping a disabled slider in an inert dim is harmless and keeps one rule.
- **D-04 Nothing is saved; nothing in the store changes.** Liveness is view state derived from the tab. The
  DATASHEET's own cells, the VIEWER's toolbar and the drawings are untouched. No other screen changes.
- **D-05 Browser proof** is a new `e2e/rocker-live-controls.spec.ts`, with `261006-v20` in every describe title, reusing
  the helpers from `rocker-top-view.spec.ts`. A control is inert when `el.closest("[inert]")` is not null; assert both
  ways (live controls have NO inert ancestor). Keep every test under the suite's default 30 s. Run the regression specs
  below. Fix any failure in the CODE, never by loosening an assertion. The one exception is a test that itself drives a
  sidebar control while DATASHEET is open: it must now switch to VIEWER first (the planner's grep found none; see
  `<context>`). Name any such test in the SUMMARY.
- **D-06 Pictures for the founder**, by the scratch-config recipe 261006-qfm used, into this task's `pictures/`. Look at
  each one before committing it.
- **D-07 No desktop reference picture changes.** `e2e/desktop-baseline.spec.ts` shoots ROCKER on VIEWER with no blank,
  where every wrapper is live. Prove it by running that spec on the desktop project, all five pictures passing, none
  re-recorded.
- **D-08 The wrapper lives in its own file, `components/rocker/live.tsx`, not inside `rocker-controls.tsx`.**
  `board-on-blank.tsx` needs it too, and `rocker-controls.tsx` already imports `board-on-blank.tsx`; defining it in
  `rocker-controls.tsx` would make the two files import each other. It is still implemented once (D-02).
- **D-09 A group is dimmed once, never twice.** On TOP VIEW the whole THICKNESS section is wrapped AND its rows are
  wrapped, and nested `opacity-40` would compound to 16%. `Live` reads a small React context: a `Live` inside a not-live
  `Live` carries `inert` and `data-live="false"` but adds no opacity of its own. Only the outermost not-live wrapper
  dims. (The one double dim D-03 accepts is a `disabled` Placement slider inside a not-live wrapper: `SliderRow`'s own
  dim plus the wrapper's. It shows only on DATASHEET with no blank, or with a blank too short to slide along.)
- **D-10 The wrapper is layout-neutral: `flex flex-col`, not a plain block `div`.** Every group it wraps is a flex item
  of a `flex flex-col` parent today. A `flex flex-col` wrapper around one item keeps that item stretched to the full
  width, keeps its `self-start` working (the Reset Fine-Tune button), and adds no line box. A plain block `div` would
  lose `self-start` and give the inline Reset button a line box taller than its text, moving the rows under it. On
  VIEWER the wrapper carries no `inert`, no opacity and no stacking context, so the desktop picture cannot change.
- **D-11 One wrapper per row inside THICKNESS and BOARD ON BLANK; never one wrapper round several rows.** The rows are
  spaced by their parent's `gap-3.5`; wrapping each row on its own leaves that gap exactly where it is.
- **D-12 The THICKNESS section's 12" stations in both states share one flag, `fineTune`.** The flag covers the two
  `FineTuneRow`s with a blank, the two hand-set `Nose @ 12"` / `Tail @ 12"` `ThicknessRow`s without one, the
  Fine-tune off pair and ↺ Reset Fine-Tune. It is not live on DATASHEET or TOP VIEW. D-01's DATASHEET list of live
  controls is exhaustive, and the founder said "only make live the 3 thickness values". So with no blank, the sidebar's
  two hand-set 12" rows are dimmed on DATASHEET, even though the table itself types all five thicknesses then. This is
  the planner's reading, flagged in the SUMMARY for the founder to overrule: changing it is one value in the table.
- **D-13 The THICKNESS heading and its intro line follow a derived flag, `thicknessHeading`:** live whenever any of the
  section's rows is live (true on VIEWER and DATASHEET, false on TOP VIEW). It is computed inside `liveControls` and
  pinned by the unit test, so the component never works out an OR of its own.
- **D-14 `RockerTab` gets one definition**, exported from `rocker-live-controls.ts`. `rocker-editor.tsx` imports it in
  place of its own local type.
- **D-15 No checkpoint inside this plan.** Both tasks are `type="auto"`. The founder judges the pictures after the merge.
