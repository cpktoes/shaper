# Quick Task 260830-03j: Rocker cards hold their size when the board is turned nose-up

**Turned nose-up, the ROCKER screen's station cards and their inch figures now hold the same on-screen size the TEMPLATE screen's own callouts already do, instead of shrinking to about two-thirds size with the tall, narrow board.**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-08-30
- **Tasks:** 2 of 3 completed (Task 3 is a browser checkpoint, deferred — see below)
- **Files modified:** 3

## Accomplishments

- Added a card-pin scale to the rocker drawing's math (`rocker-view-frame.ts`): a new `maxCardPinScale` works out how far a station card can grow before it would touch its neighbour, and `cardPinScale` works out the scale that lands the card's number at the same size the Template screen's own labels use.
- Wired that pin through `rocker-viewer.tsx` so the ROCKER screen measures its own panel, works out the right size, and redraws the cards and their numbers at that size — automatically, with no user action.
- Made sure the drawing's outer frame never changes shape because of this — it is always reserved at the largest the cards could ever grow to, so growing a card's text can never trigger a resize loop or shrink the board itself.
- Proved by test that turning the board sideways (nose-left) draws exactly as it always has, and that the printed order form on the Summary page is completely unaffected — the pin can never reach either of those.

## Files Created/Modified

- `components/rocker/rocker-view-frame.ts` - Added `maxCardPinScale` (the station-pitch ceiling a card can grow to), `cardPinScale` (the scale that lands a card's number at a target on-screen size), a `cardScale` input on `rockerViewLayout`, and new `cardScale`/`cardType` fields on its output. Every frame extent (`cardBandDepth`, the vertical cross-axis and long-axis reserves) is now derived from the ceiling, not the live scale.
- `components/rocker/rocker-view-frame.test.ts` - 24 new tests: the card-pin math itself, the layout's new scale/type-stack fields, and (Task 2) four safety suites proving the frame never changes shape at any card scale, the nose-left drawing is byte-identical at any scale, the printed order form can never be reached by the pin, and neighbouring cards never collide even at the largest scale the pin allows.
- `components/rocker/rocker-viewer.tsx` - Measures its own panel once (a quick "frame pass"), works out the right card scale from that measurement, then draws the board a second time at that scale. `StationCard` and `StationReadout` now take their type sizes and text positions from the layout's own `cardType` field instead of fixed numbers.

## Decisions Made

- One scalar (`cardScale`) moves the card box and its whole two-line text stack together, so a number can never grow past the edge of its own card — the plan's own design decision, implemented as specified.
- The drawing's frame always reserves room for the largest the cards could ever grow to (the "ceiling"), never for whatever size is actually showing — this is what keeps the screen from ever getting into a loop where a bigger card makes a bigger frame which measures a different fit which changes the card size again.
- Nose-left, the ceiling works out to exactly 1.0 (not just "close to 1" — the same underlying number twice), so that view is provably untouched by this whole change, not merely unchanged by convention.
