# Quick task 260909-ok2 — a diamond tail's angle stays fixed under the drag point

**Founder's report:** "on diamond tail, the tail angle can be changed via the drag control, but the
slider is greyed out, it's supposed to be fixed when greyed out." Then: "actually, desktop also has
this last issue."

**Why the slider is greyed:** the prototype pins the tail angle for a diamond tail
(`tailAnglePinned: s.tailType === 'diamond'`) and its Diamond button sets 30° — the app's
`TAIL_PRESETS.diamond` does the same and greys the Tail Angle slider. But `solveOutlineDrag`'s
tail-handle case read a new angle off the drag vector regardless of the tail kind, so a mouse or a
thumb could drag the drawing into an angle no control could reproduce.

**Fix (Rule 1 — in the geometry, tested):** `OutlineGeometry` gains `tailAnglePinned` (a diamond)
and `tailAngle` (the angle it was built with). When pinned, the tail-handle solve keeps that angle,
turns only the travel ALONG the fixed direction into fullness, ignores sideways travel, and returns
`tailFullness` alone. The touch readout card names only Fullness for a pinned tail.

Executed inline by the orchestrator: three small edits in the geometry and one in the viewer, with
the founder testing live.
