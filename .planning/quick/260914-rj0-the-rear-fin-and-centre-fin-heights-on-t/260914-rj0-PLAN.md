<objective>
Stop the rear-fin and centre-fin height numbers on the fin drawing from printing on top of each
other on a phone.

Purpose: on FINS the drawing calls out how far each fin sits up from the tail — the single most
important number on that screen, because it is what a shaper measures to when marking a blank. On
the Mid-length board (a quad with a centre fin) two of those three numbers currently land 1.48
drawing units apart on a phone and print over one another, reading as `6 1/4"5/8"`. A shaper
looking at that has no idea where either fin goes.

Output: one small pure rule that nudges an off-tail number along its own dimension line only when
it would actually collide with another one, wired into the fin drawing, and a browser test that
measures the real ink on a real phone in both Imperial and Metric and proves the numbers are
clear. Nothing changes for a mouse.
</objective>

<honest_scope>
Worth saying plainly what this is and is not, before anyone starts.

It is NOT a re-design of the fin drawing. The sideways tier stagger stays, the dimension lines stay
exactly where they are, the type size stays pinned at 14 screen pixels, and every other callout on
the screen — toe-in, off-rail, the rear pair's spread — is untouched. The ONLY thing that moves is
the vertical baseline of an off-tail height number, and only when it would otherwise be unreadable.

It is also NOT a media query. This is the easiest mistake available here, so it is called out up
front: CLAUDE.md keeps three switches strictly apart — width picks the LAYOUT, pointer picks the
CONTROL SIZE, height picks whether a short screen scrolls — and none of the three answers the
question this task asks. The question is "is this number wide enough, in the drawing's own units,
to run into that one?", which is answered by the label geometry alone. A phone held sideways lands
in the DESKTOP shell (about 844 dots on an iPhone, 863 on a Pixel 7) and still needs this fix,
because the drawing there is short and the type is still large. Anything keyed to `max-shell:` or
`coarse` would miss it, and would also be a fourth meaning bolted onto a switch that already has
one. Do not reach for one.

The genuinely fiddly part is the resolution pass: pushing a label only as far as it has to go, in
the right direction, without walking it off the end of its own dimension line, and getting the same
answer if the rule runs again. That is why it is a pure module with its own tests and a table of
expected numbers already computed — it is not to be "simplified" into a single downward sweep during
execution, because a single sweep drives the centre label straight through the tail line on an
iPhone.
</honest_scope>

    `FinLabelBox` carries, per label: `y` (its baseline as the drawing already computed it), `x`

    The rule:

    1. Two labels INTERACT only if their estimated x-ranges (`[x - width, x]`) actually overlap.
       Labels that do not overlap sideways are never moved, whatever their baselines are, and no
       order is forced between them. This predicate is load-bearing: without it a plain monotone
       sweep would move the desktop labels and break the screenshot baselines.
    2. Per-label bounds are `lineTop + FIN_LABEL_INK_TOP_EM * fontSize` (lower bound on the
       baseline) and `lineBottom - FIN_LABEL_INK_BOTTOM_EM * fontSize` (upper bound). A bound that
       the label's UNTOUCHED baseline already violates is relaxed to that untouched baseline, so
       the rule can never move a label to a worse place than it started in.
    3. Forward pass, in the given order: push each label DOWN only as far as its interacting
       predecessors demand (at least `FIN_LABEL_CLEARANCE_EM * fontSize` below each), clamped to
       its upper bound.
    4. Backward pass, in reverse: push each label UP only as far as its interacting successors
       still demand, clamped to its lower bound.
    5. Bounds always win over clearance. If a clamp stops a label short of the full clearance, it
       stops there — the rule never pushes a number off the end of its own dimension line to buy
       air.
