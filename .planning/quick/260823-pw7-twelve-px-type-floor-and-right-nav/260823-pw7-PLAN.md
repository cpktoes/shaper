# Quick Task 260823-pw7 — a 9pt floor, and the nav to the right

## 1. Nothing prints below 9pt (12px)

The smallest printed text is 7.9px. Bringing that to 12px is a ~50% increase across most of page 1 —
which is the densely packed page — so the real work is not the numbers, it is whether the sheet still
fits afterwards.

**The floor goes in the clamp minimum, not just the coefficient.** `clamp(12px, …, …)` holds at any
container width, so the guarantee does not depend on the sheet being printed at the width it was
calibrated for. The `cqw` coefficients are set so the printed size lands on 12px too
(`1.636cqw` × 733.448px = 12.0px).

A consequence to accept rather than fight: the floor compresses the bottom of the scale, so `micro`,
`caption` and `group` all land on 12px and are no longer separated by size. Weight and colour already
carried most of that distinction at 8px.

## The bug this uncovers

`useOrderFormPrintFit` pins each **sheet** to the page box but leaves the **root** — the `@container`
every `cqw` size resolves against — at whatever width the print viewport hands it. So the printed type
size is not actually knowable from the design, and if the print viewport were wider than expected the
sheet would overflow, the hook's guard would zoom it down, and the type would drop back under the
floor it is supposed to hold.

The root gets pinned to the printable width too, restoring the invariant the hook's own head comment
describes: the layout it measures is the layout that prints.

## 2. Nav menu right-justified

`justify-between` on the nav, so the wordmark stays left and the links go right.
