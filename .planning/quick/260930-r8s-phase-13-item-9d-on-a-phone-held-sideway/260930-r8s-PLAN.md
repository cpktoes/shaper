- **P-2 — The phone menu does NOT carry the six screens today.** Its contents, top to bottom: Home (left out on `/`),

  Tip Defaults), Blank Makers, a divider, the account control. This plan adds the screens group above Home.
- **P-3 — A hidden row stays a real menu item, hidden by CSS, not left out of the tree.** Base UI 1.7.0 (installed)
  treats a row that is not drawn as unavailable: its arrow-key navigation (`floating-ui-react/utils/composite.js`,
  `isListIndexDisabled` calls `isElementVisible`, which uses the browser's `checkVisibility()`) and its type-to-jump
  (`useTypeahead` checks `isElementVisible` too) both skip it, and a row that is `display: none` is out of the
  accessibility tree. So on an upright phone the six rows are simply not there for a finger, a keyboard or a screen
  reader. Each ROW carries `hidden shell:flex` itself (not only its group), so the row's own computed display is
  `none`: older Safari without `checkVisibility()` falls back to reading the element's own display, and a row hidden
  only through its parent would read as visible there. Leaving the rows out of the tree instead would need a
  JavaScript screen-width check, a second copy of the 820 number outside `app/globals.css` (whose compiled-CSS guard
  owns it), against the house rule that CSS alone decides what paints.
- **P-4 — No visible "Screens" heading; the group is named for screen readers only.** Measured with the phone menu open
  sideways (after the change, emulated): the menu's visible box is 324 dots tall on an iPhone at 844x390 and 294 on a
  Pixel 7 at 863x360 (it starts about 60 dots down and stops at the screen's edge, so at 844x340, an iPhone with
  Safari's bar showing, it is about 274). Each row is 44 dots under a touch pointer; six rows plus the menu's 6-dot
  top padding is 270, so all six fit whole in the first view on all three. A 27-dot heading like Units' would push
  SUMMARY 3 dots under the fold on the Pixel 7 and about 23 on the iPhone with Safari's bar. So the group carries
  `aria-label="Screens"` (Base UI's `Menu.Group` passes it straight to its `role="group"` element) and no visible
  heading, the same way the Home/Contact/Privacy group above the settings already has none. The rest of the menu
  scrolls inside itself below the six, as it already does on a phone (quick 260926-wmf).
- **P-5 — How a row looks and what it does.** Row box: the Home row's classes, with its leading `flex` swapped for
