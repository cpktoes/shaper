# BOTTOM's GUIDE adopts the shared GUIDE card

## Goal

Phase 17 built BOTTOM's GUIDE first with its own card (`components/bottom/bottom-guide.tsx`); Phase 18 built the same
card as a shared component under `components/guide/` for the five other pages. With both on `main`, BOTTOM's nineteen
cards render through the shared `GuideTab` / `GuideCard`, its own `BottomCartoon` kept as the drawing, and the private
card goes. No change to what a BOTTOM card says or draws; `e2e/bottom-guide.spec.ts` stays green.

## Tasks

1. **The shared card takes a drawing of its own.** `GuideViewCard.figure` may be `null`; `GuideCard` takes an optional
   `art` node drawn in place of `GuideCartoon`; `GuideTab` takes `renderArt(card)` and spreads optional root data
   attributes, and its `page` widens to `GuidePage | "bottom"` for the region's spoken name (`Guide to Bottom`).
   Files: `components/guide/guide-view.ts`, `guide-card.tsx`, `guide-tab.tsx`, `guide-copy.ts`.
2. **BOTTOM renders through it.** `bottom-guide.tsx` builds `GuideViewGroup[]` from `BOTTOM_GUIDE_WORDS` (id = the cut's
   name, tag `On this board` or none, no caption, lines from `guideHow`) inside one memo keyed on the board, the bottom
   and the system, with each card's `BottomCartoon` element made in the same memo so a memoised card redraws only when
   the board does; `data-bottom-guide` stays on the scroller; the private `GuideCard` is deleted.
3. **Prove it.** Unit: the guide and bottom test files, `tsc`, lint. Browser: `e2e/bottom-guide.spec.ts` on the
   computer and both phones (webpack test server on its own port).

## Verify

- Every BOTTOM card's name, two sentences, How to shape note, tag and cartoon read exactly as before (the spec reads
  them from the words module).
- Nothing in the list can be pressed; the scroller alone scrolls.
- The five other pages are untouched: their `GuideTab` calls pass no new props.
