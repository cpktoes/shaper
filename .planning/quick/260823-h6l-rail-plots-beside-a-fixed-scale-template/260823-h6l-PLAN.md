# Quick Task 260823-h6l — rail plots left, fixed template window right

Page 1's body becomes one row: the three rail section plots stacked in a left column at about a
third of the width, and the template window beside them at about two thirds. The template window
gets a **fixed frame** — one size, sized once for the extremes of the board ranges, instead of one
that shrinks to whatever board is loaded.

## Decision (from the user — locked)

**Fixed window, per-board scale.** The frame stops changing shape with the board, so the sheet's
layout never shifts. Each board still fills the window's height, so every board prints as large as
the window allows — which is what the last several changes have been for. A narrower or shorter
board simply leaves more blank paper inside the frame.

The alternative — one scale across all boards, so a 6'0" reads visibly shorter than a 9'6" — was
considered and declined: honest relative sizing is not worth printing the common shortboard at 60%
of the size it prints today.

## What "fixed" is sized from

The board ranges the outline editor already enforces: length 60–120", widepoint width 16–25".

Per-board scale means the scale is highest for the *shortest* board, so the widest *rendered* case
is the shortest-and-widest board — 60" long at 25" wide — not the widest one. The frame is sized
from that, and every other board fits inside it by construction.

Those bounds are currently magic numbers inside `outline-controls.tsx`'s sliders. They move to
`lib/geometry/board.ts` as exported constants so the viewer has a legitimate source for them and the
sliders stop being the only place they are written down.
