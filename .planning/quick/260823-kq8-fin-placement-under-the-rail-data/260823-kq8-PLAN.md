# Quick Task 260823-kq8 — fin placement under the rail data

Page 2's two tables were side by side. Fin Placement moves underneath Rail Bands, so each gets the
full width of the page.

The reading order this produces also matches the order a blank actually gets worked: bands marked
first, fins set last.

## Approach

Wrap both `FormBox`es in a flex column inside the existing row, so the `SHAPING DATA` spine label
still runs down the whole page beside them.

## The consequence to handle

Going full width stretches every row of the fin table: the label sits at the far left and the
measurement at the far right, most of a page apart. That is the shape that makes a reader's eye slip
a line — and a shaper reading the wrong fin number off this sheet drills the wrong hole. The rail
table does not have this problem, because its three section columns already occupy the middle.

So the fin sections run in **columns** within their panel, keeping each label within reading distance
of its own number. `columns`, not a fixed grid: the section count is not fixed — a single fin
produces one section, a thruster two, a quad with its centre fin three — and `break-inside: avoid`
keeps a section whole rather than splitting its rows across the fold.

The panel's footnote stays *outside* the columned container, so it reads as a note on the whole panel
rather than on whichever section happened to end last.
