<objective>
Put a per-visitor limit on the one thing a signed-out visitor can make this server do that costs the founder
something: sending a Contact-form message through Resend's free plan. At most five sends per visitor per hour.
A sixth gets a kind line on the form and keeps the typed message. The limit's file also records, in one place,
why nothing else a signed-out visitor can reach needs a limit.

Purpose: batch C of the founder's 2026-10-06 request. In their words: "Add rate limiting to any API route that
can be called without being logged in". Separately decided with them: the blank list stays as it is. The app has
one API route (Clerk's signature-checked webhook). Every other server entry point is a Server Action, and the
Contact send is the only one that does costly work for a signed-out caller. So it is the only one to limit.

Output: `lib/contact/rate-limit.ts` (pure, unit-tested) and its tests; the limit step in `submitContact`; the
refused line and status; the request-time glue; the form's line; and the browser proof in `e2e/contact.spec.ts`.

The orchestrator's rulings for this quick task, numbered here for traceability (there is no CONTEXT.md):

- **D-01 — A pure decider, sliding window per visitor.** `lib/contact/rate-limit.ts`: at most `CONTACT_SEND_LIMIT = 5`
  sends per visitor per `CONTACT_SEND_WINDOW_MS = 60 * 60 * 1000`, each a named constant with a one-line reason.
  The clock and the store are injected: the caller passes the time in milliseconds and the `Map`. Fully unit-tested
  with a fake clock.
- **D-02 — Request-time glue mirrors `lib/contact-server.ts`.** The visitor is the first address in
  `x-forwarded-for`, else `x-real-ip`, else one shared `"unknown"` key. All visitors live in ONE in-memory `Map`
  hung on `globalThis` (the practice rack's pattern in `lib/rack-stand-in-server.ts`), so it survives a hot
  reload and is shared by every copy of the module.
- **D-03 — Where it fires.** Inside the send path, after the honeypot and before delivery. Planner's reading,
  following the brief's own reason ("an honest attempt that would reach Resend is what costs"): it also comes
  after the field checks and the availability check, because neither of those reaches Resend. A shaper who
  mistypes their email never uses up a send. Order: attempt → honeypot → fields → availability → **limit** →
  deliver.
- **D-04 — What a refused send looks like.** The form's own answer, never a 429 page or a stack trace. It uses a
  new status, `"limited"`, and a new line in `CONTACT_COPY`, shown in the same `role="alert"` spot as a failed
  send's line. The text is pinned by a unit test in the same way `lib/privacy/copy.test.ts` pins
  `CONTACT_COPY.privacy`.
- **D-05 — Browser proof.** `e2e/contact.spec.ts`, with the stand-in on. Every test is its own visitor: a fresh
  address is set with `page.setExtraHTTPHeaders` in the existing `beforeEach`. The new case sends five times, then
  once more, then once as a different visitor.
- **D-06 — Say plainly what it does and does not do.** The new file's opening comment covers both. It also lists
  the signed-out server entry points and why each needs no limit, read from each file's own first lines, never
  assumed. The repo has no `docs/` folder, so the opening comment is the one place this is recorded.
- **D-07 — Out of scope.** No new package. No shared store service. The blank list stays as it is (the founder,

Planner's discretion, recorded so the founder can overrule:
- The refused line names the support address as a link, like the failure line, so a shaper at the limit can still
  write at once: "That's a few messages in a short time. Please try again in about an hour, or email us at"

- A refused attempt is NOT recorded, so retrying while limited never pushes the wait further out.

- Next 16's own server fills `x-forwarded-for` only when it is missing
  (`node_modules/next/dist/server/base-server.js:612`, `req.headers['x-forwarded-for'] ??= ...socket.remoteAddress`).
  So on the local dev server a header the browser test sets reaches `headers()` unchanged, and a request without
  one is keyed by its loopback address (`::1` or similar), not by `"unknown"`.
- Vercel's request-headers documentation: Vercel overwrites `X-Forwarded-For` and does not forward external IPs,
  "to prevent IP spoofing"; `x-real-ip` is identical to it. On the live site a visitor cannot dodge the limit by
  sending their own header.
- `headers()` from `next/headers` is async, returns a read-only Web `Headers`, and is read with `.get(name)`
  (`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/headers.md`). `cookies()` is already read
  the same way in `lib/contact-server.ts`.
- Playwright: `page.setExtraHTTPHeaders(headers)` adds the headers "to every request the page initiates". That
  includes the Server Action's POST.
- `playwright.config.ts` runs `iphone` (WebKit), `android` and `desktop` against ONE dev server, `workers: 1`, and
  reuses an already-running server locally (`reuseExistingServer: !process.env.CI`). Without a per-test address,
  the existing "sent" and "failed" cases (one counted send each, per project) plus the new case would add up past
  five on one key, and a reused server carries counts from one run into the next.
- `lib/contact/delivery.test.ts` boundary (d) fails if any non-test file in `lib/contact/` imports react, next,
  next/* or @clerk/*. `rate-limit.ts` imports nothing at all. Boundary (c) fails if anything under
  `components/` imports `lib/contact/delivery` or `lib/contact-server`. The form imports neither.
- `content/legal/privacy.md` ("Usage information") already tells visitors that the hosting provider records their
  IP address and that it is used "to keep the Service running". Holding an address in memory for at most an hour
  to keep the form usable fits that, as long as it is never logged, stored or sent to the browser.
- Signed-out server entry points today (read from each file): the one API route `app/api/webhooks/clerk/route.ts`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor → Contact Server Action | Anyone can POST the action directly, signed in or not. The form fields and `previous` state are untrusted. |
| Vercel edge → app | `x-forwarded-for` / `x-real-ip` are set by Vercel, which overwrites a visitor-supplied value. On the local dev server they pass through from the client (used by the tests). |
| app → Resend | Each allowed send is one call against the founder's free Resend plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-g5q-01 | Denial of service (cost) | `submitContact` → Resend | high | mitigate | `takeContactSendSlot` allows 5 per visitor per hour, asked after availability and before `deliver` (Task 1). Wired via `allowSend: takeContactSendSlotForRequest` (Task 2). |
| T-g5q-02 | Spoofing | visitor key from `x-forwarded-for` | medium | mitigate | On Vercel the header is overwritten by the platform (documented "to prevent IP spoofing"), so a bot cannot pick a fresh key per request. Only the first entry is read, and it is cut to 64 characters. |
| T-g5q-03 | Denial of service (memory) | the `globalThis` Map | medium | mitigate | Every call prunes sends older than the hour and drops empty visitors. A hard cap of `CONTACT_SEND_MAX_VISITORS` (10,000) forgets the visitor longest without a send. Pinned by unit tests. |
| T-g5q-04 | Information disclosure | visitor addresses in memory | low | mitigate | Held in memory only, for at most an hour. Never logged (the one warn line names no address), never written to the database, and never returned to the browser (`ContactFormState` carries no address). Fits `content/legal/privacy.md`'s usage-information paragraph. |
| T-g5q-05 | Denial of service (real shapers) | shared keys (`"unknown"`, one office or café address) | low | accept | Five an hour per address is well above a real shaper's use. A refused shaper keeps their typed message and sees the support address to email instead. |
| T-g5q-06 | Denial of service (cost) | many addresses, several Vercel instances | medium | accept | Per-instance memory can't see other instances or count across addresses. A shared store needs a new service, out of scope before the 2026-10-07 freeze (D-07). If Resend's allowance runs out, the existing failure line shows the address. Recorded in `rate-limit.ts`'s header. |
| T-g5q-07 | Tampering | test-only stand-in | low | accept | The limit runs before delivery for every delivery kind, including the stand-in. The stand-in itself is already unreachable in a production build (`lib/contact/delivery.test.ts` boundary a). |
