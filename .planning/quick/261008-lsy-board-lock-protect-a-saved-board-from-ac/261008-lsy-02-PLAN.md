<objective>
Grey out and disable every control that changes the board while the open board is locked, on
every design screen and in every layout, and keep every viewing control usable. Plan 01 already
made the lock real (the store refuses every change, nothing saves, Unlock is in the top bar); this
plan makes it visible and makes the disabled state true for the keyboard and screen readers too.

What the shaper sees: open a locked board and every slider, typed box, pill, tick that changes the
board, blank pick and Reset button is greyed and won't respond; the TEMPLATE drawing still shows
its construction but has no grab points. Tabs, zoom, rotate, show/hide ticks, sections, the ☰
tiles, Back + Next, settings and printing all work as normal. Press Unlock and everything comes
back at once.

Purpose: the founder's "greys out all controls" — a shaper must see at a glance that a locked
board can't be changed, rather than finding sliders that silently don't move.
Output: one lock scope, the two shared rows reading it, explicit disables on every other
board-changing control, an inventory test, and the browser walk.
</objective>

<the_mechanism>
Measured 2026-10-08; this is the decided design, not an option list.
- ONE scope: `BoardLockScope` (client component) reads useDesign().locked and provides it through a
  plain React context whose default is false; `useControlsLocked()` reads it. It wraps the screen in
  app/design/layout.tsx, so all six design screens (including SUMMARY, which does not use
  DesignScreenShell) are inside it, while the top bar, its gear menu, the ☰ sheet and App Default
  Settings (all mounted from the root layout) are outside it and stay usable.
- AUTOMATIC: SliderRow (components/design/slider-row.tsx) and MeasureField
  (components/design/measure-field.tsx) read the scope and treat it as `disabled`. Every SliderRow
  and MeasureField on a design screen changes the board (ROCKER's DATASHEET typed thickness cells
  included); MeasureField is also used by App Default Settings, which is outside the scope, so it
  is never greyed there.
- EXPLICIT: everything else gets `disabled={locked}` (with `const locked = useControlsLocked()`)
  when its handler reaches a store change: raw `<Slider>` rows, Selects, Checkboxes,
  TwoOptionToggles, raw `<button>` pills/steppers/Resets/Automatic, shared `<Button>`s, `<input>`s.
  Why not a blanket `<fieldset disabled>` or `inert` around each panel: both would also disable the
  view-only controls that live in the same panels (section open/close, Show Construction, Show
  Callouts, the toe/aim table, the print ticks); `inert` also hides the values from screen
  readers; and neither stops a Base UI Slider drag (Base UI reads only its own `disabled` prop, or
  a Base UI Field.Root, never a native fieldset — checked in node_modules/@base-ui/react 1.7).
- VIEW-ONLY controls carry the attribute `data-lock-exempt` and are never disabled.
- The INVENTORY (components/design/board-lock-scope.test.ts, node environment like every
  components/**/*.test.ts): for each lockable file, strip comments (the stripComments idiom of
  design-store.test.ts), find every opening tag of `<button`, `<Button`, `<Checkbox`, `<Select`
  (the Root only, not SelectTrigger/SelectItem/SelectValue), `<Slider` (not SliderRow),
  `<TwoOptionToggle`, `<PillButton` (and any other local helper component that renders a button —
  list it), `<input`, `<Input`, `<select`; read each whole opening tag (track `{}` depth and skip
  quoted strings at depth 0, since class strings can hold `>`); require either a `disabled={…}`
  whose expression contains the word `locked`, or `data-lock-exempt`. Report offenders as
  file:line. Also assert each lockable file yields at least one tag, and that slider-row.tsx and
  measure-field.tsx call useControlsLocked().
</the_mechanism>

<slip_throughs>
Every path that could change a locked board without passing a disabled control, and what covers it:
1. TEMPLATE's drag points (outline-viewer SVG, a delegated pointer handler on the root svg):
   outline-editor passes `onOutlineDrag={locked ? undefined : updateOutline}`; the viewer's own
   contract is "omitted means no hit targets and no handlers at all", so the grab points (and their
   target rings) are not drawn; Plan 01's store guard backs it.
2. Base UI Slider internals (pointer on the track, keys on the thumb's range input): `disabled` on
   the Slider (via SliderRow or explicitly) stops both and removes the thumb from the tab order;
   the store guard backs it.
3. Keyboard Undo/Redo (Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, a window listener bound in an effect): the
   store's guarded undoEdit/redoEdit (read through a ref, so an older closure still sees the lock) —
   Plan 01.
4. The on-screen Undo/Redo pair: hidden while locked (canUndo/canRedo false) — Plan 01.
5. A typed field committed on blur or Enter: MeasureField disabled via the scope; store guard.
6. The SUMMARY Board Name box and Fin System select: Board Name becomes read-only, Fin System
   disabled — both print exactly as before.
7. Rename from the rack while locked: allowed by the founder (A2); Plan 01's noteRenamed keeps the
   store's name in step without a design change.
8. Starting a new board from a preset while a locked board is open: allowed — it opens a NEW
   unsaved board and leaves the locked one untouched in the rack (applyPreset is the store's one
   unguarded edit, by design).
9. App Default Settings (Fit & Tip Defaults, blank makers, Units): outside the scope and never
   change a saved board (a saved board keeps its own tips and cut — D-19, Phase 12 D-01), so they
   stay usable.
10. A lock set on another device while this one edits: Plan 01's refused save turns this editor's
    lock on at its next autosave.
</slip_throughs>
