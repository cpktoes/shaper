<objective>
Give the board name + dimensions block 4mm of clear paper on the CURVE side as well as the
stringer side, on both template prints.

Right now the block is placed so its outboard edge may touch the rail curve exactly. On the Paper
Saver strip's page 1 that shows up as the block's top-right corner grazing the curve — measured, the
gap is under a millimetre on three of the four presets. The founder reviewed the printed strip and
asked for the same 4mm of daylight on that side that the stringer side already gets, on both prints.

Purpose: a shaper cuts the template out along the curve. A block that touches the cut line is a
block the scissors go through. 4mm of daylight is the difference between the board's own dimensions
surviving the cut and being sliced off with the offcut.

Output: one term added to one expression in two functions in `lib/geometry/template.ts`, the
comments that describe the old one-sided rule rewritten, every affected expectation re-derived, and
a proof that nothing else in the tiled layout moved.

This is a single-rule change inside a module whose architecture is already proven and already
covered end-to-end by pins, so there is no new layer to trace — the work is the rule, the honesty of
the pins around it, and the comments.
</objective>

<design_decision>

## The digest-pin ruling: split the proof, then recapture — never overwrite on trust

**The problem.** The tiled-layout characterisation pin from quick task 260902-cj5
(`lib/geometry/template.test.ts` ~line 63, the describe marked "frozen, never edit") hashes EIGHT
functions into one digest per preset x paper: `computeTemplateLayout`, `computeTemplateMarks`,
`markPlacements`, `markLineSegments`, `templatePageBoxes`, `computeTailClosure`,
`tailClosureSegments` — and `nameBlockPlacement`. This task changes `nameBlockPlacement` on the
founder's explicit instruction. All eight digests will therefore go red, legitimately. A block
labelled "never edit" is about to need editing, and the lazy move — overwrite the eight hex strings,
watch it go green, move on — would destroy exactly the property the pin exists to provide: it can no
longer tell "the founder changed the name block" apart from "something broke the tile grid".

**The ruling.** Split the proof from the pin, in this order, and never the other way round:

1. **Before any source edit**, add a NEW frozen describe that hashes the SEVEN functions this task
   does not touch — the same combined object with `namePlacement` left out — and capture its digests
   from the unmodified `lib/geometry/template.ts`. This is the guard doing the real work. It is
   captured against code that has not been touched, so it cannot be tuned to a broken result, and it
   must stay green through Task 2 without being edited. That green is the mathematical statement
   "nothing but the name block moved."

2. **Only then**, in Task 2, recapture the existing eight-function pin's hex strings, with the
   seven-function pin green in the same run. Add a dated amendment to the cj5 block's own comment
   recording the one authorised recapture, what changed (`nameBlockPlacement`, on founder
   instruction), and that the seven-function sibling pin is what proves the other members did not
   move. A future reader must not be able to mistake this for casual overwriting.

**Why not the alternatives.**

- *Remove `nameBlockPlacement` from the cj5 pin instead of recapturing.* That is also an edit to the
  frozen block, and it permanently amputates a function from the tiled-layout pin's coverage — every
  future task loses the guard on the name block to save this one task an awkward recapture. Trading
  permanent coverage for temporary convenience is the wrong direction.
- *Recapture and skip the seven-function pin.* This is the move the ruling exists to forbid. Without
  a digest captured before the source moved, "the other seven are fine" is a claim, not a fact.
- *Two constants, one for each print.* Rejected on the founder's own wording: "give the 4mm of
  clearance on both template prints" is one rule applied twice, not two rules. `NAME_BOX_CLEARANCE_MM`
  stays the single source.

**The second ruling: clearance is not a paper-fit term.** `scanPagesForNameBlock` has a guard that
skips a strip page whose printable width cannot hold the box at all. That guard compares the box's
own drawn footprint (`leftEdge + boxWidthMm`) against the page's printable right edge, and it stays
that way. The new clearance term belongs only to the outline-containment test, where the curve
actually is. Adding it to the paper-fit guard too would skip a page for want of 4mm of paper that
nothing is ever drawn on — a silent, invisible page shift with no rationale a shaper could see.

</design_decision>
