<background>

## What a shaper sees today

Over the board drawing on TEMPLATE and ROCKER there is a little row of icon buttons — rotate the
board, export a template, show the construction lines, widen the view. On RAILS there is one, View
Full Sized.

Each of those buttons is parked at a hand-picked position measured in from the panel's top-right
corner: the corner itself, 40px in, 80px in, 120px in. That worked when every button was always
drawn. Phase 9 then hid two of them on a phone — rotate (turning the phone does its job) and wide
view (there is no sidebar to widen). Their parking spaces stayed. So on a phone TEMPLATE the row
starts 40px off the corner with a hole in front of it, and on ROCKER the single remaining icon
floats 40px off the corner by itself.

Quick task 260909-h3g (landing just before this one) also hides rotate on any touch screen at any
width, which means a tablet held sideways gets the same empty corner. No amount of phone-only
position patching fixes that case, because it is not a phone-width case.

## The two options that were weighed, and the measurement that decided it

**Option A — one row.** The buttons stop being individually parked. Each editor wraps them in one
container pinned to the panel's top-right corner, laid out as a flex row growing leftward with a
fixed gap. A hidden button then takes no room, and the survivors pack into the corner on every
device with no per-breakpoint bookkeeping at all.

**Option B — phone-only overrides.** Keep the parking spaces and add a phone-only override to each
button. Rejected: it cannot reach the touch-screen-at-desktop-width case without a second full set
of pointer overrides, and it multiplies exactly the hand-maintained-position problem
`components/viewer/toolbar-button.tsx` was written to end.

Option A only wins if it keeps the desktop pixel-identical, so that was measured before choosing:

| Piece | Class | Value |
|-------|-------|-------|
| Icon | `size-6` | 24px |
| Padding, each side | `p-1` | 4px |
| Border, each side | `border` | 1px |
| **Button box** (Preflight `box-sizing: border-box`) | | **34px** |
| Today's step between buttons | `right-10` | **40px** |
| **Gap that reproduces it** | `gap-1.5` | **6px** |

`app/globals.css` does not override Tailwind's `--spacing` (still 0.25rem) and sets no root font
size, so 34 + 6 = 40 exactly. No arbitrary value is needed and no fractional pixel appears. The
desktop row lands byte-for-byte where it is today: 0, 40, 80, 120 in from the corner.

## What must not move

- The five desktop baseline screenshots must still match with no `--update-snapshots`, ever.
- Every existing phone assertion about rotate and wide view being hidden stays exactly as written.
- No button's label, tooltip, icon, click behaviour, pressed state or hide-gate changes.
- `components/ui/*`, `lib/geometry/*` and `e2e/desktop-baseline.spec.ts-snapshots/` are not touched.
