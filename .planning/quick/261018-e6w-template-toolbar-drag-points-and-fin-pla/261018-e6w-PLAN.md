F1 — The Settings block's `mt-auto` was doing nothing. The controls column (`flex flex-col gap-5`) sits in a block scroller and is only as tall as its content, so the block's computed margin-top was 0px on all six screen sizes and it sat exactly 20 px (gap-5) under the row above it; on WINGS the fin note sat 20 px under the block. F2 — Turning the drag points on in the SERVER's HTML breaks hydration on WebKit (every real iPhone, iPad and Mac Safari). With the default simply `true`, the iPhone project logged "A tree hydrated but some attributes of the server rendered HTML didn't match": the nose rail handle's `cy` was 141.38360336222905 on the server (Node) and 141.383603362229 in WebKit, and Next's dev "1 Issue" badge appeared on the iPhone screen. Chromium (desktop, Android) matched exactly. Today this never happens because the overlay is off in the server's HTML and comes on after hydration on a touch device. Fix proven in the scratch copy: keep the override pattern and default it to an "after hydration" flag — a `useSyncExternalStore` with a no-op subscribe, client snapshot `true`, server snapshot `false` — so the overlay comes on one render after hydration on every device, exactly the timing phones already have.
