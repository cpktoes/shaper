The founder's locked decisions come from 13-SPEC.md item 11 and the "11 Do it" brief:
- Vercel's own Web Analytics, which is cookie-free and counts visits per screen. The founder switches it on in the
  Vercel dashboard.
- The package is `@vercel/analytics`, pinned to exactly `2.0.1`, mounted through its Next.js component.
- A privacy page that is short, plain English and has no legalese. It covers what is collected, why, cookies, who
  handles it, deletion by emailing support@, and a Last updated date of 30 September 2026. It is public and
  follows the Contact page's patterns.
- It is linked from both menus, from Clerk's sign-in, and from the end of the Contact form's privacy note. The

Choices made at plan time (the planner's discretion, recorded so the executor does not re-decide them):

- **P-1 — Where the Privacy row goes.** It sits directly under Contact in both menus: Contact, then Privacy, then the
  divider in the gear menu; Home, Contact, Privacy, then the divider in the phone menu.
  - Why: the phone menu is taller than a phone screen and scrolls inside itself (quick 260926-wmf). A row placed
    last would sit below the fold, under the account control, and "two taps" would become "tap, scroll, tap".
  - Grouping it with Home and Contact keeps the "go to a page" rows together. The cost is one row.
  - The row hides on `/privacy` itself, the same way Contact hides on `/contact`.
- **P-2 — What the visit counter sends.** A `beforeSend` removes everything from the first `?` or `#` onward, so only
  the address is counted: `https://…/design/rails`, never `…?anything` or `…#anything`.
  - Checked at plan time: the app's own addresses carry nothing personal. `find app -type d` lists only fixed
    routes, with no `[id]` segment. Nothing in app/, components/ or lib/ reads `useSearchParams` or `searchParams`.
    A saved board opens from memory, never by address.
  - Other things can add to an address, though:
    - Clerk's sign-in dialog uses `routing="hash"` (components/auth/sign-in-dialog.tsx:62), which writes its steps
      after a `#`.
    - A returning sign-in can carry Clerk's own values after a `?`.
    - A link posted on social media can carry a per-click id (for example `fbclid`).
  - Vercel's own documentation says query parameters are recorded ("Query Params (Filtered)") and tells sites to
    use `beforeSend` to redact them.
  - Trade-off, listed for the founder: a campaign tag such as `?ref=instagram` will not show. The referring site
    still does.
- **P-3 — Mounted everywhere, not gated.** `<SiteAnalytics />` renders on every page in every environment, as the
  brief and Vercel's quickstart prescribe. No NODE_ENV or VERCEL guard is added.
  - The package decides the mode itself (verified in dist/next/index.mjs):
    - In development it loads `https://va.vercel-scripts.com/v1/script.debug.js`, which only logs.
    - In production it loads a first-party script from the site's own address.
  - It injects one script tag, and skips injecting if one is already there.
  - A guard that read the wrong variable would silently switch counting off in production, which is exactly what
    this item exists to prevent.
- **P-4 — Clerk's link.** `ClerkProvider` in app/layout.tsx gets
  `appearance={{ options: { privacyPageUrl: PRIVACY_ROUTE } }}`.
  - In the installed @clerk/nextjs 7.8.2 the key is `options`. There is no `layout` key in these types (see
    <interfaces>).
  - Clerk's UI passes the address straight to the link's href without checking it, and opens it in a new tab.
    Clerk's source (packages/ui/src/elements/Card/CardFooter.tsx) shows the footer links on the sign-in and
    sign-up card whenever at least one of the three addresses is set.
  - A relative `/privacy` therefore works on production, on previews and on localhost alike.
  - The account-settings popup only shows these links on a Clerk-branded footer. The SPEC asks only for the link
    on sign-in.
- **P-5 — The Contact note's link.** It is appended after the approved sentence inside the same paragraph, as one
  space and then a Next `<Link>` reading **Privacy**.
  - "Privacy" is the same word as the menu row and as Clerk's own footer link.
  - `CONTACT_COPY.privacy` itself is not edited, and a unit test pins its exact words.
- **P-6 — Menu row code.** `ContactMenuItem` and the new `PrivacyMenuItem` become two thin exports over one
  private `PageMenuItem`, so the two rows can never drift apart.
  - The gear menu's divider becomes a plain, unconditional divider after the two rows, the same as the phone menu
    already does.
  - `ContactMenuItem`'s `divider` prop is removed. Its only caller is the gear menu.
  - This is valid because Contact and Privacy can never both be hidden: each hides only on its own route.
- **P-7 — No Content-Security-Policy exists**, so none needs changing.
  - Checked: next.config.ts has no `headers()`.
  - proxy.ts only runs `clerkMiddleware()`.
  - There is no vercel.json.
  - A repo-wide grep for Content-Security-Policy finds nothing outside node_modules.
- **P-8 — Deletion (revised by the orchestrator 2026-09-30, after item 11a shipped).** The page says three things:
  - A saved board can be deleted by the shaper from the three-dot menu on its card on the home screen. This is
    verified in the code.
  - A shaper can delete their whole account themselves: account menu (their picture in the top bar), then Manage
    account, then Security, then Delete account — and their saved boards and settings are deleted with it. Backed
    by item 11a (quick 260930-ckm): the founder turned on "Allow users to delete their accounts" in Clerk's
    Production instance, and `app/api/webhooks/clerk/route.ts` + `lib/db/account-deletion.ts` delete the account's
    `models` and `user_preferences` rows on a signed `user.deleted`; the founder's live test on 2026-09-30 got
    "Deleted: saved boards 1, settings rows 1".
  - Or email support@ and the founder does it for them.
