<objective>
Phase 13 item 8 (13-SPEC.md; todo `2026-09-27-summary-needs-tip-thickness-and-deck-bottom-passes`), as
redirected by the founder on 2026-09-29. Asked whether a Tips & Planing box should go on page 1 beside the
rocker, he said: "The rocker box already has thicknesses so tips is taken care of. A Planning box such as how
many passes etc can fit on page 2 if we condense the rail markings horizontally to make a new column next to
it."

So page 1 does not change. Page 2, the Shaper Reference, gets a PLANING column in a new column beside the
Rail Bands table, and the table is condensed horizontally to make room. With a blank picked, the column shows
the Deck Skin, the foam off the bottom at the centre as a depth, and that depth as planer passes at the
shaper's own Planer Max Depth: the same numbers and words ROCKER shows. With no blank it shows one plain line.

Purpose: a shaper at the blank reads how much comes off and how many passes that is off the paper, beside
the rail markings they are about to cut, instead of walking back to the screen.

Output: one pure tested module, a two-class change to the order form's compact rail table, the page-2 row
and CSS rule, one new Playwright spec, and the todo closed.
</objective>

<placement_decision>
The founder decided the placement: page 2, a new column beside the rail markings, made by condensing
them horizontally. This plan makes that concrete and proves the hard constraint, that the rail table gets NO
taller.

- The Rail Bands FormBox and a new PLANING FormBox share one row. The row takes the Rail Bands box's own
  `flex-[1.6]` share, so the rail box keeps its height.
- The PLANING box is `flex: none`, 20% of the Shaping Data column's width (`--order-form-planing: 0.2`,
  the same longhand pattern as page 1's `--order-form-left`). That is 138 px at the computer's print, 104 px
  at the narrowest phone print (560 dots) and 172 px at 900.
- The rail table gives up that width. Its compact variant (used only by the order form) moves the label
  column from `flex-[1.4]` to `flex-[1.75]` against `flex-1` per value column, in the header spacer and in
  every row. The DATA page's full-card variant keeps `flex-[1.4]`.
- Why 0.2 and 1.75: the narrowest phone print (560 dots, where type sits at its 12px floor) is the binding
  case, and there two strings set the limit. The longest row label, `Tapered Rail Thickness`, needs 131.5 px.
  The widest header, Metric's `Center (mm)`, needs 74.8 px. 1.75 balances the two, and 0.2 leaves 4.2 px and
  2.8 px of margin on them there. The measured ceiling before anything wraps at 560 is about 0.222; wider
  pages have far more room. At the computer's print 0.2 also fits `Off Bottom @ Center` (126.1 px) on one
  line in the column's 128 px inner width (`px-1`).
- The PLANING caption rule lines up with RAIL BANDS'. Rail Bands' caption row carries a captionRight
  (`plots overleaf`), which makes that row about 2 px taller, so the PLANING box passes a non-breaking
  space as its captionRight to match.

FOAM OFF five-station rows: left to ROCKER's DATASHEET. Five station columns cannot fit 138 px, and a
full-width row would add height page 2 does not have (a quad's fins have 3.4 px to spare today).
</placement_decision>

<no_blank_decision>
With no blank, the column stays and holds one plain line: `Pick a blank on ROCKER for the planing numbers.`
Three reasons:
1. The sheet keeps ONE layout, so the rail table is condensed the same way on every print and its numbers
   sit in the same place whether or not a blank is picked.
2. An empty captioned box reads like something failed to print. The line says why it is empty and where the
   numbers come from.
3. It does not offer write-in lines: every planing number is derived from a picked blank's foam, and a
   hand-worked figure could silently disagree with the app. The Blank line in Shaper Use Only stays the
   shop's write-in, as it is today.
</no_blank_decision>

<printed_wording>
Every new printed string, exactly. The caption prints in capitals through FormBox's `uppercase` class, so
its source string is `Planing`.

| Slot | Blank: Imperial | Blank: Metric | No blank (both systems) |
|---|---|---|---|
| Caption | `Planing` | `Planing` | `Planing` |
| Item 1 label → value | `Deck Skin` → `1/8"` (`none` at zero) | `Deck Skin` → `3 mm` (`none` at zero) | none |
| Item 2 label → value | `Off Bottom @ Center` → `3/8"` | `Off Bottom @ Center` → `10 mm` | none |
| Item 3 label → value | `Planer Passes` → `3 passes` | `Planer Passes` → `4 passes` | none |
| Item 3 note | `at 1/8" a pass` | `at 3 mm a pass` | none |
| The one line | none | none | `Pick a blank on ROCKER for the planing numbers.` |

The examples use skin 1/8", centre gap 3/8" and Planer Max Depth 1/8". Metric counts 10 printed mm over 3
printed mm and rounds up to 4, one more than Imperial: planerPasses' documented printed-number rule, the
same as ROCKER. Other edge wording:
- one pass reads `1 pass`;
- none reads `0 passes`;
- a depth below zero prints signed (`-1/16"` / `-2 mm`) with `0 passes`;
- a depth that prints as zero reads `0"` / `0 mm`, never `-0"`.

Each value stands alone in its own block, so it carries its own unit. The note is one line of running text
with its one unit (CLAUDE.md Rule 2).
</printed_wording>
