<objective>
Make the example rail's mark names stack **only when their text would actually overlap**, and make
the axis rule lift **only the names that need lifting**, so "Deck 3" stops being shoved off the top
of the drawing.

Purpose: after quick task 260908-b35, all six left-hand names on the example rail get treated as one
column, because the ported prototype rule groups labels by how close their *dots* are (95px), not by
whether their *words* could ever collide. Six names chained into one column, that column overflowed
the axis rule at the bottom, and lifting the whole column carried "Deck 3" clean off the top edge of
the plot. The prototype's own comment states the intent this task finally implements — "Only labels
whose text would actually occupy overlapping horizontal space need vertical separation" — its code
just never checked the text.

Output: a rewritten de-overlap pass in `components/rails/rail-callouts.ts` plus five new test cases.
No other file changes; `rail-instructions.tsx` keeps its existing call untouched.
</objective>

render scale 0.893). Treat them as given; do not re-derive them.

**Side −1 anchor x positions on the real example rail:** Deck 3 ≈ 250, Deck 1 ≈ 334, Deck 2 ≈ 404,
Bottom Tuck 3 ≈ 421, Bottom Tuck 1 ≈ 450, Corner Cut ≈ 471. Every consecutive gap (84, 70, 17, 29,
21) is under the old 95px bucket, which is why single-linkage chaining swallowed all six into one
column.

**Text extents that matter:** "Deck 3" spans x 207–250 and "Deck 1" spans 294–334 — they cannot
touch, so neither should move the other. "Bottom Tuck 3" (327–417) and "Bottom Tuck 1" (359–446) do
overlap, so they must stack, and the axis ceiling must lift **that pair only**.

**Character width:** "Domed Taper" is 11 characters and measured 83 viewBox px at scale 0.893, i.e.
about 74 px at scale 1 — roughly **6.7 viewBox px per character** for the pinned 11px bold face.
Because the font is pinned in *screen* px, a label's viewBox width shrinks as the plot renders
larger, so a per-character estimate calibrated at scale 1 is conservative (over-wide, never
under-wide) on bigger renders — the order form's third sheet renders at about 2.3.
