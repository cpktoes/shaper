## 1. The station band and the overlap — reuse what the full template already proved

The strip is landscape, so the station (nose-to-tail) axis runs down the paper's **short**
edge and the half-width axis runs across its **long** edge. Reusing `TEMPLATE_MARGIN_MM`
(10mm) and `TEMPLATE_OVERLAP_MM` (0.5in = 12.7mm) unchanged, as CONTEXT.md directs:

| | Letter landscape | A4 landscape |
|---|---|---|
| paper | 279.4 x 215.9mm | 297 x 210mm |
| usable station (short edge − 2 margins) | 195.9mm = 7.71in | 190mm = 7.48in |
| usable half-width (long edge − 2 margins) | 259.4mm = 10.21in | 277mm = 10.91in |
| step between pages (usable − overlap) | 183.2mm = 7.21in | 177.3mm = 6.98in |

The reference PDF's own step measures ~7.17in on Letter. Reusing the existing constants lands
on 7.21in without a single new number — that is why no reason to differ is stated, and why no
new margin or overlap constant is introduced.

The bands come from **`buildWindows(geometry.length, usableStation, overlap, count, true)`** —
the same module-private helper `computeTemplateLayout` already uses for its rows, called
directly (same file, no edit to it). Page 0 is therefore flush with the nose tip and the strip
runs nose to tail, matching the full template's row order, as CONTEXT.md directs.

## 2. The registration lines — at the centre of the shared overlap band

Each page's two lines sit **`overlap / 2` inside its own printable station edges**. That
placement is not aesthetic, it is the whole mechanism:

```
page N   window = [sN,        sN + usable]
page N+1 window = [sN − step, sN − step + usable]  where step = usable − overlap

page N   bottom line = sN + overlap/2
page N+1 top    line = (sN − step + usable) − overlap/2
                     = sN + overlap − overlap/2
                     = sN + overlap/2            ← the same station
```

So the two lines a shaper reads on consecutive sheets are **the same station by construction**,
which is what makes the locked "the same label appears on both" decision a property of the
layout rather than something to hope for. On Letter this puts each line 16.35mm (0.64in) from
the paper's edge; the reference measures 0.67in. Close enough that no adjustment is warranted.

**A line is drawn only where it is shared with a neighbouring page.** Page 1 gets no top line
and the last page gets no bottom line — a registration line's only job is to align against the
next sheet, and there is no next sheet there. This exactly reproduces the reference (page 1 of
14 has one line, near the bottom, and no line at the top). It also disposes of an awkward case
for free: every line that IS drawn provably falls strictly inside `(0, geometry.length)`, so
`sampleOutline` is never asked for a half-width off the end of the board.

## 3. The sideways slide — one expression, and the stringer falls out of it

For each page, take `max` = the outline's greatest half-width over that page's own station
band (sampled from `geometry.points` inside the band, plus both band ends via `sampleOutline`).
Then:

```ts
const halfWidthStart = Math.max(
  -STRIP_RAIL_INSET_MM,
  max + STRIP_RAIL_INSET_MM - usableHalfWidth,
);
const halfWidthRange = [halfWidthStart, halfWidthStart + usableHalfWidth];
const stringerOnPage = halfWidthStart <= 0;
```

with `STRIP_RAIL_INSET_MM = inchesToMm(0.5)`. Read the two arms in plain English:

- **When the whole board fits across the page at this station** (a nose page, a tail page),
  the first arm wins: the stringer is pinned half an inch inside the left printable edge and
  the curve sweeps out to the right. The stringer prints.
- **When it does not** (anywhere near the widepoint), the second arm wins: the outermost rail
  point is pinned half an inch inside the RIGHT printable edge and the page slides out past
  the stringer. The stringer does not print.

That is exactly the reference's behaviour — stringer on pages 1 and 12–14, absent on 2–11 —
from one expression, and it is a pure function of the page's own station band plus the paper.
No page ever looks at a neighbour, which is the property CONTEXT.md requires. It is also
continuous: nothing jumps as a board's widepoint crosses the threshold.

Checked against the numbers: for a 22.5in-wide board, `max` at the widepoint is 285.75mm,
the threshold (`usable − 2 x inset`) is 234mm on Letter, so the widepoint pages slide right
and `halfWidthStart` = 39.05mm > 0 — no stringer, matching the reference's page 7.

**The one degradation, stated rather than hidden.** In the right-anchored arm the curve's own
inner end can only fall off the page if the curve rises more than `usableHalfWidth − inset`
(246.7mm on Letter) within a single 195.9mm station band — a taper no real outline has. The
rail is what a shaper traces, so if that ever happened the rail is what stays on the paper and
the stringer-side end is what goes. `StripPage` exposes `minHalfWidth` and `maxHalfWidth` so
this is asserted, not assumed: a test proves the whole curve is on the page for every preset,
both papers, and at the extreme ends of `WIDEPOINT_WIDTH_RANGE_IN`.

## 4. Page 1's furniture goes in the top-right, outboard of the nose taper

The locked decision says page 1 carries the 2in scale square and the name/dims block "using
the SAME conventions and drawing helpers the full template already uses". The full template's
own `nameBlockPlacement` puts the box INSIDE the outline, scanning down from the nose until
the board is wide enough to hold it — on a 7.7in-tall landscape band that search lands right
on top of the bottom registration line and its label. So the placement rule differs even
though every drawing convention (box width, padding, font sizes, dims-row content, truncation)
is reused verbatim.

**The strip anchors both to the printable top-right corner of page 1** — scale square first,
name block beneath it. That corner is the blank paper outboard of the nose taper: the name box
is 74mm wide, so its left edge sits at half-width 172.7mm (6.8in) on Letter, and over the top
~90mm (3.5in) of any board the outline is nowhere near 6.8in of half-width. This is asserted
rather than eyeballed — a test walks the furniture's own station span and requires the
outline's half-width to be strictly less than the furniture's left edge at every step.

Reused unchanged from `build-template-pdf.ts`, all already exported so that file needs no
edit: `nameBlockContent` (the wrapped dims row and the box's real height),
`templateNameBlockText` (empty-name fallback and ellipsis truncation),
`templateNameBlockDimsText` (the seven order-form values), `wrapTextToWidth`, `rectsOverlap`,
`rectContains`. `SCALE_SQUARE_MM` is NOT exported, so the strip declares its own
`inchesToMm(2)` rather than editing the file to export it — the same call this repo already
makes in `overviewFileName`, which deliberately duplicates `templateFileName` "as a sibling
function rather than an import".

## 5. Text placement — a numeral column on the left, labels in their own column

Every piece of text on a page is placed by `lib/geometry/template.ts`, which hands the drawing
module a finished string and a finished baseline station. Two rules keep it collision-free:

- **The page numeral owns a fixed column** at the printable left edge,
  `STRIP_PAGE_NUMBER_COLUMN_MM` (22mm) wide, vertically centred in the page's own band. Every
  label row starts to the right of that column, so a numeral can never sit under a label.
- **All label rows sit INSIDE the registration band**, on the interior side of their line: the
  top line's label just below it, the bottom line's label just above it, a mark's label just
  above its tick. Nothing is squeezed into the 6.35mm strip between a line and the paper edge.

Marks and registration lines can land at nearly the same station, so `stripLabelRows` runs a
de-collision pass in the same spirit as the existing `resolveCenterWidepointLabelCollision`:
**registration rows are pinned and never move**; a mark row within
`STRIP_LABEL_MIN_SEPARATION_MM` of an already-placed row is nudged to whichever side is
further from it. Three invariants are tested rather than trusted — no two rows on a page
within the separation, every row inside its page's own station range, and no registration row
carrying a nonzero nudge.

A label can still cross the curve where the board is narrow (the last page or two). Text
crossing a hairline stays legible and the reference itself has no rule for this, so it is
accepted rather than engineered around.

  `overviewFileName` is one.
- **Card:** title **Paper Saver**, description *"Just the rail curve, one page at a time."*
  Never "segments" — the artifact is a continuous strip, as CONTEXT.md insists.
- **Card layout:** the picker's `grid grid-cols-2` becomes `grid grid-cols-1` — three cards

  the same time so the taller picker can never push the Download button off a laptop screen.
  Full Template stays the default selection.
- **Preview:** a page-count line only, no diagram. A 1-column x 13-row strip diagram at the
