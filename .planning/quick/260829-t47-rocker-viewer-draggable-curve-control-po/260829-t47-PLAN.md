<objective>
Finish the ROCKER screen's direct-manipulation story: make the four curve control points
draggable, take the two tip-height drags away, and re-draw the station read-outs as data cards in
the TEMPLATE screen's own grammar.

Purpose: yesterday's two tasks drew the rocker's steering lines but left them inert — a shaper can
see what is bending the curve and still has to go back to the sidebar to change it. The TEMPLATE
screen solved this months ago: you grab the control point and the curve follows, and the sliders
follow the curve. The rocker curve is built on that identical construction, so the same inverse
solve applies. At the same time the two tip-height grabs go: a tip's rocker is a headline number a
shaper quotes and types ("a 4 1/2 inch nose"), not something to eyeball by dragging, and leaving
it draggable makes the tip look like a shape control when it is a dimension. Finally the numbers
under the board, today loose floating text, become bordered cards so the ROCKER screen and the
TEMPLATE screen read as one drawing system.

Output: four inverse solves in `lib/geometry/rocker-drag.ts` with round-trip tests, a rocker
viewer whose grabbable points are exactly the four control points, and five station data cards
drawn on a card surface shared with the TEMPLATE screen's chips.

**1. The handle array's index order (the single most important fact in this plan).**
`buildRocker` in `lib/geometry/rocker.ts` pushes its four handles in this exact order, two per
Bezier segment, out-handle then in-handle:

- `handles[0]` — `from` = `knots[0]` (**tail tip**, station 0, height = `tailLift`), `to` = segment
  0's first control point. This is the tail tip's own steering handle. It carries **`tailAngle` +
  `tailSmoothness`**.
- `handles[1]` — `from` = `knots[1]` (**centre**, station `length/2`, height 0), `to` = segment 0's
  second control point, which lies on the flat toward the tail. It carries **`tailFlatness`**.
- `handles[2]` — `from` = `knots[1]` (**centre**), `to` = segment 1's first control point, on the
  flat toward the nose. It carries **`noseFlatness`**.
- `handles[3]` — `from` = `knots[2]` (**nose tip**, station `length`, height = `noseLift`), `to` =
  segment 1's second control point. It carries **`noseAngle` + `noseSmoothness`**.

`RockerKnot.point` and `RockerHandle.from`/`.to` are `Point2D` in board space, where **`x` is the
station and `y` is the lift**, both `Mm`.

**2. The forward formulas each solve must invert, quoted from `buildRocker`.**

- Tail tip direction: `dir0 = (cos(tailAngle), -sin(tailAngle))`. Handle length
  `outLen0 = ((100 - tailSmoothness) / 100) * rockerTipHandleMaxLength(dir0.y, chord0, tailLift)`,
  and `handles[0].to = P0 + outLen0 * dir0`. Note the **inversion**: length grows as smoothness
  falls (see `rocker.ts`'s own deviation note 2 for why).
- Nose tip direction: `dir4 = (cos(noseAngle), +sin(noseAngle))` — note the sign differs from
  `outline.ts`'s nose direction. Handle length
  `inLen1 = ((100 - noseSmoothness) / 100) * rockerTipHandleMaxLength(dir4.y, chord1, noseLift)`,
  and `handles[3].to = P4 - inLen1 * dir4`, i.e. the handle runs **back** from the nose tip.
- Centre direction: `dir2 = (1, 0)` — purely along the station axis, which is what makes the curve
  read flat through the middle. `inLen0 = railMult(tailFlatness) * HANDLE_CAP * chord0` and
  `handles[1].to = P2 - inLen0 * dir2`; `outLen1 = railMult(noseFlatness) * HANDLE_CAP * chord1`
  and `handles[2].to = P2 + outLen1 * dir2`. Because `dir2.y` is zero, these two handles have
  **no height freedom at all** — the cross-axis component of a drag on them carries no
  information and must be discarded, not approximated.
- `chord0 = |P2 - P0|` and `chord1 = |P4 - P2|`, where `P0`/`P2`/`P4` are the three knots. A
  control-point drag never moves a knot, so both chords hold for the whole gesture — the same
  argument `outline-drag.ts` records at its own `tailChord`/`noseChord`.
