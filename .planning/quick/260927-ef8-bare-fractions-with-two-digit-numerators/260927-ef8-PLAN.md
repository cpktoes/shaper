<objective>
**What the shaper sees today.** In Imperial, typing a bare fraction whose top number has two digits into
any typed box quietly saves a whole inch too much, with no error. This affects a width, a thickness, a
ROCKER station or a fin measure. Measured at plan time on main (a793be4) through the real commit path
(`commitTypedMeasure`, Imperial mark field, bounds 0.5" to 5"):

| Typed | Saved today | Should be |
|---|---|---|
| `11/16` or `11/16"` | 1 1/16" | 11/16" |
| `13/16` | 1 3/16" | 13/16" |
| `15/16` | 1 5/16" | 15/16" |
| `10/16` | 1" | 5/8" |
| `0 11/16`, `1 11/16`, `3/16`, `9/16` | correct | (no change) |

**Why.** The inch part of `parseImperial` (`lib/geometry/units.ts`) is read by one pattern that has an
optional whole number, optional spaces, and then an optional fraction. The whole-number part is allowed
to take the first digit of `11`, which leaves `1/16` for the fraction. The function's own doc comment
already says the fraction is "space-separated". The code just never enforced it.

**The fix.** The inch part must be one of two shapes, and only two:
1. A whole or decimal number, optionally signed. It may be followed by at least one whitespace
   character and then an unsigned fraction.
2. A fraction standing alone, with an optional leading minus.

So a fraction with any numerator, standing alone, is that fraction. A whole number and a fraction need
whitespace between them, which is how every shaper writes it and how the app's own error line already
shows it ("a fraction like 2 5/8").

**Decision (planner's discretion, asked for by the brief): a minus in front of a bare fraction is read,
not refused.** `-11/16` reads as −11/16, where today it gives −1 1/16. The same rule changes `-1/2`
from refused to −1/2, because the grammar cannot treat one-digit and two-digit numerators differently.
A minus on the fraction after a whole number (`-2 -11/16`) is refused. Today every typed field has a
range that starts above zero, and `commitTypedMeasure` clamps to that range, so the minus forms exist to
keep the parser honest rather than because a screen takes them.

**Consequences, stated so nobody is surprised:**
- A whole number typed straight onto a fraction with no space is now read as one fraction, by the same
  rule. For example, `191/2` becomes 191 ÷ 2 rather than 19 1/2. Nobody types it that way. The field
  clamps it to its maximum and shows the result, so it is never silent.
- Everything else `parseImperial` accepts today reads identically. That includes spaces around the
  slash (`1 / 2`, `19 1 / 2`), tabs as the separator, a decimal whole with a fraction (`18.5 1/2`), feet
  (`6'`, `6'2"`, `5'11 15/16"`), `-0 11/16`, a zero denominator (null), and a hyphen separator such as
  `2-11/16` (still null, out of scope).

The plan-time probe of the proposed grammar against the current one ran 38 inputs. The only changes it
showed are the ones listed above.

Purpose: a shaper has to trust the number they typed is the number that gets cut (Core Value). This
bug was silent: the box accepts the input, shows no error, and the design carries an extra inch.
Output: a fixed `parseImperial` with an accurate doc comment and a test for every form above. Test 12-02
had worked around this bug, and that workaround is removed.
</objective>

lib/geometry/units.ts, `export function parseImperial(input: string): Mm | null` (around lines 351-406):
- Trims the input; empty returns null.
- Feet prefix: matches an optionally signed whole-or-decimal number followed by `'` at the start. It
  sets `feet` and strips that prefix. This part is NOT changed.
- A trailing `"` is stripped. NOT changed.
- The inch part, when anything is left, is the ONE place that changes. Today it is a single pattern
  with three groups (optional signed whole-or-decimal, optional spaces, optional unsigned fraction
  with spaces allowed around the slash). A bare minus is detected from the whole part's text starting
  with `-`, and the inches become whole minus fraction when negative. A zero denominator returns null.
- Total = feet × 12 + inches, returned through `inchesToMm`.

lib/geometry/measure-display.ts: `commitTypedMeasure({ typed, current, family, min, max, system, bare })`.
In Imperial it runs parseImperial(typed), clamps in INCHES to [min, max], snaps with
roundToSixteenthInch, and returns `{ value, display, error }`. For family "mark" with bare false,
display is formatMark(value, "imperial"): `11/16"` for 11/16 in, `5/8"` for 10/16 in. The existing
Imperial example test is at measure-display.test.ts line 416 (`typed: "20 1/4"`, family "dim").

lib/geometry/measure-display.test.ts, the planer-pass describe block (around line 804). Its `printedBack`
helper (around lines 818-829) prints a mark with formatMark. It then has a five-line comment (lines
820-824) and a workaround line (825) that builds a zero-prefixed copy of any bare Imperial fraction. Line
826 parses that copy with parseMetric(…, "mm") or parseImperial(…). Line 827 throws if the parse
failed, and it quotes `printed`.

lib/geometry/units.test.ts `describe("parseImperial")` (lines 135-167) holds the existing cases: `6'0"`,
