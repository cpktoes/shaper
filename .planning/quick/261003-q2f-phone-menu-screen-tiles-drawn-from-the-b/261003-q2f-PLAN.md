Planner rulings (each the founder may overrule at review):

- **P-1 — Sideways, one row of six.** The sheet's tile grid is three columns below the 820-dot shell width and six
  columns at or above it — width alone, CLAUDE.md's layout switch. At a shell width ☰ only ever appears on a short
  screen (a tall window there has the desktop row), so six-across is only ever a phone held sideways. Arithmetic at plan
  time: upright 390 wide, 12-dot sheet sides and 8-dot gaps give tiles about 116 wide; sideways 844 wide gives about
  130, so the pictures are LARGER sideways, and one row (about 12 + 100 + 10 dots) leaves 174 to 224 dots of the
  292–342-dot sheet for the rows. Below the shell width a narrow phone held sideways (an iPhone SE, 667x375) keeps 3×2
  with the sheet scrolling inside itself, as the menu already does.
- **P-2 — The sheet hangs from the top bar.** Base UI 1.7.0's `Menu.Positioner` takes an `anchor` element; anchoring
  it to the top bar's own `<header>` (bottom side, start alignment, no offset, no collision padding, no collision
  flipping or shifting) and sizing the popup to Base UI's own `--anchor-width` gives a sheet exactly the window's width
  directly under the 48-dot bar, with `--available-height` capping it — no new primitive, no shadcn wrapper, the same
  Menu, Group and Item semantics the menu already has (arrow keys, Escape, tap outside to close).
- **P-3 — FINS reads the FINS screen's own name.** The line is the setup's label from `FIN_SETUPS` (the list the FINS
  screen's own picker shows): "Single Fin", "Twin", "Thruster", "2+1", "Quad" — so the sketch's "Single fin" reads
  "Single Fin", matching the FINS screen.
- **P-4 — TEMPLATE's line, unit once in Metric.** Imperial `6'2" × 18 3/4"` (each value carries its own mark, as
  everywhere in Imperial); Metric `188.0 × 47.6 cm`-style, centimetres to one decimal with the unit once at the end
  (CLAUDE.md Rule 2: dims family; one unit per line of running text). The numbers come from the same formatters as the
  setup card's line, so the tile and the card can never disagree.
- **P-5 — FINS tile: straight segments through the tail's own points.** The FINS screen smooths its tail through a
  curve-fitting step; the tail's points are already half an inch apart (48 per 24") or the outline's own dense points,
  so at tile size each step is under two dots and straight segments draw the same curve. `fin-viewer.tsx` is not
  touched.
- **P-6 — One dot rule for RAILS.** Which rail marks get a dot (every band end except the three connector lines and a
  hard edge, plus the apex centre and, on a domed deck, the dome's top) moves out of the RAILS plot component into
  `lib/geometry/rail-bands.ts` as `railPlotDots`, and both the RAILS plot and the RAILS tile read it — same dots, same
  order, so the RAILS screen does not move a pixel (the desktop RAILS reference screenshot proves it).
- **P-7 — Pictures only while the sheet is open.** The tiles are built from the design store inside the popup, which
  Base UI unmounts when the menu is closed, so dragging a slider never rebuilds six pictures; nothing is captured,
  cached or stored.
- **P-8 — All three end rooms move together.** After q2c there are three phone end rooms, each sized today so the last
  row (Back + Next) ends 64 dots above its scroller's bottom edge, 8 clear of the pair's top at 56: DesignScreenShell's
  `::after` block (TEMPLATE, ROCKER, RAILS, FINS), the extra bottom padding q2c gave VOLUME's simple-sidebar branch, and
  the extra bottom padding q2c gave the Summary's order form (C-10). With the bar gone the pair's top is 60 dots plus
  the home-bar inset above the window's bottom edge, which is now each scroller's bottom edge, so each of the three
  grows by 4 dots plus the inset — same mechanism each already uses (the shell's stays an `::after` block, VOLUME's and
  SUMMARY's stay padding as q2c built them) — and the measured gap on every screen is the proof.
- **P-9 — Only the upright phone's pair moves.** The computer (and a phone held sideways, which lands in the desktop
  shell) keeps its 16-dot corner exactly; only the below-shell-width offset changes.
- **P-10 — Each tile's accessible name is its screen and its line** (`TEMPLATE — 6'2" × 18 3/4"`; VOLUME's includes
  the litres: `VOLUME — 29.6 L Estimated`), the pictures themselves hidden from screen readers.
- **P-11 — Tiles on every ☰ page draw the store's board.** On the home screen, Contact, Privacy and the error pages
  the tiles draw whatever board the design store holds (the default board until a preset or saved board is opened) —
  the same board the desktop row's links open.
