<decisions>
There is no CONTEXT.md for a quick task. These are the planner's decisions, built on the orchestrator's verified
facts. The orchestrator or the founder may overrule any of them before execution.

- **D-01: The page lives in Clerk's account panel.** The installed `@clerk/react` 6.14.7 (behind `@clerk/nextjs`
  7.8.2) types `UserButton.UserProfilePage` as `{ label: string; url: string; labelIcon: ReactNode }` and
  `UserButton.Action` as `{ label; labelIcon; open: string }` (checked in
  `node_modules/@clerk/react/dist/index.d.mts` and `types-Dd22QRBT.d.mts`). So there is one custom page,
  label `Your data`, url `your-data`, icon lucide `FolderOpen`. It sits after Clerk's own Account and Security
  pages. The avatar menu also gets a `Your data` row that opens the panel straight to it
  (`UserButton.MenuItems` > `UserButton.Action open="your-data"`), ordered Manage account, Your data, Sign out.
  There is no fallback to App Default Settings.
- **D-02: The export is the stored data, as stored.** The file is `{ about, fileVersion: 1, exportedAt, boards,
  settings }`. `boards` holds one entry per saved board, oldest first: `{ id, name, createdAt, updatedAt,
  design }`. `design` is the `models.snapshot` envelope exactly as stored, never decoded. Dates are ISO strings.
  `settings` is the shaper's `user_preferences` row with every column except the account id, values exactly as
  stored (the JSON-text columns stay text), or `null` when there is no row. `id` is kept because the
  settings' rack order lists boards by id. The Clerk account id never appears anywhere in the file. Everything
  stored is metric (CLAUDE.md Rule 2), so nothing is converted. The `about` line says so. The file name uses the
  shaper's local date: `shaper-assistant-designs-YYYY-MM-DD.json`.
- **D-03: Delete runs in this order: data first, then Clerk.** In the Server Action: `await auth()`. Signed out
  means it stops. The typed word is re-checked; wrong means it stops. Then `deleteAccountData(db, userId)`, one
  atomic Neon batch, all or nothing. Then `(await clerkClient()).users.deleteUser(userId)`. Data goes first so
  the action itself guarantees the rows are gone, even where no webhook can reach (the local dev server that
  the founder's throwaway-account test uses). If Clerk then fails, the page says so plainly and pressing again
  is safe: the data step finds nothing and the Clerk step retries. `deleteAccountData` is already idempotent
  (a delete that matches no rows removes nothing), so it needs no code change, only a run-twice test. The
  webhook already answers 200 to a 0/0 delete.
- **D-04: The confirmation happens in place on the page, not in a pop-up.** This deviates from the
  orchestrator's suggested `components/ui/dialog`. Clerk's account panel is itself a full-screen modal, drawn
  by Clerk's own script at its own stacking level, and it keeps keyboard focus inside itself and treats the
  rest of the page as inert. An app dialog portalled to the page body (which is what `AlertDialogContent` and
  `DialogContent` do) would draw behind Clerk's panel or fight it for focus. None of that can be proven here,
  because the browser suite runs signed out and never reaches the panel. Clerk's own Delete account, in the
  same panel's Security page, confirms in place with a typed phrase too, so the shaper meets one shape twice.
  The section swaps to a confirmation: the consequences as a list, a field ("Type DELETE to confirm"), the
  final button disabled until the word matches, and Keep my account to back out. The word matches with any
  case and surrounding spaces ignored, because a phone keyboard capitalises the first letter. The browser's
  built-in yes/no prompt is never used.
- **D-05: The colours are pinned to Daylight.** Clerk's panel has no theme from the app (`app/layout.tsx`
  passes only `privacyPageUrl`), so it is white in every app theme. The app's `--surf-*` tokens flip in Slate
  and Phosphor and would draw light text on Clerk's white. The page therefore uses the always-present Daylight
  ramp variables (`--ramp-daylight-ink`, `-ink-muted`, `-line`, `-accent`, `-on-accent`, `-warning-ink`,
  defined unconditionally on `:root` in `app/globals.css`) through Tailwind's `(--var)` arbitrary-value
  syntax. No new hues. Buttons and the field are plain elements, not the shared `Button`/`Input`.
  `components/ui/input.css.test.ts` counts the shared Input's importers exactly, and both shared components
  take their colours from the theme. The field's text is 16px so an iPhone does not zoom on focus. Every
  button and the field grow to a 44-dot row under a touch pointer (`coarse:min-h-11`), the pointer rule from
  CLAUDE.md's Layout section.
- **D-06: The words.** Every string on the page lives in `components/account/your-data-copy.ts`, in sentence
  case like Clerk's panel around it. The support address comes from `CONTACT_ADDRESS` in
  `lib/contact/message.ts`, never retyped. The exact strings are in Task 1 and Task 2.
- **D-07: The ownership test only gains lines.** `lib/db/ownership.test.ts` keeps an explicit list of action
  files. `app/actions/account.ts` joins its three lists, and a new "exports exactly" case is added. No existing
  assertion, title or list entry is changed or removed. Proof: `git diff --numstat` shows 0 deleted lines for
  that file in each task's commit.
- **D-08: Nothing else changes.** No schema change, no migration, no new package, no push, no deploy.
  Clerk's own Delete account in the Security page stays as it is: it still works through the webhook.
</decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Server Action (`app/actions/account.ts`) | The typed word and the call itself arrive from the browser. Identity must come only from the Clerk session. |
| Server Action → Neon | Owner-scoped reads (export) and the owner-scoped atomic delete. |
| Server Action → Clerk Backend API | `users.deleteUser` with the app's secret key, which can delete any user, so the id must be the session's own. |
| exported file → the shaper's device | The file leaves the app and may be shared onward by the shaper. |
