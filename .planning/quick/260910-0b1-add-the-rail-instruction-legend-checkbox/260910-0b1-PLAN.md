<objective>
Give the shaper the same nine line-ticks on the SUMMARY screen that the RAILS screen's
INSTRUCTIONS tab already has, sharing ONE set between the two, so the Rail Band Instructions sheet
prints only the lines the shaper wants to see.

Purpose: today those nine ticks tidy up the figure on the RAILS tab and nothing else — the printed
sheet always draws all nine, so a shaper who has decided he only cares about the deck marks still
gets a page with every rail mark, band and tuck crossing it. The founder wants the ticks to reach
the paper, and wants one set of them rather than two that can disagree.

Three things are settled and not up for revisiting:

- **D-01 — one shared set of ticks for both screens.** Untick Bottom Tuck on RAILS → INSTRUCTIONS
  and the Summary's preview and its print drop it too, and the other way round.
- **D-02 — session-only memory.** Forgotten on reload, starts with all nine on. No cookie, no
  account column, no migration, no server action; `components/print-instructions-provider.tsx` and
  `lib/db/schema.ts` are not touched.
- **D-03 — the printed example rail stays Flat.** Only the nine legend ticks become selectable; the
  Flat/Domed switch does not appear on the Summary.

Output: a small session-only shared set of ticked lines mounted across the design screens, the nine
ticks rendered from one shared component on both screens, the printed sheet reading that set, three
stale doc comments corrected, and the sheet's test file rewritten to assert the new rule instead of
the old one.
</objective>

<design_decisions_settled_here>

**Where the shared set lives — a session-only React context in its own module, mounted in the
design layout.** It is screen state, not board data: it must not enter
`components/design/design-store.tsx`, must not mark a board dirty, must not reach a saved board's
snapshot. That is the same reasoning `components/print-instructions-provider.tsx` already records
("this describes how the shaper prints, not what the board is"), but WITHOUT that file's
localStorage/cookie/account machinery, which D-02 rules out. A plain `useState` in a provider
mounted at `app/design/layout.tsx` gives session-only for free: App Router keeps a shared layout
mounted across a client-side route change, so the set survives RAILS → SUMMARY (both use
`next/link`, verified) and is dropped on a reload, which is exactly the asked-for behaviour with no
storage at all. It gets its own module — not an export from `rail-instructions.tsx` — because the
sheet's existing import-list test pins what may come out of that file.

**The ticks show on the Summary only when the sheet is in the print.** The third sheet is rendered
behind `{printRailInstructions && (…)}`, so with the box unticked there is no sheet on screen and
none on paper. Nine checkboxes with nothing visible to change would be a puzzle, not a control. So
the tick block sits behind the same condition as the sheet itself, immediately below the "Include
Rail Band Instructions in Print" checkbox that reveals it — tick the box, the sheet appears above
and its line controls appear below, in that order down the screen. As a bonus this keeps the
control row exactly as it is today for anyone not printing the sheet.

**How the row stays safe on a phone.** The control row's `flex-wrap items-center justify-center` is
a shipped fix: an unbroken row was the only thing making the Summary scroll sideways on a phone.
Nine more siblings in that same row would interleave with the buttons at intermediate widths. So
the ticks go in ONE nested child carrying `w-full`, which on a flex child of a wrapping row forces
its own line at every width. Desktop keeps buttons-and-hint on line one with the ticks centred
underneath; a phone gets a tidy wrapping block. The widest single label works out around 220px at
`text-xs`, comfortably inside a phone's ~354 dots, so nothing can overhang.

**The page-count hint sentence needs no change, and must not get one.** Both of its wordings
describe how many pages come off the printer — two, or two plus a single-sided instructions page.
Unticking a legend line changes what is DRAWN on that third sheet, never whether it exists or how
many pages it takes. The sentence stays verbatim, and a test pins both strings so it stays that
way.

</design_decisions_settled_here>
