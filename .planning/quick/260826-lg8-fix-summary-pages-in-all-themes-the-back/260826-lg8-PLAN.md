still print as shaded as they help define sections of the document, but should never be black

    Three parts. Two are edits; the third is a check that must be reported rather than a change.

    PART A — the page can never carry a background onto paper.
    Give the scrolling wrapper `<div>` in order-form.tsx a `data-order-form-page` attribute,
    beside the classes Task 1 left on it, and add a rule inside order-form.css's `@media print`
    block forcing that element's background to `#fff !important`. A colour literal is correct
    here and only here: this rule only ever runs against paper, which really is white.

    Why it is needed even though Task 1 already leaves it white on paper: today the sheet's
    printability is a consequence of a chain — globals.css forces the Daylight tokens in print,
    which makes ground white, which makes this wrapper white. That chain is three files long and
    the wrapper is neither `html` nor `body`, which are the only two elements order-form.css
    currently pins white. The founder's "we must ONLY EVER pass a printer friendly version" is a
    request for a guarantee, and a guarantee means it takes an edit to THIS rule, at the point
    where the printed sheet is defined, to put a background on paper.

    PART B — the spine labels print shaded, faintly.
    Add a second rule inside the same `@media print` block giving `.order-form-spine`, scoped
    under `[data-order-form-root]` like every other rule in the file, a background of
    `#ececec !important`.

    Why this is new work rather than a no-op: on screen the spine labels take
    `--order-form-shade`, which follows `--surf-board-fill`, and globals.css pins that token to
    the daylight ground inside `@media print` so the board prints hollow. The side effect is that
    the spine labels currently print with no shade at all. The founder wants them shaded, because
    they are what tells the bands of the sheet apart on paper.

    Why #ececec: it is about 7.5% coverage — 1.18:1 against white — so a printer lays down a
    whisper of tone rather than a block of ink, which is exactly the "never black, never a ton of
    ink" constraint. The label lettering is `text-surf-ink`, which prints as the daylight ink
    #1f2a3b, measuring 12.24:1 on that grey against a 4.5:1 floor. (Even the muted grey would
    clear it at 5.32:1, though no muted text sits on a spine.) It will print whether or not the
    shaper ticks "Background graphics", because the file already sets `print-color-adjust: exact`
    on everything inside a sheet.

    Do NOT get this by re-pointing `--order-form-shade` inside the print block. That token also
    feeds the SHAPER USE ONLY box, which must stay white on paper — the founder's own rule for
    everything besides the spines is a rule or a border rather than a fill. Target the spine
    class directly, which after Task 2 is the only way to move one consumer without the other.

    PART C — check, and report in the SUMMARY, that nothing else fills paper. Confirm each of
    these resolves to white or draws nothing when printing: both sheets' own surface
    (`bg-surf-panel`), the SHAPER USE ONLY box, the fin-system dropdown, and the board drawings'
    interior wash. Confirm the top bar and the Print Order Form button are hidden on paper by
    their `data-print-hide` hook. If any of them still lays down colour, fix it the same way Part
    A is fixed — a named rule inside this print block — and say so in the SUMMARY.

    Finally, write commentary for both new rules in the file's own voice, saying what each one
    guarantees and why the literal is allowed. Someone reading this block later must be able to
    tell that the white page and the grey spine are deliberate decisions, not leftovers.
  </action>
