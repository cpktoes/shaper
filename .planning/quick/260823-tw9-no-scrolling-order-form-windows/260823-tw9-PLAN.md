# Quick Task 260823-tw9 — the sheet is paper, so nothing scrolls

The `RAIL BANDS` panel scrolls. Measured: **62px over at print width** (461 client / 523 content) and
56px over on screen. It is the only scrolling container on either sheet.

A sheet of paper does not scroll, so this is a defect rather than a preference — and the fix is to
make the content fit, not to let the reader drag it.

## Why every previous audit missed it

My clipping checks looked for elements whose content exceeds a box with `overflow: hidden` or `clip`.
This container is `overflow-y-auto`: it **scrolls** rather than clips, so it never appeared. Every
"zero clipping" result in the last several tasks was true and still missed this.

That is worth fixing structurally, not just numerically: switching the panel to `overflow-hidden`
means any future regression shows up as clipping, which the existing audit already catches. A
scrolling panel hides the problem; a clipping one reports it.

## Making it fit

Two levers, and the font is the one the user named:

- **Row type down**, `2cqw` → `1.75cqw` (14.7px → 12.8px at print). Still clear of the 9pt/12px floor
  from `260823-pw7`, which is not negotiable.
- **Row line-height tightened** to `leading-tight`. The rows inherit a 1.5 body line-height, which on
  nineteen rows is most of the overflow on its own. Line-height is not font size, so this costs
  nothing against the floor.

Both tables on page 2 take the smaller row size, not just the offending one — two tables side by side
at different row sizes would read as a mistake.
