<decisions>
Locked by the founder (2026-10-19). Numbering shared with plans 01 and 02.

- **D-04 — "Full passes" means whole passes plus what is left over**, counted from the printed numbers — plan 01's
  `wholePasses` / `formatWholePasses` in `lib/geometry/measure-display.ts` (`2 + 1/16"` / `2` / `0`, Metric
  `2 + 2 mm`). Used as is; this plan adds no second rule.
- **D-12 — The order form matches.** The Summary's printed PLANING table switches its Passes row to whole passes plus
  the rest, through the same helper and the same wording rule as ROCKER's sidebar line and PLANING tab: the Longboard's
  Bottom prints `1 + 1/16"` (Metric `1 + 2 mm`) instead of `2`. Everything printed stays within the sheet's room.
- **D-13 — The fold opens when a tweak is set.** A board that opens — from the rack, a preset, or a reload — with a
  Nose or Tail @ 12" tweak other than 0 shows FOIL's Advanced fold open; a board with no tweak shows it closed; the
  shaper's own tap still toggles it; a tweak set while the fold is open never closes it. The opening state is decided
  once, when the board on screen changes, not re-decided on every slider move.

Planner's choices (each recorded so the founder can overrule):

- **P-18 — "Carries a tweak" is one pure test,** `hasFineTune(blank)` in `lib/geometry/blank.ts`: either stored 12"
  offset is not exactly zero. It is the same test that already makes ↺ Reset Fine-Tune live (`noTweak` in
  `rocker-controls.tsx`, which this plan rewrites onto the helper), so the fold opens by itself exactly when Reset has
  something to reset.
- **P-19 — The printed cells stay on one line.** The Passes cells keep `whitespace-nowrap`; the planing column's own
  `min-width: min-content` floor (order-form.css) takes the extra width wherever the 28% share is not enough. M2
  predicts that happens only on the computer's print (about 10 px) and by under 3 px at 680–812 dots, with the rail
  markings still on one line everywhere. If `summary-planing.spec.ts`'s widest-numbers test says otherwise at any width,
  the fallback is in Task 1's action — never a smaller type size, never a wider share.
- **P-20 — The row label `Passes` and the footnote stay as they are.** Page 2's boxes have no spare height at the
  narrowest phone prints (quick 260928-vpi measured the rail box at 312.5 / 312.5 dots at 560 and 344.5 / 344.5 at
  618), so no explanatory line is added; `1 + 1/16"` under `Passes` reads plainly as one pass and a sixteenth more.
- **P-21 — The fold's rule: decided once, when FOIL appears.** FOIL becomes its own component, `FoilSection`, mounted
  whenever the board on screen has a blank. It holds the fold's open state itself, starting from
  `useState(() => hasFineTune(blank))` — so the state is born with FOIL and read from the board at that moment only:
  - ROCKER opened on a board with a blank — from the rack, a preset or another screen — mounts FOIL with that board;
  - a page reload starts from the stock board, which has no blank, so FOIL appears only once the reload brings the
    shaper's own board back (quick 261019-ep5's restore, whenever it lands), and is born with that board;
  - a first blank pick (tweaks start at 0) and an undo that brings a removed blank back both mount FOIL afresh.
  After that the state changes only on the shaper's tap. Switching blanks keeps FOIL mounted (and keeps the tweaks,
  D-11 of Phase 12), and closing FOIL's own heading hides its rows without unmounting `FoilSection`, so neither resets
  the fold. No effect, no state set during render, no store change and no new key are needed (this repo's lint rejects
  the first two). The one gap, recorded here on purpose: a board replaced wholesale while ROCKER stays on screen with a
  blank on both boards would keep the fold as it was — no path in the app does that today (the rack and the presets
  live on the home page; a reload starts from the stock board).
- **P-22 — `advanced` leaves `sectionOpen`.** Plan 01 put the fold's state in `rocker-editor.tsx`'s `sectionOpen`
  (`advanced: false`) and `RockerControlsSectionKey`; both lose the `advanced` key, since `FoilSection` owns it now.
</decisions>
