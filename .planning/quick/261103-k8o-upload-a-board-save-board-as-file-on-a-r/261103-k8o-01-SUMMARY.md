# Quick 261103-k8o Plan 01: Save a Board as a File, and Open a Board File Summary

**A saved board's ⋯ menu on the Board Rack now has Save board as file…, which downloads that one board as a
small file named after it (`Fish 5'10.shaper-board.json`). The home page has Open a board file… under the
preset cards, which opens such a file — a friend's or your own — as a new, unsaved board on TEMPLATE, signed
in or not. Nothing reaches the account until the shaper presses Save. No web link, and no database change of
any kind.**

## What changes for the founder

- **The ⋯ menu on a saved board** (the Board Rack, computer and phone) reads Rename, Duplicate, **Save board as
  file…**, Lock board, Delete — with Move left and Move right above them on a computer. Save board as file…
  downloads the one board straight away. It works on a locked board too, because saving a copy changes nothing,
  and nothing on the rack moves. On an iPhone, Safari asks first whether to download the file.
- **The file** is named after the board, with anything a computer won't allow in a file name taken out
  (`Fish 5'10"` saves as `Fish 5'10.shaper-board.json`; a board with no name saves as
  `Untitled Board.shaper-board.json`). It is about 8 KB. It holds the board's name and its design exactly as the
  account keeps it — every length in millimetres, whichever units you view in — and nothing else: no board id,
  no account, no lock, no settings. Send it by Messages, AirDrop or email like any file.
- **Opening one** — the home page, under the four preset cards, has an outlined **Open a board file…** button
  with your line under it: "A board someone saved as a file, or one of your own. It opens as a new board."
  On a phone the button is finger-sized. Picking a board file opens it on TEMPLATE as a new board under the
  file's own name, with its blank, its foil and everything else exactly as saved. It is unsaved, so the rack
  shows it as "In progress — not saved", a reload keeps it, and Save puts it on the account like any new board.
  It works signed out too.
- **A board already in progress** — opening a file first asks **"Open this board file?"** ("This replaces your
  board in progress. It hasn't been saved — opening this file will lose it."). Keep Editing leaves the board in
  progress exactly as it was; Discard & Open opens the file's board.
- **A whole Export my designs download** (from the Your data page) that holds just one board opens the same
  way. One that holds more says, under the button: "That file holds 3 boards. To add them all to your account,
  sign in and use Import my designs on the Your data page." (Import my designs is plan 02.)
- **A wrong file** says why in one quiet line under the button and changes nothing — never a pop-up:
  "That file isn't a Shaper Assistant board file.", "The board in that file couldn't be opened. The file may be
  damaged.", "That file holds no boards.", "That file is too big to be a board file (over 20 MB)." or "Couldn't
  read that file. Try again." The line clears the next time a file is picked.
- **A board saved on the old blank cut** (before Phase 12) opens with the shaper's own Tip Style from the gear
  menu, as such a board does from the rack.

### For the founder's look, on a real phone

Save a board as a file on the iPhone (Safari asks before it downloads; the file lands in Files → Downloads),
send it by Messages or AirDrop, and on the receiving phone press Open a board file… and pick it from Files. The
file picker's `.json` filter on real iOS is the one thing the browser tests cannot prove: if iOS greys the file
out in the picker, say so and the filter can be widened.

One thing in `after-opened-desktop.png` that looks wrong but isn't: the tab band over the drawing reads
**Untitled**, not "Friend's Fish". That is the band's own rule since quick 261008-raw (the founder, 2026-10-08):
a board that has never been saved reads Untitled there. The file's name is kept as the board's name — the rack
caption shows it, SUMMARY's Board Name box holds it, and the top bar's Save saves straight under it without
asking for a name.

## How it was built (the plan's choices, as applied)

- **PC1** — the file is `{ about, fileVersion: 1, kind: "board", exportedAt, board: { name, design } }`, written
  with two-space indents; `design` is `buildSnapshot({ ...fields, boardName: name })`, the very shape a saved
  board's row holds. A test checks every practice board's file text for `"id"`, `"clerkUserId"`, `"locked"`,
  `"createdAt"` and `"settings"` and finds none.
- **PC2** — `boardFileName`: `/ \ : * ? " < > |` and control characters become spaces, runs of spaces become
  one, leading dots and surrounding spaces and dots are trimmed, cut to 80 whole letters by `Array.from`, and
  an empty result is `Untitled Board`.
- **PC3** — `readOneBoardFile` takes a one-board file and an Export my designs file holding exactly one board;
  refusals `too-big` (20 MB, checked on the picked file's size before reading and on the text), `not-ours`,
  `no-boards`, `many-boards` (with the count), `unreadable`. The download's `settings` are never read.
- **PC4** — readable means `parseSnapshot` takes the design AND `rackBoardFigures` can draw it, inside one try
  that answers null. The name is trimmed and cut to 200 whole letters and wins over the design's own
  `boardName`.
- **PC5/PC6** — the menu row sits straight after Duplicate in plain ink; `handleSaveAsFile` calls
  `downloadBoardFile` at once inside the tap (nothing awaited first, for Safari), speaks "Saved as
  {file name}." and shows a failure in the status pill. The download lives in
  `components/setup/board-file-download.ts`, outside the rack's own files, because `rack-source.test.ts`
  forbids any rack file from making a browser address for a file; that test still passes untouched.
- **PC7** — the control is the app's own outlined Button with a hidden file input, the muted line, and one
  quiet status line (`role="status"`, `aria-live="polite"`), `mt-8` (`mt-6` on a phone), inside
  `[data-setup-content]` after the preset grid. The input is emptied after every pick.
- **PC8** — `applyBoardFile(snapshot)` is a third store function beside `applyPreset` and `applyModel`:
  `{ ...DEFAULT_DESIGN_STATE, ...snapshot, modelId: null, locked: false, boardStarted: true, dirty: true }`,
  with applyPreset's resets and applyModel's failure-count reset. Two existing store contract tests gained it
  beside `applyPreset` (it starts a new board, so it neither checks the lock nor calls `startedFrom`).
- **PC9** — the control reads `useFitDefaults().defaults.tipStyle` and passes it to the reader.
- **PC10** — `ReplaceBoardDialog` gained the `open-file` mode ("Open this board file?", "Discard & Open",
  "opening this file"); the file is read before anything is asked.
- **PC11** — every word as the plan lists it, in `components/setup/board-file-copy.ts` (no React import) and
  `RACK_COPY` (`saveAsFile`, `savedAsFile`, `saveAsFileFailed`, pinned in `rack-config.test.ts`).
- **PC12** — nothing is converted; no inch or millimetre figure is typed anywhere new.
- **No database change** (R2): nothing under `lib/db/` or `drizzle/` was touched; no server action was added.
