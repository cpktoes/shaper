# Quick 261103-k8o — a board file goes both ways: save one board as a file, open a board file, import a whole download

The founder, 2026-11-03: **"I can download my board data from the site, but I need a way to upload it (or send a
board to a friend)."**

Today a signed-in shaper can press **Export my designs** on the Your data page (Clerk's account panel, from the
avatar menu) and get one `.json` file holding every saved board and their settings, exactly as stored. Nothing
reads such a file back, and there is no way to hand one board to someone else.

## The founder's rulings (asked and answered 2026-11-03)

- **R1 — both paths, as files.** (a) The friend path: a saved board's ⋯ menu on the Board Rack gets **Save board
  as file…**, which downloads that one board as a small `.json` file; the home page gets **Open a board file…**,
  which opens such a file as the board in progress, signed in or not, and Save then puts it on the account like
  any new board. (b) The restore path: the Your data page gets **Import my designs**, which takes a whole Export
  my designs file and puts its boards on the account. Two plans, the founder's look between them.
- **R2 — a file, never a web link.** No share-link table, **no database change at all** (the saved board is one
  JSON column; the import inserts rows exactly as Duplicate does). If a database change ever looks necessary, the
  planner stops and says so rather than planning it.
- **R3 — Import my designs previews, then one choice.** Before anything is written it reads the file and says what
  will happen: how many boards will be added (by name) and how many are already on the account (matched by board
  id) and will be left exactly as they are. One tick box, **off by default**: *also add the file's versions of the
  already-there boards as copies* (named the way Duplicate names a copy). Then **Import** or **Cancel**. **Nothing
  on the account is ever overwritten**, a locked board included. Settings in the file are ignored; the account's
  own settings stay as they are. (The founder asked "should the app ask to skip rather than just blind skipping?"
  — this is the answer: a preview that tells, with one choice, never a per-board yes/no.)

## Rules

- **No database change** (R2). No new table, no new column, no migration.
- **A file is untrusted input.** Everything read from a file goes through `parseSnapshot` (one board) or a Zod
  schema of the download file's shape plus `parseSnapshot` per board (the whole file), with a size cap on the file
  (say 20 MB) and on the board count, before anything is shown or written. A board that fails to parse is reported
  by name/position and skipped, never half-written; a file that is not one of ours says so in plain words.
- **One board's file** — its own shape, say `{ about, fileVersion: 1, kind: "board", exportedAt, board: { name,
  design } }` (no id, no account id, no dates needed), name `<board name>.shaper-board.json` with the name made
  safe for a file system (or `Untitled Board`). Open a board file… accepts BOTH a one-board file and a whole
  download file holding exactly one board; a download file holding more than one board is refused with words
  pointing at Import my designs on the Your data page.
- **Import my designs** — a server action in `app/actions/account.ts` (or a sibling) that takes the parsed boards
  (never a user id), re-parses every board on the server, skips ids already on the account, inserts the rest
  with `locked: false` and their file names, keeps the file's `createdAt` ONLY if the planner finds it harmless
  (otherwise now), places them in the rack order (first, newest at the front — `orderWithNewBoardFirst` per board,
  or one batched placement), `revalidatePath("/")`, and answers counts: added, already there, copies, failed. The
  preview is computed client-side from the file plus the account's board ids — a small read action
  (`listModelIds`) or the import action run in a `dryRun` mode; the planner picks one and says why. All-or-nothing
  per board (one insert each), never one transaction for the whole file that a single bad board can roll back.
- **Plain English everywhere** (CLAUDE.md): words a shaper reads, commit messages, the SUMMARY. "File", "board",
  "already on your account", never "snapshot", "envelope", "JSON".
- **Rule 2** — nothing in these files is converted: a file is the stored metric data. No `25.4` anywhere new.
- **Tests before code** for every pure function (file shapes, the added/already-there/copies rule, the safe file
  name), relation tests, never a hand-typed geometry number. `npm test`, `npx tsc --noEmit` (after `npx next
  typegen` in a fresh worktree), `npm run lint`, and the rack/home browser specs on all projects; the five desktop
  reference pictures must pass unchanged, or the plan says which moves and why.
- **Pictures before the founder's look**: the ⋯ menu open with Save board as file…, the home page's Open a board
  file… control (computer and phone), the replace prompt for a file, the Your data page's new section with a
  preview showing "3 will be added · 9 already on your account" and the tick box (a stand-in render, since Clerk's
  panel can't be driven — the component rendered in a scratch page or a static mock from the real markup is
  acceptable, say which).
- **Where the home-page control sits**: below the preset cards (both layouts), a quiet outlined button in the app's
  own Button, 44-dot under a coarse pointer, with a hidden `<input type="file" accept=".json,application/json">`;
  the words: "Open a board file…" and one line under it: "A board someone saved as a file, or one of your own."
  (the planner may improve the words; sentence case, no jargon).
- **The GSD mechanics**: two plans, `261103-k8o-01-PLAN.md` (Save board as file… + Open a board file…) and
  `261103-k8o-02-PLAN.md` (Import my designs with its preview), each self-contained with its own tests, pictures,
  gates and SUMMARY; plan 02 may depend on plan 01's file-shape module. The planner commits its plans on main.
