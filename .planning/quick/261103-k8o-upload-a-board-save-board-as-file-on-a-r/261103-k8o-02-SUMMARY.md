# Quick 261103-k8o Plan 02: Import My Designs Summary

**The Your data page in the account panel now has Import my designs, between Export my designs and Delete my
account. It takes a whole Export my designs file back. Before anything is written it says which boards will be
added (by name), how many are already on the account and will be left exactly as they are, and which couldn't be
read. One tick box, off every time, also adds the file's versions of the boards already there as copies. Then
Import or Cancel. Nothing on the account is ever overwritten or deleted, a locked board included. The file's
settings are ignored, and there is no database change of any kind.**

## What changes for the founder

- **Where it is.** Avatar menu → Your data. The page now has three sections in this order: Export my designs,
  **Import my designs**, Delete my account. The new section reads: "Add the boards from an Export my designs file
  to your account. Boards already on your account are never changed, and your settings stay as they are." Under
  it, an outlined **Choose a file…** button.
- **The preview.** Pick a file and the section says, in place (never a pop-up):
  "From shaper-assistant-designs-2026-11-03.json:", then "3 boards will be added: Mid-length, Fish and
  Shortboard.", then "9 are already on your account and will be left exactly as they are." Past six names it says
  "and 7 more". A board in the file that can't be read is named on its own line and skipped. Nothing has been
  written at this point.
- **Why nothing on the account changes.** "Already on your account" means a board with the same board id is on
  the account, even if it has been changed since the download. That board is never touched. The import only ever
  adds new boards, each one unlocked. It never updates or removes anything. The server checks every board again
  before writing it, by the same rule a save uses.
- **The tick box.** It only appears when some boards are already there, and it is off every time a file is read:
  "Also add the file's versions of those 9 as copies ("Copy of …")". Tick it and those boards also go in as
  copies, named the way Duplicate names one ("Copy of Fish"). If every board is already there and the box is off,
  the section says "Every board in this file is already on your account. Tick the box to add the file's versions
  as copies." and Import can't be pressed.
- **Import.** The button counts as it goes ("Importing… 25 of 40"), and Cancel and the tick box can't be pressed
  meanwhile. Cancel before Import sends nothing.
- **Where the boards stand.** Everything one import adds, copies included, stands at the front of the Board Rack,
  the file's newest board first (your ruling). In a rack you have never arranged nothing is written to the order:
  the rack already puts the newest first.
- **Importing the same file twice adds nothing twice.** Each board keeps its own id from the file, so the second
  time every board reads as already on the account.
- **The done line.** One plain line, for example: "Added 3 boards to your account. They stand at the front of
  your Board Rack. 9 already on your account were left as they were." It also names any board that couldn't be
  read or written ("1 couldn't be read and was skipped: board 3."). The line is in the warning colour when
  something was skipped.
- **Wrong files** each get one line in the warning colour, and nothing changes: "That file isn't an Export my
  designs file from Shaper Assistant.", "That file holds no boards.", "That file is too big (over 20 MB).",
  "That file holds more than 500 boards, more than one import can take." or "Couldn't read that file. Try
  again." A one-board file saved from a rack card (plan 01) is accepted too, and its board is always added.
- **Settings in the file are left alone.** Units, fit and tip defaults, blank makers, starred blanks and rack
  order on the account stay exactly as they are.
- **Duplicate** now names its copy through the same rule as the import, so the two can never drift apart. What
  you see doesn't change: still "Copy of …".
- **The Privacy Policy.** Section 6, Your choices, the Export your designs line now ends with exactly one new
  sentence: **"You can put a downloaded file back onto your account with Import my designs."** Nothing else in the
  policy changed. The effective date at the top is still October 10, 2026 (see the open question below).

## Your check, signed in on your own review server

Do this on your own review server, which uses the development database, never production:

1. Avatar menu → Your data → **Export my designs**. Keep the file.
2. On the Board Rack, delete one board (one that isn't locked).
3. Your data → **Import my designs** → Choose a file… → pick that file. The preview should say **1 board will be
   added** (by its name) and the rest **are already on your account**.
4. Press **Import**. The deleted board should be back at the front of the rack.
5. Import the same file again. It should say every board is already on your account, and Import can't be
   pressed.
6. Tick the box once and Import, to see the copies ("Copy of …") at the front of the rack. Delete them after if
   you like.

## How it was built (the plan's choices, as applied)

- **PC13: how the preview knows what's on the account.** A new read-only action, `listMyBoardIds`, answers the
  signed-in shaper's own board ids (one select). The page works out the preview with the same `planImport` the
  import runs on the server. There is no "dry run" mode of the import, for three reasons. A Server Action takes
  at most 1 MB a call, so a dry run would have to send the whole file just to count it. A look-only switch on the
  action that writes would leave one yes-or-no between looking and writing. And the ids are tiny. If the preview
  goes stale (a board added from another device in the meantime), only a count can be wrong, because the server
  decides again at the moment it writes.
- **PC14: dates.** Both dates of an imported board are the database's own, today. Nothing a shaper sees shows the
  date a board was made, and the file's dates are untrusted text. The last-changed date must be today anyway for
  the rack to put the board at the front.
- **PC15: ids kept.** A board keeps the file's id when it is free: the write carries the id and does nothing on a
  clash. On a clash the board goes in again with a fresh id. A clash can only be another account's board, which
  is never touched or revealed. Only an id in the database's own form is kept, and a repeated or malformed one
  reads as no id. Copies always take fresh ids.
- **PC16: batches.** The page sends at most 25 boards a call, and fewer when their design text passes 600,000
  characters. One board's design is at most 64,000 characters, and a file holds at most 500 boards. The server
  refuses a call of more than 25.
- **PC17: rack order.** Your ruling. In an arranged rack, the stored order after each call is the existing
  "new board first" rule applied to each added board in turn, so the last added stands first. A failed placement
  is logged without the error (which can carry the account id) and never fails the import.
- **PC18: one copy-name rule.** `boardCopyName`, used by the import and by Duplicate.
- **PC19:** a one-board file is accepted, as one board with no id.
- **PC20: reading.** Plan 01's `readBoardFileContents` and `readBoardEntry` (the save reader plus the rack's
  drawing check), plus the caps above. One private helper reads a board for both the page and the server. An
  empty name becomes "Untitled Board", and the design's own name is set to it.
- **PC21: the action.** Sign-in first, then the request checked, then the Tip Style looked up only when a board
  still carries a pre-Phase 12 blank, then every board read again. Next the account's ids are read and
  `planImport` decides. Each board is one insert inside its own try, unlocked; never an update or a delete. Then
  the rack placement, and the page refreshed when anything was added.
- **PC22, PC23: the section and its words.** In place, Daylight colours only, plain elements, every button and the
  tick box's row 44 dots under a finger. The words are in `YOUR_DATA_COPY.import`. The view (no action, no Clerk)
  is drawn in unit tests and the stand-in page; the section holds the steps.
- **PC24: pictures** from a stand-in route gated by the practice-rack flag, archived with the shoot script as
  `pictures/shoot-source-02.tar.gz` and deleted. No such route is in the code.
- **PC25: the Privacy Policy.** The one sentence, quoted above, test first. `git diff` shows one line changed in
  `content/legal/privacy.md`; `terms.md` is untouched.
- **R2: no database change.** Nothing under `lib/db/schema.ts` or `drizzle/` changed, and nothing was migrated.
  The real database was never reached: the actions are proven against a fake database.

## Deviations from Plan

**1. [Rule 1 - Bug] A long file name broke mid-word on the iPhone**
- **Found during:** Task 3's after pictures.
- **Issue:** the preview's "From …:" line used `break-all`, which split "…2026-11-03.json:" as "…03.js" / "on:".
- **Fix:** `break-words`, the class the app already uses elsewhere. The name now wraps after "2026-11-".
- **Commit:** 86274b05.

**2. The page's class strings moved into one new shared file,** `components/account/your-data-classes.ts`. The
plan let me choose between this and repeating them. The page keeps its own names, pointed at the shared strings,
so nothing it draws changed (the before and after pictures match above and below the new section).

**3. The fake database answers each statement by what it is** (the account's ids, the stored order, a board
written), rather than from a queue in a fixed order. The import makes a varying number of statements, so a queue
would have tested the order of the calls rather than what they write. The case list is the plan's.

**4. Two of my own test expectations were wrong at first and were fixed in the test, not the code.** The save reader
fills a missing part of a design from the app's defaults, so a "broken" board is now one shorter than any board can
be. The button checks first matched the `disabled:` styling in the class string rather than the real `disabled`
attribute. Both corrections are in commits 5f542e1a and eaff980e.

**5. The pictures hide the development server's own "N" badge,** which a shaper never sees, so it doesn't cover
Delete my account in the iPhone picture.

**6. The commit trailer** reads `Co-Authored-By: Claude Opus 5.5`, the attribution this environment requires,
rather than the line the orchestrator named (as in plan 01).
