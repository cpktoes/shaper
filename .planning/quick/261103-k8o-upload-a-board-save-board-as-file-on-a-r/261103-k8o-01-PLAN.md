<objective>
The founder, 2026-11-03: "I can download my board data from the site, but I need a way to upload it (or send a board
to a friend)." This plan is the friend path (R1a). A saved board's ⋯ menu on the Board Rack gets **Save board as
file…**, which downloads that one board as a small file. The home page gets **Open a board file…**, which opens such a
file as a new, unsaved board — signed in or not — so Save then puts it on the account like any new board.

Purpose: a shaper can hand one board to a friend, or keep one board as their own file, without any web link and
without any database change (R2). Plan 02 (Import my designs) runs after the founder has looked at this one, and
reuses this plan's file module.

Output: the pure file module with its tests, the menu row, the home-page control, one new store function, the replace
prompt's third wording, a browser spec on a computer and both phones, before/after pictures and the SUMMARY.
Nothing pushes, merges, deploys or migrates.

**Locked by the founder (the BRIEF, read it first):** R1 both paths, as files — this plan is (a), the friend path; R2

**Planner's choices (each overrulable by the orchestrator):**
- PC1 — The one-board file's shape, per the BRIEF: `{ about, fileVersion: 1, kind: "board", exportedAt, board: { name,
  design } }`. `design` is the saved-board envelope `buildSnapshot({ ...fields, boardName: name })` — the very shape a
  saved board's row holds, so the save reader reads it. No board id, no account id, no lock, no settings, no dates but
  `exportedAt`. Written with two-space indents, the way Export my designs writes its file. `about` is one plain
  sentence: what the file is, where it opens (Open a board file… on the home page), and that lengths are millimetres
  whichever units the shaper views in.
- PC2 — The file's name is `<board name>.shaper-board.json`. The board name is made safe for any computer: each of
  `/ \ : * ? " < > |` and every control character becomes a space, runs of spaces become one, leading dots and
  surrounding spaces and dots are trimmed, and it is cut to 80 whole letters (never splitting an emoji — cut by
  `Array.from`). An empty result is `Untitled Board`. So `Fish 5'10"` saves as `Fish 5'10.shaper-board.json`.
- PC3 — One reader for Open a board file…, `readOneBoardFile(text, options)`. It accepts a one-board file AND a whole
  Export my designs file holding exactly one board (the BRIEF). Refusals, each a plain line (PC11): `too-big` (over
  20 MB — checked on the picked file's size before it is read, and again on the text), `not-ours` (not JSON, or no
  shape of ours, or a `fileVersion` other than 1), `no-boards`, `many-boards` (with the count — the words point at
  Import my designs), `unreadable` (the board itself can't be opened). The download file's `settings` and every other
  key are ignored and never validated.
- PC4 — A board in a file is readable only if `parseSnapshot` takes its design (with the shaper's Tip Style for a
  Phase 11 blank, PC9) AND the rack's own drawing check, `rackBoardFigures` (`lib/models/rack-models.ts`), works it out.
  That is the exact rule a saved board must pass to stand on the rack; without it a board could open that the rack
  would later drop. The board's name is the file's `name` (a string, trimmed, cut to 200 whole letters), and it wins
  over the design's own `boardName`, which is set to it — the same pinning `saveModel` does. An empty name opens as
  an untitled board (`""`, which the app shows as Untitled Board).
- PC5 — Save board as file… is a `Menu.Item` straight after Duplicate and before the lock row, in plain ink (never the
  warning colour), and it works on a locked board (saving a copy changes nothing). It is a pure download in the
  browser — no server action — from the card's own `RackModel` (`model.name`, `model.snapshot`): the board exactly as
  its card shows it, which is the saved board. The download runs synchronously inside the row's click, with nothing
  awaited first (unlike Duplicate, which waits for order saves): Safari, the iPhone's above all, refuses a download
  that starts after the tap has gone stale. The confirmation is spoken only (`announce(…, { visible: false })`, like
  Duplicate's); a failure is shown in the rack's status pill. No new line in the caption: `rack-source.test.ts` pins
  the caption to exactly two warning-ink lines.
- PC6 — The download itself lives in its own small file, `components/setup/board-file-download.ts`, never in a rack
  file: `components/setup/rack-source.test.ts` forbids every rack file from making a browser object address (its "no
  picture is stored or exported" rule, SPEC constraint 3). A file whose name has no "rack" in it is outside that
  contract by its own design. It uses the Your data page's hidden-link pattern (a Blob of type `application/json`, an
  object address, a hidden `<a download>` added to `document.body`, clicked, removed, and the address let go a minute
  later for Safari).
- PC7 — Open a board file… sits under the preset cards in both layouts, inside `[data-setup-content]`, after the
  cards' grid: the app's own `Button` (`variant="outline"`, default size — 32 dots drawn, 44 under a coarse pointer by
  the Button's own pointer rule), with a hidden `<input type="file" accept=".json,application/json">` beside it, then
  one muted line under it, then one quiet status line for problems (`text-xs`, the warning ink the rack uses for its
  failure lines, `role="status"`, `aria-live="polite"`), cleared on the next pick. The input's value is reset after
  every pick so the same file can be picked again. Spacing: `mt-8`, `max-shell:mt-6`.
- PC8 — `applyBoardFile(snapshot)` is a third store function beside `applyPreset` and `applyModel` (the BRIEF): the
  board from the file with `modelId: null`, `locked: false`, `boardStarted: true`, `dirty: true`, built as
  `{ ...DEFAULT_DESIGN_STATE, ...snapshot, modelId: null, locked: false, boardStarted: true, dirty: true }` — the same
  spread the kept-board read-back uses, so a field added to a saved board later can't be missed. It makes
  `applyPreset`'s resets and `applyModel`'s failure-count reset. Never `applyModel` with a made-up id.
- PC9 — A Phase 11 blank in a file is carried over with the shaper's own Tip Style: the control reads
  `useFitDefaults().defaults.tipStyle` and passes it to the reader, as the rack passes the account's.
- PC10 — Through the replace prompt: with a board in progress (`hasBoardInProgress`), a readable file waits behind
  `ReplaceBoardDialog` in a third mode, `open-file`: title "Open this board file?", action "Discard & Open", verb
  "opening this file". The dialog's words stay in the dialog's own file (rack-config.ts's rule). The file's board is
  read BEFORE the prompt, so a bad file never asks anything — it just says so under the button.
- PC11 — The words (sentence case, no jargon), in a new `components/setup/board-file-copy.ts` with no React import so
  the browser tests can import it (rack-config.ts's own rule):
  - button "Open a board file…"; the line under it "A board someone saved as a file, or one of your own. It opens as
    a new board."
  - `tooBig` "That file is too big to be a board file (over 20 MB)."
  - `notOurs` "That file isn't a Shaper Assistant board file."
  - `noBoards` "That file holds no boards."
  - `manyBoards(n)` "That file holds {n} boards. To add them all to your account, sign in and use Import my designs
    on the Your data page."
  - `unreadable` "The board in that file couldn't be opened. The file may be damaged."
  - `readFailed` "Couldn't read that file. Try again."
  The rack's new words go into `RACK_COPY` (the BRIEF): `saveAsFile` "Save board as file…", `savedAsFile(fileName)`
  "Saved as {fileName}." (spoken), `saveAsFileFailed` "Couldn't save this board as a file. Try again."
- PC12 — Nothing in a file is converted (Rule 2): a file is the stored metric data. No inch or millimetre figure is
  typed anywhere new.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| picked file → the browser's design store | A file from anyone (a friend, a download, a stranger) becomes the board on screen |
| saved board → downloaded file | A board leaves the app; only the board itself may go with it |
| opened board → Save | A board from a file reaches the account only through the existing `saveModel`, which re-reads it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-k8o-01 | Tampering | `readOneBoardFile` / `readBoardEntry` | high | mitigate | Zod shapes for the outer file and the entry, then `parseSnapshot` (bounded numbers, lengths, blank stations, strings) and `rackBoardFigures`, all inside one try that answers null; the name is cut to 200 letters; unknown keys are never read. Tested refusals for every malformed case (Task 1). |
| T-k8o-02 | Denial of service | the file picker | medium | mitigate | `BOARD_FILE_MAX_BYTES` (20 MB) checked on the file's size before it is read and on the text before it is parsed; one board's reading costs milliseconds (M2). A file holding many boards is refused by count without reading them. |
| T-k8o-03 | Information disclosure | `buildBoardFile` | medium | mitigate | The file holds the board's name and design only — no board id, account id, lock, dates of the row or settings; a test checks the text for each of those keys. |
| T-k8o-04 | Tampering (integrity of the account) | Open a board file… | medium | mitigate | `applyBoardFile` always sets `modelId: null` and `locked: false`, so a file can never write over a saved board; the first Save goes through `saveModel(null, …)`, which re-parses the design on the server (existing T-02-05). |
| T-k8o-05 | Spoofing / XSS | a board name from a file | medium | mitigate | Names are rendered as React text only (caption, tab band, prompt); the download name passes through `boardFileName`'s character rule; nothing is set as markup. |
| T-k8o-06 | Repudiation | replacing a board in progress | low | mitigate | A readable file waits behind the replace prompt whenever a board is in progress; Keep Editing changes nothing (f7). |
