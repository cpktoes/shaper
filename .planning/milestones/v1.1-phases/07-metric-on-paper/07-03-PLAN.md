<objective>
Make the Overview Sheet read in the system the shaper chose.

The Overview Sheet is the one-page summary a shaper prints alongside a template: the board drawn
small with its dashed reference stations, and a spec block down the side listing every number that
defines the shape. It is not a 1:1 print — nothing on it is measured with a ruler — so the only thing
this plan changes is what the words and figures say.

Purpose: a shaper who designed in centimetres hands over an Overview Sheet whose spec block reads in
centimetres, so the sheet and the screen agree number for number.

Output: the spec block, the length callout, the widepoint offset label, the dashed station names and
the station width figures all following the chooser; the drawing itself untouched.
</objective>

Convert the three pieces of text that sit on the drawing itself rather than in the spec block.

**The length callout.** Add a required `system: UnitsSystem` parameter to
`overviewLengthLabelText(length, system)`. Imperial keeps its existing dual form exactly — the
feet-and-inches figure, the existing separator, and the same length again as a plain inch fraction.
Metric has no counterpart to that dual form: feet-and-inches is an imperial idea, and printing a
centimetre figure twice would be noise. So Metric returns the single centimetre figure with its own
`cm`, composed through `formatDim`. This matches the discretion note Phase 6 already applied to the
on-screen outline callout, so the printed sheet and the screen agree.

**The widepoint offset label.** Add a required `system` parameter to
`overviewWpOffsetLabelText(offset, system)`. Keep the function's existing intent exactly: the
direction word is decided from what will actually be **printed**, not from the raw number, so an
offset small enough to round away at print precision prints unsigned with no direction word rather
than claiming a direction it cannot show. On Metric that means comparing the printed centimetre
magnitude against its own zero form; on Imperial it means comparing the printed inch fraction against
its own zero form, exactly as today. The wording — the label prefix and the two direction words — is
identical in both systems; only the magnitude changes.

**The station width figures on the drawing.** In the loop that draws each dashed reference line, the
figure printed to the left of the line is the board's own full width at that station — a **dim**, per
D-04. Route it through `formatDim(mm(halfWidth * 2), system)`. Do not use the marks formatter here: a
Metric sheet printing `400 mm` beside a station whose name reads `30.5 cm` puts two different metric
families on one line, which is exactly the confusion D-03 already fixed on the Paper Saver.

Thread `options.system` from `buildOverviewPdf` into the drawing loop, into
`overviewLengthLabelText`, and into `overviewWpOffsetLabelText` wherever they are called.

Convert the dashed reference lines' names, and handle the one place in this phase where the chosen
system legitimately changes what gets *drawn* rather than only what gets *said*.

Add a required `system: UnitsSystem` parameter to `overviewStationLines(geometry, system)` and pass
`options.system` in from the drawing loop.

**The station names.** The two twelve-inch lines' names compose from `stationLabel(system)` rather
than a hardcoded inch string, so Metric reads `NOSE @ 30.5 cm` and `TAIL @ 30.5 cm` in the sheet's
existing small-caps style. The stations themselves do not move — this is a name change only.
`CENTER`, `WIDEPOINT` and the merged `WIDEPOINT / CENTER` are plain English words with no unit inside
them and are returned unchanged in both systems.

**The merge threshold.** Keep the function's existing intent exactly as its own comment states it:
the decision to merge WIDEPOINT and CENTER onto one dashed line is made from the **printed**
magnitude of the offset in the **active** system, never from a raw tolerance. Concretely, compare the
printed magnitude against that system's own zero form — the metric zero form on Metric, the imperial
zero form on Imperial — using the same display-boundary formatter the label itself uses, so the merge
and the label can never disagree about whether the offset is zero.

Be explicit in the code comment about the consequence, because it is real and it is intended: Metric
prints to a millimetre where Imperial prints to a sixteenth of an inch, so an offset of about a
millimetre merges on an Imperial sheet and does not merge on a Metric one. That is the honest
outcome of "decide from what is actually printed" — pinning the threshold to one system would make
one of the two sheets draw a directional label for an offset it prints as zero. Nothing a shaper
measures moves either way; only how many dashed lines get drawn.

unmerged case in **each** system; and — the important one — a case at an offset chosen so it rounds
away in one system and not the other, asserting the merged result in the first and the two-line

forms rather than hand-picking a millimetre figure.
