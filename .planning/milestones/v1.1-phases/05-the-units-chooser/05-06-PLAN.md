  <action>
    Create `components/viewer/toolbar-button.tsx` (a `"use client"` module in the shared viewer
    directory) exporting:

    - `ViewerToolbarButton` — the button. Props: `onClick`, `label` (used for both the accessible
      name and the tooltip when they match), an optional separate `title` for the buttons whose
      tooltip text differs from their accessible name, `pressed?: boolean`, `slot`, `children` (the
      icon), and `className?`. It renders a real `<button type="button">` carrying the exact base
      class string both files use today — the cursor, flex centring, rounded corners, the border and
      ground background, the muted icon colour, the colour transition, the removed outline, the
      hover accent fill paired with its on-accent icon colour, the focus ring, and the absolute
      positioning with its z-index. When `pressed` is supplied, it also sets the pressed attribute
      and adds the pressed add-on classes that keep the accent fill while the toggle is on — again
      paired with the on-accent icon colour in the same variant. When `pressed` is not supplied the
      button must carry **no** pressed attribute at all, so a one-shot action never announces itself
      as a toggle.
    - `ViewerToolbarSlot` — the position. The buttons step along the top-right edge at fixed
      offsets, and Tailwind can only see class names that appear whole in the source, so the slot
      must map through a literal record from a small ordinal (`0` through `3`) to the four complete
      offset class names used today. Do not build an offset class by concatenating a number onto a
      prefix. Document that constraint in a comment; it is the kind of thing that looks like a
      harmless simplification and silently produces an unstyled button.
    - `RotateBoardIcon` — moved here verbatim from `outline-editor.tsx`, including its per-instance
      id derived from `useId` (the glyph is referenced by id twice inside one SVG, and a literal id
      would collide if two of these ever rendered on one page) and its full explanatory comment
      about the two reused planshapes, the shared scale, the stroke width chosen so the drawn weight
      lands correctly after that scale, and why the button uses the larger icon size.

    Give the module a header comment saying plainly what it is and why it now exists: the same
    button was mirrored by hand across the TEMPLATE and ROCKER screens, that mirroring was edited in
    all seven places twice in one day, and the accent fill and its paired icon colour must never
    again live in two files that can drift.
  </action>
