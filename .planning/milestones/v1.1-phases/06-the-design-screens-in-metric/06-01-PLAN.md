<objective>
Prove the whole metric display chain end to end on one measurement — the TEMPLATE screen's
widepoint width — then finish the rest of the TEMPLATE screen's numbers.

In plain English: a shaper who has picked Metric opens the Template Builder and every number on
it now reads the way a metric tape reads — the board's widths and the widepoint's offset in
centimetres to one decimal, the swallow/diamond depth in whole millimetres — and the sliders move
in whole millimetres instead of sixteenths of an inch. A shaper on Imperial sees exactly what they
saw yesterday, character for character.

Purpose: this is the phase's tracer. Every later plan is call-site work that reuses what this plan
builds — one pure display layer (`lib/geometry/measure-display.ts`), one pure metric-bounds helper
(`metricSliderRange`), and one mechanical guard (the conversion ledger) that fails the test suite
if a design-screen component ever formats a measurement on its own again.

Output: `lib/geometry/measure-display.ts` + its test suite, `metricSliderRange` in
`lib/geometry/units.ts` + its tests, the conversion ledger in `lib/units-isolation.test.ts`, and a
fully converted TEMPLATE screen except its Board Length control (which needs the typed field built
in Plan 02).
</objective>

<assumption_delta_decision>
**Signal:** the assumption-delta scan fired `pluralization` on "second" ("the metric parser is its
counterpart, not a second code path inside components") and `chosen` on "chosen" ("re-prints it in
the chosen system").

**The noun that is now primary:** the **units system a shaper has chosen** (`UnitsSystem`, one of
`UNITS_SYSTEMS`). Imperial is one variant of it, not the app's default with a metric branch bolted
alongside — Phase 5 already promoted the noun in `lib/geometry/units.ts`'s own header.

**Decision: `promote`.** Every design-screen display site is converted to call a function that
*takes* a `UnitsSystem` (`formatDim`, `formatMark`, `formatLength`, `measureSlider`,
`commitTypedMeasure`), rather than keeping today's imperial call and adding a metric `if` beside
it. The same rule reaches the typed field: Plan 02 replaces `ImperialField` with one system-aware
`MeasureField` rather than adding a `MetricField` sibling, so neither system is the primary and a
third system could not silently inherit Imperial's behaviour. The storage identity is unchanged —
everything stored stays branded `Mm`.

**Rationale (one line):** adding a metric branch alongside 300 imperial calls would bake an
Imperial-primary asymmetry into every call site Phase 7 then prints from; promoting costs the same
edit and leaves no asymmetry to inherit.

**Invariant test (accepted):** `lib/geometry/measure-display.test.ts` iterates `UNITS_SYSTEMS`
rather than naming the two systems by hand — the same idiom `lib/geometry/summary-line.test.ts`
already uses — so a formatter that silently drops a branch fails the suite instead of falling back
to Imperial.
</assumption_delta_decision>

    - Returns a millimetre-domain `{ min, max, step }`. `step` is `stepMm`.
