## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → Vercel build → public internet | Everything on `main` that survives the production build is served publicly, to anonymous users |
| GitHub → Vercel | An OAuth grant gives a third-party platform read access to the repository and push-triggered build rights |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Information Disclosure | committed secrets reaching the public build | high | mitigate | This phase has no secrets by design — no auth, no database, no API keys. Task 1 asserts no `.env` file is tracked and adds env-file coverage to `.gitignore`; the Vercel project is created with zero environment variables; Task 3 re-asserts both. Any future secret must arrive as a Vercel Environment Variable, never a committed file. |
| T-01-08 | Elevation of Privilege | Vercel GitHub OAuth grant | medium | mitigate | Grant Vercel access to the `cpktoes/shaper` repository only, not to all repositories on the account, via **Adjust GitHub App Permissions** during import. The repository is already public, so read exposure is unchanged; the meaningful grant is push-triggered build rights on one repo. |
| T-01-09 | Tampering | anyone with push access to `main` triggers a production deploy | medium | accept | Solo-developer project with a single maintainer on a public repo; branch protection and required reviews are disproportionate at this stage. The pre-flight gate in Task 1 (`test`+`lint`+`build`) is the practical control. Revisit when a second contributor or real user data arrives (Phase 2 introduces accounts). |
| T-01-10 | Information Disclosure | Vercel build logs | low | accept | Build logs are visible to project members only and this build emits no secret material (no env vars are configured). No control needed at ASVS L1. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | RESEARCH.md `## Package Legitimacy Audit` records zero new packages this phase (empty table, no `[SLOP]`, no `[SUS]`). This plan runs no install command; Vercel's own `npm install` during the build resolves the existing committed lockfile only. If any task here would add a dependency, stop and re-run the legitimacy gate before installing. |
</threat_model>
