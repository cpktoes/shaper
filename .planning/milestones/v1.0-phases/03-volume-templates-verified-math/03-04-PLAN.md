<objective>
Make the export preview-first (D-04) and reachable from both screens the shaper works on (D-03):
a dialog that shows how the board splits across pages, lets them pick Letter or A4 (D-02), and only
then builds the file.

Purpose: a wrong print scale fails silently and expensively. Showing the split, the page count and
the paper size before anything is generated is the second of the three defences against that (the
scale square and the how-to box are the other two) — and it is also just how a shaper decides
whether to print at home or take it to a shop.

Output: one shared dialog component and two entry points using it.
</objective>

  <action>
Create `components/template/export-preview-dialog.tsx` as a client component exporting
`ExportPreviewDialog`, taking a `trigger` element as a prop so both screens can supply their own
entry button while sharing one dialog implementation.

State is local `useState` only — a `PaperSize` (initial value `"letter"` per D-02), a generating
boolean and an error boolean. Add no field to the design store: this is a view preference, exactly
like `showConstruction` and `orientation` already are in `outline-editor.tsx`.

Compose from the existing shadcn primitives; install no new shadcn component. Structure, in this
order (the UI spec's populated-state contract):
  - `DialogTitle` reading `Export Full-Size Template`
  - `DialogDescription` reading `Prints at true size, tiled across pages you tape together.`
  - the paper picker: a two-button segmented control built from the existing `Button` variants,
    labelled `Letter` and `A4`, with the selected one carrying the pressed treatment and
    `aria-pressed`. Install no new shadcn control for this — it is a closed two-value choice and the
    app's precedent (the fin toggles, the rotate button) is button pairs, not radio inputs
  - the tile diagram: a grid of `layout.rows` by `layout.columns` cells drawn from
    `computeTemplateLayout(outlineGeometry, paper)`, each cell carrying its page number, with the
    nose page (page 1) badged in the accent fill. Size the diagram to the board's own proportions so
    a long single-column board reads as a tall stack and a wide board reads as a grid. Constrain it
    so a multi-row, multi-column grid stays inside the dialog rather than pushing it wider — a
    25in-widepoint board is the case that will find any weakness here
  - the page-count line, singular or plural exactly as fixed: `1 page — no taping needed.` when
    `pages.length` is 1, and `{n} pages — tape nose to tail.` otherwise
  - `DialogFooter` with `Cancel` (a `DialogClose`) and the primary `Download PDF`

Recompute the layout whenever the paper choice changes, so the page count and the diagram both
respond to the pick. This is pure geometry with no IO, so it runs synchronously in a `useMemo` — do
not add a loading state to the diagram or the page count; none is reachable.

`Download PDF` sets the generating flag, calls `downloadTemplatePdf` with the previewed layout, the
marks from `computeTemplateMarks`, the geometry, the chosen paper, `boardName`, and `dims` built
from `templateValues.length`, `templateValues.widePointWidth` and `railValues.centerThickness`, then
clears the flag and closes. While generating, the button's label becomes `Preparing PDF…` and the
button is disabled — the label swap is what prevents a double-press; a sub-second operation needs no
spinner. On failure, clear the generating flag, re-enable the button, and show
`Couldn't build the PDF — try again.` inline in the dialog, matching the existing
`DeleteConfirmDialog` failure-copy pattern: short, names the failure, gives the one next step.

Colour discipline, per the approved UI spec: the accent fill is reserved in this phase for the
`Download PDF` button and the nose-page badge in the diagram, and nowhere else in the dialog. Note
that the pattern map suggested reusing the Summary screen's accent-filled `Print Order Form` button
styling for the entry-point buttons; the approved UI spec overrides that and keeps entry points
neutral, so follow the spec and record the divergence in the SUMMARY. Every surface reads from the
existing `--surf-*` token contract; introduce no new token and no hard-coded colour value.

Do not build any PDF bytes before `Download PDF` is pressed — the whole point of D-04 is that the
preview is free.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shaper's paper choice → layout computation | The only new user input this phase introduces crosses into geometry |
| client design state → downloaded file | The dialog reads the open design and turns it into a file on the shaper's disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12 | Tampering | paper-size input | low | mitigate | `PaperSize` is a closed TypeScript union of two values with a hard default, so an invalid value is a compile error rather than a runtime branch needing a guard (RESEARCH.md's V5 Input Validation position) |
| T-03-13 | Information Disclosure | design data reaching the export | low | accept | The dialog reads only the design already held in this browser's own store; no fetch, no server action and no new API route is introduced, so no other user's board is reachable |
| T-03-14 | Denial of Service | repeated Download presses | low | mitigate | The Download button disables itself and swaps its label while generating, so a double-press cannot start a second concurrent generation |
| T-03-15 | Repudiation | silent export failure | medium | mitigate | A failed generation surfaces the fixed error copy inline and re-enables the button, rather than closing the dialog as though it had succeeded |
</threat_model>
