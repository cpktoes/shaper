`RulerIcon` from lucide-react at `size-6`.

Match the rotate button's box exactly — same padding, same border token, same radius, same focus

introduce a larger touch-target variant alongside the existing ones.

of state. The sidebar checkbox in `outline-controls.tsx` reads and writes that same state, so the
two controls stay in agreement by construction rather than by synchronisation — leave that file
untouched. The shaper asked for the button in addition to the checkbox, not instead of it.

State treatment: at rest the button carries the same `border-surf-line` edge and `surf-ground` fill
as its neighbours. When construction lines are ON it takes the accent fill — this is the one
control in this phase's toolbar the UI contract allows to do so. Anything drawn on the accent fill
must take that fill's paired on-accent foreground token; this codebase has been bitten three times
by ignoring that rule, and the warning comment above the rotate button records it, so the icon must
switch to the on-accent foreground in the ON state rather than staying on the muted ink token.

Give it `aria-pressed` reflecting the state, an `aria-label` that names the action for the current
state (hide or show), and a `title` for the hover tooltip — the same pattern the rotate button uses,
where the label is the only thing that changes between states.

Add a local `wideView` boolean, alongside `showConstruction` and `orientation`, and hide the
`aside` entirely when it is true so the `main` region takes the full window width. Do not persist it
and do not put it on the design store: the file's own header states the rule, and a reload should

to study the drawing, and the construction lines are what there is to study. Leaving wide view puts
the construction-lines setting back to whatever it was before wide view changed it, so the shaper
does not silently inherit a setting they never chose. Remember the prior value in local state when
entering, and apply it when leaving. Do this in the click handler; do not reach for an effect that
sets state during render, which this codebase's lint configuration rejects and which caused a real
bug in plan 02-05.

Keep the sidebar's own internal structure intact — the scrolling controls region and the
flex-none development-only preset footer are load-bearing (a quick task had to fix that footer
once already because it was only pinned by luck). Hide the whole `aside`; do not restructure what is
inside it.

Give the button `aria-pressed` for the wide-view state, an `aria-label` naming the action for the
current state, and a `title`.
