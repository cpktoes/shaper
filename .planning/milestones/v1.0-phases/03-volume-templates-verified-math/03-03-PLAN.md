<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shaper's typed board name → PDF content stream | Free user text is measured and drawn into the printed name block |
| generated PDF → physical printer and workshop | The template is trusted by a shaper cutting foam to it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Tampering | name block rendering with arbitrary user text | low | mitigate | Board name text is measured against a fixed block width with `getTextWidth` and truncated with an ellipsis before drawing, so no name can overrun the block, overlap the cut line, or push other furniture off the kept area. jsPDF draws plain text into a content stream with no execution context, so this is a layout concern, not a script-injection one |
| T-03-10 | Tampering | match-mark and mark placement arithmetic | high | mitigate | Both are pure functions in `lib/geometry/template.ts` with tests asserting that adjacent pages' marks map to identical board-frame positions and that mark stations equal the geometry's own values — a misaligned template is the failure a shaper pays for in foam |
| T-03-11 | Repudiation | printed artifact provenance | low | accept | The name and dims block records which board a stack of pages belongs to; no stronger provenance (timestamp, signature) is warranted for a workshop template |
| T-03-SC | Tampering | npm dependency surface | high | mitigate | This plan installs nothing. `jspdf` was audited OK in RESEARCH.md's Package Legitimacy Audit and installed under plan 01; no `[ASSUMED]` or `[SUS]` package enters here |
</threat_model>
