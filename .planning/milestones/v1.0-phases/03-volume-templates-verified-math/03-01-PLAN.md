<objective>
Prove the whole template-export path end to end on one thin slice: a shaper opens the Template
screen, presses Export Template, and gets a real multi-page PDF on disk whose outline is at true
1:1 size — then confirms it with a ruler before anything else in this phase is built on top of it.

Purpose: a wrong print scale fails silently and expensively (a 6'2" template at 97% is about 2"
short, discovered only after taping eight pages). Proving scale first, on one path, means every
later task in this phase inherits a verified foundation instead of compounding an unnoticed error.

Output: `jspdf` installed, the pure tile-layout module and its tests, the single PDF-drawing module
and its bytes smoke test, and an Export Template button on the Template screen that downloads a
real file.
</objective>

Per D-01 the template is a downloaded, multi-page PDF with true physical size baked into the file —
not a browser-print path. Do not route this through `window.print()`, a hidden HTML element, or the
Summary order form's `use-print-fit.ts` machinery: that hook measures a live DOM layout at
`beforeprint` and scales it with CSS zoom, which is the opposite of what a 1:1 template needs. Its
pinned-margin, exact-page-box reasoning is useful prior art; its mechanism is not.

Install the dependency D-01 anticipates: run `npm install jspdf` (version ^4.2.1). RESEARCH.md's Package Legitimacy
Audit records jspdf as verdict OK — created 2015, ~15M weekly downloads, no postinstall scripts,
source at github.com/parallax/jsPDF — so no legitimacy checkpoint is required before installing.
Do not add pdf-lib or any jsPDF plugin; core `rect`, `lines`, `text`, `setLineWidth`,
`setLineDashPattern` and `addPage` cover everything this phase draws.

Make the colocated PDF test actually run: `vitest.config.ts`'s `include` today is
`["lib/**/*.test.ts"]`, which would silently skip a test file under `components/`. Widen it to also
match `components/**/*.test.ts`. Leave `environment: "node"` and the `@` alias untouched.

Remove the duplicate-constant trap: in `lib/geometry/outline.ts`, add the `export` keyword to the
existing `MEASURE_STATION_MM` declaration (line 32) so the 12" measuring station has exactly one
definition. `lib/geometry/template.ts` imports that constant; it must never re-derive the same
physical station from a fresh unit conversion, because two independent constants for one physical
quantity is exactly the drift CLAUDE.md Rule 1 exists to prevent.

Create `lib/geometry/template.ts` — pure, no jsPDF import, no React, no browser API, following the
`lib/geometry/volume.ts` header/deviation-comment shape (state plainly that this is new project
logic layered on existing `OutlineGeometry` data, not a prototype port, and that the drawing lives
in `components/template/build-template-pdf.ts`). It exports:
  - `PaperSize`, a closed union of `"letter"` and `"a4"` (per RESEARCH.md's V5 note: a compile-time
    union, never a validated free string);
  - `PAPER_MM`, a `Record<PaperSize, { width: Mm; height: Mm }>` holding letter 215.9 x 279.4 and
    a4 210 x 297;
  - `TEMPLATE_MARGIN_MM` = `mm(10)` and `TEMPLATE_OVERLAP_MM` = `inchesToMm(0.5)` (D-09 grants the
    exact overlap to discretion; name it, do not inline it);
  - `TemplatePage` with `index`, `row`, `col`, `stationRange: [Mm, Mm]`, `halfWidthRange: [Mm, Mm]`
    and `label`;
  - `TemplateLayout` with `pages`, `columns`, `rows`, `paper`, `margin` and `overlap`;
  - `computeTemplateLayout(geometry, paper, margin = TEMPLATE_MARGIN_MM, overlap = TEMPLATE_OVERLAP_MM)`;
  - `TemplateMarks` with `noseTwelve`, `tailTwelve`, `center`, `widepoint`, and
    `computeTemplateMarks(geometry)` returning `tailTwelve` = `MEASURE_STATION_MM`, `noseTwelve` =
    `geometry.length - MEASURE_STATION_MM`, `center` = `geometry.length / 2`, `widepoint` =
    `geometry.widePointStation`.

`computeTemplateLayout` must be a two-dimensional grid from the start, not a list of length bands
that happens to work for a 19in board. `WIDEPOINT_WIDTH_RANGE_IN.max` is 25in, so a half-width can
reach 12.5in while a Letter page's usable width after margins is roughly 8in and A4's is narrower —
wide boards genuinely need more than one column. Tile the rectangle spanning station 0 to
`geometry.length` by half-width 0 to `geometry.halfWidePointWidth`, using a step of
(usable page dimension minus overlap) in each direction, so consecutive pages share exactly
`overlap` millimetres. Page order runs nose to tail per D-09: row 0 is the nose-most station band
and rows advance toward the tail (station 0 is the tail in `OutlineGeometry`), and within a row,
column 0 is the one containing the stringer at half-width 0, advancing outward. Number pages 1..N
in that reading order and set each `label` to "Page {n} of {N} — nose to tail".

Create `lib/geometry/template.test.ts` in the `it.each(BOARD_PRESETS)` invariant style of
`design.test.ts` (no golden JSON — this is new project math, not a prototype port). Assert, for

`stationRange` and `halfWidthRange`; consecutive rows and consecutive columns overlap by exactly
`TEMPLATE_OVERLAP_MM` (within a floating-point tolerance); `pages.length` equals `rows * columns`;
and page labels number 1..N with no gap. Add an explicit case built from a board at
`WIDEPOINT_WIDTH_RANGE_IN.max` (25in widepoint) asserting `columns` is greater than 1, so the
multi-column path is exercised rather than assumed. Do not assert a hardcoded page count.

Create `components/template/build-template-pdf.ts` — the only module in the codebase that imports
jsPDF. It computes nothing: it iterates data handed to it. Fix its public argument contract now,
complete, so later plans extend the drawing without touching a call site: a single options object
with `layout`, `marks`, `geometry`, `paper`, `boardName`, and `dims` (an object carrying `length`,
`widePointWidth` and `centerThickness`, all `Mm`). Export `buildTemplatePdf(...)` returning the jsPDF document,
`templateFileName(boardName)` returning a slugified `<board-name>-template.pdf` (falling back to
`board-template.pdf` when the name is empty or slugifies to nothing), and `downloadTemplatePdf(...)`
which calls `buildTemplatePdf` then `doc.save(templateFileName(boardName))`. Construct the document
with jsPDF's `unit: "mm"` and `format` set to the `PaperSize` value, which is what makes the output
1:1 without a second conversion layer — never convert millimetres to points by hand. For each page
in `layout.pages`, call `addPage` for every page after the first and draw, all in solid black
(#000000 — the PDF deliberately ignores the app's theme; a workshop printout has no theme):
  - the outline curve, 0.5mm solid, as the run of `geometry.points` inside this page's
    `stationRange`, translated into page millimetres by subtracting the page origin and adding the
    margin (include the sample immediately outside each end of the range so the curve meets the
    page edge rather than stopping short of it);
  - the stringer edge, 0.35mm with dash pattern 16 4 4 4, as the straight line at half-width 0 —
    this is the half (spin) template's spine per D-05;
  - on the nose page only (page index 0), the D-07 scale-check square: 50.8mm x 50.8mm, unfilled, at 0.35mm solid, placed
    in a page corner clear of the outline curve and inside the margin, with the label
    `2" x 2" — measure before taping` beneath it at 9pt bold Helvetica;
  - the page's own `label` at 9pt regular Helvetica in the bottom margin of every page;
  - the board name and dims block (D-08), on the page whose `stationRange` contains the board's
    centre station: a bordered box at 0.25mm, placed inside the kept template area — between the
    stringer edge and the outline curve, in the board's own interior, never in a page margin a cut
    or a printer would remove — carrying the board name at 14pt bold above the core dims at 10pt
    regular. Format the dims through `lib/geometry/units.ts` only: `formatFeetInches` for length and
    `formatInchesFraction` for width and thickness. No module in this plan performs its own
    inch-millimetre conversion; that arithmetic lives in units.ts alone, per CLAUDE.md Rule 2.
Use jsPDF's built-in Helvetica; embed no font.
