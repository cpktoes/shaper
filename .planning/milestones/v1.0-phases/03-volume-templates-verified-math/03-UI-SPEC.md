# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase's UI surface is small and additive — no new screens. It adds three toolbar
controls to the Template screen (`components/outline/outline-editor.tsx`), one matching export
button to the Summary screen, one shared export-preview dialog (D-03/D-04), and a wholly new
**physical print artifact** (the tiled 1:1 PDF itself) that is drawn with `jsPDF` rather than
themed CSS. The Volume screen's live litres readout (VOL-01) already exists and is out of visual
scope — this phase verifies and tests its correctness, it does not restyle it. Everything below
reuses the project's existing shadcn/Base UI components and `--surf-*` token contract already
established in `app/globals.css`; nothing here introduces a new design system.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized in Phase 1 — `components.json` present) |
| Preset | `base-nova`, base color `neutral`, `cssVariables: true`, no prefix |
| Component library | Base UI (`@base-ui/react`) wrapped by shadcn primitives in `components/ui/*` |
| Icon library | lucide-react (import pattern: `{Name}Icon`, e.g. `DownloadIcon`) — one hand-drawn inline SVG exception already exists (`RotateBoardIcon` in `outline-editor.tsx`) for a glyph lucide doesn't have; no new hand-drawn icon is needed this phase |
| Font | Inter, loaded via `next/font` as `--font-inter`; both `--font-display` and `--font-body` resolve to it (headings are distinguished by weight/tracking/case, not a second family) |

No new shadcn components need installing this phase. Reuse: `dialog.tsx`, `button.tsx`. The Letter/A4
picker (D-02) is a two-option segmented control built from existing `Button` variants (see
Typography/Copywriting below) — not a new `radio-group` install — because it is a closed,
two-value choice and the app already has a precedent for button-pair toggles (fin toggles,
rotate button) rather than radio inputs.

## Spacing Scale

Declared values (must be multiples of 4), matching the scale already in use across `/design/*`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tick-mark offsets |
| sm | 8px | Compact control spacing (toolbar button gaps, dialog row gaps) |
| md | 16px | Default element spacing, dialog content padding (`p-4`) |
| lg | 24px | Section padding (dialog header-to-body gap) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions:**
- **34px toolbar icon-button box, 24px icon** — the Template screen's Construction Lines toggle,
  Wide View toggle, and Export Template button must match the existing rotate button's established
  size exactly (`size-[34px]` box, `size-6` icon, `border-surf-line`, `bg-surf-ground`), per the
  260825-wrq decision already recorded for that toolbar. Do not introduce a 44px touch-target
  variant alongside it — a toolbar of mixed-size icon buttons reads as a bug, not a11y care.
- **Physical PDF units are millimetres, not the 4px scale** — page margins, overlap width, and mark
  positions on the printed template are governed by D-02/D-07/D-09's physical dimensions (paper
  size, ~12.7mm/½" overlap, 2"×2" square), not by the app's on-screen spacing tokens. This is a
  different domain (paper), not a violation of the UI spacing contract.

## Typography

On-screen UI (dialog, toolbar, buttons) — matches the app's existing type scale exactly, no new sizes introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label / Caption | 12px (`text-xs`) | 500 (medium) | 1.4 |
| Heading (dialog title) | 16px (`text-base`, `font-heading`) | 500 (medium) | 1 (`leading-none`) |
| Display (existing volume readout, unchanged) | 22px (`text-[22px]`) | 800 (extrabold) | 1.2 |

Two weights only: 400 (regular, body/captions) and 500/800 where the existing app already uses a
heavier weight for emphasis (dialog titles at 500, the litres readout at 800 — both pre-existing,
reused verbatim, not new choices for this phase).

**Print artifact typography (the PDF itself — a separate, non-CSS domain):**

| Element | Size | Weight | Notes |
|---------|------|--------|-------|
| Board name | 14pt | Bold | Inside the D-08 name/dims block |
| Core dims (length × width × thickness) | 10pt | Regular | Directly under the board name, same block |
| Station/mark labels (nose 12", tail 12", center, widepoint) | 9pt | Regular | Matches the project's own established 9pt/12px print-legibility floor (recorded decision `260823-pw7`) |
| Page label ("Page 3 of 8 — nose to tail") | 9pt | Regular | Bottom margin of every page |
| How-to box body copy (nose page only) | 9pt | Regular | Three short numbered lines |
| Scale-check square label ("2\" × 2\"") | 9pt | Bold | Inside/beside the square |

No embedded custom font: use jsPDF's built-in Helvetica. This is a workshop artifact read at arm's
length under shop light, not a branded document — legibility and the 9pt floor matter, typeface
does not.

## Color

On-screen UI reuses the existing four-theme `--surf-*` contract (Daylight/Chalk light, Slate/Phosphor
dark) verbatim — no new tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surf-ground` / `--surf-canvas` | Page background, canvas frame around the Template viewer, dialog backdrop |
| Secondary (30%) | `--surf-panel` / `--surf-sidebar` | Dialog surface, toolbar button resting fill (`bg-surf-ground` on `border-surf-line`, per the existing rotate-button pattern), tile-grid preview cell fill |
| Accent (10%) | `--surf-accent` (+ `--surf-on-accent` text) | Reserved for: the dialog's primary "Download PDF" button fill; the Construction Lines toggle's ON/active state; the nose-page badge in the tile-grid preview (the one page shapers start from) |
| Destructive | `--destructive` (existing shadcn token, unused by any control this phase introduces) | Not applicable — this phase adds no delete/destroy action. Reserved for future use only. |

Accent reserved for: **the Download PDF button, the active-state fill of the Construction Lines
toggle, and the nose-page badge in the export preview's tile grid** — nowhere else in this phase's
new surface. The Wide View toggle and the Export Template entry-point buttons stay on the neutral
`outline`/`ghost` button variants (matching the existing rotate button, which is also not accent-filled)
until pressed into a dialog-open state, at which point they behave like any other toolbar toggle
(`aria-expanded` background, not an accent fill).

**The generated PDF is drawn in pure black ink only (`#000000`) — it does not observe the app's
theme at all.** This is a deliberate, phase-specific deviation from the on-screen token system:
the printed template is a workshop object read off a home or shop printer that may well be
monochrome, and a shaper's chosen screen theme (e.g. Phosphor's green-on-black) has no meaning on
paper. Every line, tick, label, and box in the PDF is solid black; differentiation between line
*types* (outline curve vs. stringer edge vs. station ticks vs. widepoint tick vs. overlap match
marks) is carried entirely by **line weight and dash pattern**, borrowing the sketch manifest's
existing grammar (`--outline-stringer-dash: 16 4 4 4`, `--outline-station-dash: 5 4`) translated
to jsPDF's `setLineDashPattern`, with the widepoint tick given a third, dotted pattern (`2 3`) so
it never depends on the color distinction the manifest's decision 7 required on screen.

| Print line/mark | Weight | Dash |
|---|---|---|
| Outline curve (the cut/trace line) | 0.5mm solid | none |
| Stringer edge (straight edge, half-template spine) | 0.35mm | `16 4 4 4` (long-short-short, matches on-screen stringer) |
| Nose 12" / tail 12" / center ticks | 0.25mm | `5 4` (matches on-screen station dash) |
| Widepoint tick | 0.25mm | `2 3` (dotted — distinct from the other three by pattern alone) |
| Overlap match marks | 0.25mm | none (small solid crosshair/tick pair, identical on both overlapping pages) |
| Scale-check square | 0.35mm solid | none |

## Print Artifact Contract

The tiled PDF (TMPL-01) is the one genuinely new visual surface this phase ships. Because it is
drawn imperatively (jsPDF), not rendered from themed HTML/CSS, its contract is specified here in
full so `lib/geometry/template.ts` (pure layout data) and the PDF-drawing consumer module have an
unambiguous target — this is the layer between "geometry is correct" and "the shaper trusts the
paper enough to cut foam to it."

1. **Page order and numbering (D-09):** nose to tail. If the tile grid is wider than one column
   (Pitfall 1 — wide boards need column tiling too), reading order is row-major within the nose→tail
   direction: finish all columns of one length-band before advancing to the next. The how-to box
   states this explicitly ("tape left-to-right, then row to row, nose to tail") whenever `columns > 1`;
   omit that clause entirely when `columns === 1` (the common case) rather than printing a caveat
   that never applies.
2. **Overlap + match marks (D-09):** ~12.7mm (½") overlap between adjacent pages in both directions
   where the grid has more than one row/column. A pair of identical small crosshair marks sits
   inside the overlap strip on each of the two overlapping page edges — sized ~4mm — so lining up
   the marks (not just eyeballing the cut edge) confirms correct alignment before taping.
3. **Scale-check square (D-07):** exactly 2"×2" (50.8mm×50.8mm), solid black outline only (no fill),
   placed on the nose page in a corner guaranteed clear of the outline curve and any margin the
   printer might clip, labeled "2\" × 2\" — measure before taping" directly beneath it.
4. **How-to box (D-10):** plain-English, three numbered lines, on the nose page beside the scale
   square:
   1. Print at 100% — turn off "Fit to page."
   2. Measure the square above. It should be exactly 2" × 2".
   3. Cut out each page and tape them together, nose to tail, matching the marks.
5. **Board name + dims block (D-08):** a bordered box positioned inside the kept template area
   (never in a margin that a cut removes), containing the board name in bold 14pt and the core
   dims (length × width × thickness, formatted through `lib/geometry/units.ts` — feet-inches
   fractional, never raw millimetres) in regular 10pt directly beneath it. If `boardName` is empty
   (an unsaved, unnamed design), print **"Untitled Board"** rather than leaving the line blank —
   matching the fallback text already used by `board-rack-card.tsx` / `continue-board-card.tsx`.
   (Note for the record: `order-form.tsx` uses the lower-case variant "Unnamed board" for the same
   fallback — a pre-existing minor inconsistency between two print surfaces. Do not silently "fix"
   `order-form.tsx` to match as a side effect of this phase; that file's own folded refit task is
   scoped separately. If both are touched in the same session, flag the inconsistency and let the
   founder pick one.)
6. **Long board names:** the name/dims block has a fixed maximum width; a name exceeding it
   truncates with an ellipsis rather than wrapping into or overlapping the outline curve or an
   overlap strip. Truncation, never font-shrinking — a template's name label doesn't need to be
   read at full length to serve its purpose (identifying which stack of pages belongs to which
   board), and font-shrinking risks dropping under the 9pt floor.
7. **Page label:** "Page {n} of {total} — nose to tail" in the bottom margin of every page, 9pt.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (Template screen toolbar) | **"Export Template"** — opens the preview dialog |
| Primary CTA (Summary screen, D-03) | **"Export Template"** (same label as the Template screen's — one capability, one name, regardless of entry point) |
| Primary CTA (inside the preview dialog) | **"Download PDF"** |
| Secondary action (inside the preview dialog) | **"Cancel"** |
| Preview dialog title | **"Export Full-Size Template"** |
| Preview dialog description | **"Prints at true size, tiled across pages you tape together."** |
| Paper-size picker labels | **"Letter"** / **"A4"** (Letter selected by default per D-02) |
| Tile-count summary — one page | **"1 page — no taping needed."** |
| Tile-count summary — many pages | **"{n} pages — tape nose to tail."** (matches CONTEXT.md's own example wording verbatim) |
| Loading (Download button, mid-generation) | **"Preparing PDF…"** (button disabled, label swap — no separate spinner needed for a sub-second operation, but the label change prevents a double-click) |
| Error state (PDF generation fails) | **"Couldn't build the PDF — try again."** (mirrors the existing `DeleteConfirmDialog` failure copy pattern: short, names the failure, gives the one next step) |
| Empty state | Not applicable this phase — a design always exists (the app seeds `DEFAULT_DESIGN_STATE` on load), so Export Template is never shown with nothing to export. |
| Destructive confirmation | Not applicable this phase — no destructive action is introduced. (Existing precedent for reference, unchanged: `Delete "{boardName}"?` / `This can't be undone.` / `Delete Board`.) |
| Board-name fallback (printed on the template, see Print Artifact Contract #5) | **"Untitled Board"** |
| How-to box (printed, see Print Artifact Contract #4) | Three numbered plain-English lines, verbatim as specified above |
| Scale-check square label (printed) | **"2\" × 2\" — measure before taping"** |

## UI Considerations

Probe run 2026-08-28 (ui-consideration-probe over 6 surfaces, kinds confirmed by founder): 28 applicable
element/state pairs — **12 resolved (explicit), 1 resolved (backstop), 15 dismissed with reason, 0 unresolved.**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | export-preview-dialog (form) | ⚠ dismissed | Unreachable by construction: a design always exists on load (`DEFAULT_DESIGN_STATE`), so Export Template is never shown with nothing to export. |
| empty | board-name-block (static-content, printed) | ✅ covered | Empty `boardName` prints the fallback "Untitled Board" rather than a blank line (Print Artifact Contract #5). |
| empty | tile-grid-preview (list-collection: pages) | ⚠ dismissed | Zero pages is unreachable: any board with positive length yields ≥ 1 tile page. |
| empty | template-toolbar-controls (interactive-control) | ⚠ dismissed | Icon controls carry no data content — no empty state exists. |
| loading | export-preview-dialog, download-button (interactive-control) | ✅ covered | Download button shows "Preparing PDF…" and disables itself during PDF generation (Copywriting Contract). |
| loading | template-export-button, summary-export-button (interactive-control) | ⚠ dismissed | Opening the dialog is a synchronous state flip (no async work happens before the dialog paints) — no loading state possible or needed. |
| loading | tile-grid-preview (list-collection: pages) | ⚠ dismissed | Tile layout is a synchronous pure-geometry computation from design state — no async gap to show a loading state in. |
| error | export-preview-dialog, download-button (interactive-control) | ✅ covered | "Couldn't build the PDF — try again." inline in the dialog, button re-enables (Copywriting Contract). |
| error | template-export-button, summary-export-button (interactive-control) | ⚠ dismissed | Same synchronous state flip as loading above — no failable operation occurs before the dialog paints. |
| error | tile-grid-preview (list-collection: pages) | ⚠ dismissed | Pure function of design state, no IO — no error state is reachable. |
| populated | export-preview-dialog (form) | ✅ covered | Happy-path structure specified: title → description → Letter/A4 picker (Letter default) → tile-grid preview → Download PDF / Cancel (Scope note + Copywriting Contract). |
| populated | tile-grid-preview (list-collection: pages) | ✅ covered | Typical board (CONTEXT.md's own example): ~8 pages, single column, straightforward nose-to-tail numbering — the common case, not the edge case, drives the default visual weight of the diagram. |
| populated | template-toolbar-controls (interactive-control) | ✅ covered | Resting fill (`bg-surf-ground` on `border-surf-line`) and active states (accent fill for Construction Lines ON, `aria-expanded` background for dialog-openers) specified under Color. |
| partial | export-preview-dialog (form: paper-size picker) | ⚠ dismissed | Closed two-value TypeScript union (`"letter" \| "a4"`) with a hard default (Letter) — no state exists in which the picker has "some but not all" of its value, so partial doesn't apply. |
| partial | tile-grid-preview (list-collection: pages) | ⚠ dismissed | Grid is fully derived from board dimensions in one pass — no partial data source exists. |
| overflow | tile-grid-preview (list-collection: pages) | 🧪 backstop | The preview diagram must render a multi-row/multi-column grid (Pitfall 1: max-widepoint boards need `columns > 1`) without visually overflowing the dialog — needs a held-out visual check at planning/execution time (e.g. render the diagram against `WIDEPOINT_WIDTH_RANGE_IN.max`), since no unit test can assert "doesn't look cramped." |
| overflow | export-preview-dialog (form) | ⚠ dismissed | Dialog content is fixed small controls; the only variable-size content is the tile grid, handled by its own backstop row above. |
| overflow | board-name-block (static-content, printed) | ✅ covered | Truncates with ellipsis at a fixed max width rather than overlapping the outline or an overlap strip (Print Artifact Contract #6). |
| overflow | printed page furniture (how-to box, page label, scale square, match marks) | ✅ covered | Fixed author-controlled geometry and copy; page-label page count is bounded by the tile grid — placement rules in Print Artifact Contract #1–#4, #7 keep all furniture inside kept areas. |
| zero-one-many | export-preview-dialog + tile-grid-preview (list-collection: pages) | ✅ covered | Singular/plural copy rows defined explicitly: "1 page — no taping needed." vs. "{n} pages — tape nose to tail." (Copywriting Contract). |
| long-text | board-name-block (static-content, printed) | ✅ covered | Same resolution as overflow above — truncation, never font-shrink below the 9pt floor (Print Artifact Contract #6). |
| long-text | how-to-box, page-label (static-content, printed) | ✅ covered | Fixed, author-controlled copy (Copywriting Contract) — not user input, so no runtime long-text risk exists for these two elements. |
| long-text | export-preview-dialog, toolbar + export buttons (interactive-control) | ⚠ dismissed | All on-screen copy is fixed author-controlled strings from the Copywriting Contract (no user input renders in the dialog or on any button) — no runtime long-text risk. |
| loading/error | template-toolbar-toggles (construction-lines, wide-view — interactive-control) | ⚠ dismissed | Instant client-side UI-state toggles with no network or async work behind them — no loading or error state is reachable. |
