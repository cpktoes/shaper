# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds no new visual language. Every new surface (sign-in dialog, banner, Save
control, board rack, rack-card menu, rename/delete dialogs) is built from the existing
`surf-*` token contract in `app/globals.css` and the existing card/dialog patterns in
`components/setup/*` and `components/settings-menu.tsx`. Where this document is
prescriptive, it is pinning down *which* existing pattern to reuse and the exact copy —
not inventing new tokens, spacing, or color.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — do not re-run `shadcn init`) |
| Preset | not applicable — see frontmatter |
| Component library | Base UI (shadcn's `base-nova` style is a Base UI preset; some app chrome — e.g. `components/settings-menu.tsx` — is hand-built directly on `@base-ui/react/*` primitives rather than a generated `components/ui/*` wrapper, styled with `surf-*` tokens instead of the shadcn neutral scale) |
| Icon library | lucide-react |
| Font | Inter, loaded via `next/font` as `--font-inter` in `app/layout.tsx`; both `--font-display` and `--font-body` resolve to it (display/body are the same family, distinguished by weight/tracking/case, not typeface) |

**New shadcn components needed this phase** (not yet present in `components/ui/`):
- `dialog` — run `npx shadcn add dialog`. Used for the sign-in/sign-up dialog (D-03), the
  board-name prompt (D-05), and the rename dialog (D-13). Style it identically to the
  existing `alert-dialog` usage in `replace-board-dialog.tsx` (surf-panel surface,
  surf-line-faint border, surf-ink text) — no new chrome.
- `input` — run `npx shadcn add input`. Used for the name-prompt and rename dialogs. No
  raw `<input>` text-entry component exists in `components/ui/` today (the closest
  precedent, `OrderFormField` in `components/summary/order-form.tsx`, is a print-form
  field, not a dialog input — do not reuse it here).

**Do NOT add** a shadcn `dropdown-menu` component for the rack-card menu (D-13's
Rename/Duplicate/Delete affordance). Build it the same way `components/settings-menu.tsx`
builds the nav's gear menu: directly on `@base-ui/react/menu`, styled with `surf-*`
tokens (`bg-surf-panel`, `border-surf-line-faint`, `data-highlighted:bg-surf-well`). This
keeps the one existing menu pattern in the app as the only menu pattern, rather than
introducing a second, differently-themed one.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (e.g. rack-card internal `gap-2`, matching preset cards) |
| md | 16px | Default element spacing |
| lg | 24px | Section padding, grid gaps (`gap-6` between rack/preset cards) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (nav `px-12`) |
| 3xl | 64px | Page-level spacing (`pb-16` page padding) |

Exceptions: **12px** (`p-3`) — the established card/panel inset used by
`PresetCard`, `ContinueBoardCard`, and `TabbedPanel`'s content card. Every new rack card
and its inner thumbnail frame reuses this exact inset; do not introduce a different
padding value for the sake of the 8-point scale. This is a pre-existing, deliberate
exception (see `components/setup/preset-card.tsx`), not a new one created by this phase.

## Typography

**New typography roles this phase** (the only 2 weights this phase declares):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | Regular (400) | 1.5 |
| Label | 12px | Semibold (600) | 1.4 |

Regular (400) and Semibold (600) cover every new element this phase adds: dialog body
copy, banner text, rack-card metadata, menu items, form labels/errors. Body is for
sentence-case copy (banner text, dialog descriptions, error/validation text); Label is
for sentence-case dialog field labels (e.g. "Board name") — neither is the uppercase
eyebrow treatment below, which this phase reuses but does not redeclare.

**Reused from Phase 1 (not new declarations — do not redefine, match exactly):**

| Existing role | Size | Weight | Line Height | Where this phase reuses it |
|----------------|------|--------|--------------|------------------------------|
| Heading | 20px | Semibold (600) | 1.2 | Rack card title (matches `PresetCard`'s card-title treatment) |
| Display | 30px | Extrabold (800) | 1.2 | The rack section's own heading, if one is added (matches the page `h1`, e.g. "Shape a New Board") |
| Nav/CTA eyebrow | 12px | Bold (700), `tracking-architectural uppercase` | 1.4 | Rack card CTA label ("Open This Board"), the "In progress — not saved" tag — same treatment as the existing preset card's "Start Shaping" label and the nav links |

## Visual Focal Points

Each new surface has exactly one focal point — the thing a shaper's eye should land on
first. Everything else on that surface is secondary weight (muted text, thin borders, no
competing color).

| Surface | Focal point |
|---------|-------------|
| Rack card | The outline thumbnail — same window-frame treatment as `PresetCard`, so a shaper recognizes their board by its shape first, name/dims second |
| Sign-in dialog | The heading + primary CTA (Sign In / Create Account button) — Clerk's own field stack is secondary until the shaper is mid-fill |
| Sign-in banner | The "Sign In" link (accent text) — the reassurance sentence around it is muted body copy |
| Nav Save control | The "Saved" tick's accent checkmark once saved; the filled "Save" button itself before the first save |
| Board-name / rename dialog | The text input — auto-focused on open, primary action is secondary until a name is typed |
| Rack-card menu | The Delete item (destructive color) — the only item that should draw the eye differently from Rename/Duplicate |
| Delete-confirm dialog | The destructive "Delete Board" button — never the "Cancel" button, which stays the default/neutral treatment |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surf-ground` (#ffffff Daylight/Chalk · #12141a Slate · #050805 Phosphor) | Page background, dialog surface, Dialog overlay content |
| Secondary (30%) | `--surf-canvas` (#dfdcd3 Daylight/Chalk · #1a1d25 Slate · #142414 Phosphor) | Rack card outer frame (identical to `PresetCard`'s `bg-surf-canvas`), sign-in banner background |
| Accent (10%) | `--surf-accent-ink` (#48605c Daylight · #2b424c Chalk · #3490bc Slate · #52ab52 Phosphor) | See reserved-for list below |
| Destructive | `--surf-warning-ink` (#ac3811 Daylight/Chalk · #ff9670 Slate · #a6ffa6 Phosphor — already mapped to shadcn's `--destructive`) | Delete Board button/menu item only |

This app is themed (four named themes in `lib/theme.ts`); no single hex is "the" color for
any role — the hex values above are the Daylight-theme reference point. New UI must be
built against the `surf-*` token/utility names, never a literal hex, exactly like every
existing screen.

**Accent reserved for** (explicit list — nothing else may use it):
- Nav "Sign in" button hover/active text and the signed-in avatar's focus ring
- Nav Save button's filled state (`bg-surf-accent` / `text-surf-on-accent`) — same primary
  filled-button treatment as the site already has no other example of, so this is the
  first primary-filled button in the app; use shadcn `Button` default variant
- Sign-in banner's "Sign In" link text
- Rack card hover/focus ring and border (`hover:border-surf-accent-ink hover:ring-2
  ring-surf-accent-ink`) — identical to `PresetCard`/`ContinueBoardCard`
- Rack card CTA label text ("Open This Board")
- The "Saved" tick's checkmark icon
- Dialog primary action buttons (Sign In, Create Account, Save, Rename)

Rack-card menu items (Rename/Duplicate) use the **secondary** surface for hover
(`data-highlighted:bg-surf-well`), matching `SettingsMenu`'s `ThemeRow` — a menu row
highlight is not a 10%-budget accent moment.

## UI Considerations

Probe run 2026-08-27 over 9 surfaces: 56 applicable considerations — 25 resolved
(explicit), 4 resolved (backstop), 27 dismissed with reason, 0 unresolved.
Statuses: ✅ resolved, verification: explicit · 🧪 resolved, verification: backstop
(needs execution-time evidence; verifier must not silently pass it) · ➖ dismissed
(reason required, nothing to lift).

### board-rack (list-collection)

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| empty | ✅ | D-06 resolves this structurally: the rack section never renders when there are zero saved models AND no in-progress board — that view is exactly today's plain preset grid. There is no "empty rack" state to design. |
| loading | 🧪 | Home is a Server Component awaiting `listModels()` (RESEARCH.md architecture) — no client skeleton for the normal-speed case. If the query is ever slow enough to be visible, the Suspense fallback is the plain page shell with no rack section (same visual as "empty"), not a spinner. Verify at execution with a throttled query. |
| error | ✅ | If `listModels()` throws, the page renders the plain preset grid (same as signed-out) rather than a broken page — a board-list failure must never block starting a new board. |
| populated | ✅ | Rack cards reuse `PresetCard`'s exact visual weight (window-frame thumbnail, name, one metadata line, uppercase CTA label) so a saved board reads with the same eye as a preset. |
| partial | ➖ | No partial state exists — the rack renders from one complete `listModels()` result; no pagination or progressive fill. |
| overflow | ✅ | Same `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` wrap as the preset grid — many boards wrap to more rows, never scroll or clip. |
| zero-one-many | ✅ | Zero+none → rack omitted (see "empty" row). In-progress card (if any) is always first per D-07; saved boards follow, sorted last-touched-first. |

### rack-card (card / list item)

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| empty | ➖ | A card renders only for an existing board (saved row or in-progress state); there is no empty-card state. |
| loading | ✅ | The outline thumbnail renders synchronously from the stored spec snapshot — the same SVG outline rendering as preset cards, no async image, so no per-card loading state. |
| error | ✅ | A board whose stored snapshot fails to parse/validate is omitted from the rack (and logged) rather than rendering a broken card. |
| populated | ✅ | Card shows outline thumbnail, name, length × width × thickness in shaper units + volume in litres (formatted via `lib/geometry/units.ts`), and last-touched date per D-12. |
| partial | ➖ | A saved row always carries name, snapshot, and updatedAt (required columns) — no partially-populated card exists. |
| overflow | ➖ | Card content is fixed-format apart from the name, which the long-text row handles. |
| zero-one-many | ➖ | Collection-level concern — handled by the board-rack rows above. |
| long-text | ✅ | Name truncates to one line (`truncate`), matching `ContinueBoardCard`'s existing `displayName` treatment — never wraps into the metadata line below it. |
