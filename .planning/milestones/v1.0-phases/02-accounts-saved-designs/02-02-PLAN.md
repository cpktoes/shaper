<objective>
Boards that look after themselves: once a board has a name and a home, edits save themselves a
moment after the shaper stops adjusting, and the nav says plainly whether the work is safe.

Purpose: D-08's whole point is that a shaper stops thinking about saving. That only works if
the save state is honest — "Saved" must mean written, and a failure must be visible and one
click from a retry, without an interrupting dialog while someone is mid-shape.

Output: a pure, tested autosave decision module; dirty tracking and save status on the design
store; and the nav Save control's four states.
</objective>

    `"save"`, `"wait"` or `"idle"`. Tests, written first:
    - Signed out, dirty, with a modelId: returns idle. A signed-out shaper has nothing to save to.
    - Signed in, dirty, modelId null: returns idle. A board that has never been saved has no
      home; the first save is the shaper's own deliberate act (D-03, D-08).
    - Signed in, dirty, modelId present, nothing in flight: returns save.
    - Signed in, dirty, modelId present, a save already in flight: returns wait — never two
      concurrent writes to one row.
    - Signed in, not dirty, modelId present: returns idle.
    - `AUTOSAVE_DEBOUNCE_MS` is exported, is a number, and sits between 800 and 3000 — long
      enough that dragging a slider does not fire a write per frame, short enough that a shaper
      who stops and looks away sees "Saved" before they wonder.
    - `nextStatusAfter(result)` maps a completed attempt to a `SaveStatus` of "saved" or
      "error", and never returns "saved" for a rejected attempt. This is the prohibition about
      a lying save state, in code.
  </behavior>
