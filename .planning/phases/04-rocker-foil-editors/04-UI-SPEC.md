# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds one new screen (ROCKER, between TEMPLATE and RAILS) and extends two existing
ones (RAILS gains a thickness-link toggle; the Summary order form's reserved rocker box gets a
real curve). **Nothing here is a new visual language.** Shaper (this codebase) already has a
fully worked-out, four-theme design system — this contract is almost entirely "reuse the exact
tokens/classes/patterns already established on the Outline, Rails, Fins and Volume screens,"
with only the truly new pieces (a typed imperial-fraction entry field, a five-station datasheet
table, a side-profile viewer) getting fresh prescriptive detail.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, no gate needed) |
| Preset | `base-nova` (read from `components.json`) |
| Component library | Base UI (per project CLAUDE.md: "shadcn/ui components built on Base UI") |
| Icon library | lucide-react |
| Font | Inter — `--font-inter`, aliased to both `--font-display` and `--font-body` (globals.css: display and body are deliberately the same face; roles are distinguished by weight/tracking/case, not family) |

Theming: four named themes (Daylight/Chalk light, Slate/Phosphor dark) via `lib/theme.ts` +
`app/globals.css`'s three-layer token system (ramps → `--surf-*` contract → Tailwind bridge).
**Every new component in this phase must use `surf-*` / `outline-*` Tailwind utilities or
`var(--color-surf-*)` — never a literal hex or an un-themed Tailwind neutral** (this is how the
existing 228 call sites survive all four themes with zero per-theme edits). Verify new UI in at
least Daylight and one dark theme (Slate) before calling a plan done, per this codebase's own
established practice (see STATE.md's recurring "verified in all four themes" pattern).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-button padding (`p-1`), tick/hint gaps |
| sm | 8px | Compact stacks (`gap-2`, `mt-2`) |
| md | 16px | Default control spacing (`p-4` dev footer, `gap-4`) |
| lg | 24px | — (not used by sibling screens; skip unless a new layout needs it) |
| xl | 32px | — (not used by sibling screens; skip unless a new layout needs it) |
| 2xl | 48px | — |
| 3xl | 64px | — |

**Exceptions (existing, established house style — mirror these, do not "fix" them):**
- `p-10` (40px) — the controls sidebar's own inner padding (`outline-editor.tsx`, `rail-controls`
  consumers). Multiple of 8, kept for parity across every design-screen sidebar.
- `gap-3.5` (14px) and `mb-1.5`/`mt-0.5` (6px/2px) — fine baseline-alignment nudges used
  throughout `rail-controls.tsx` between a slider's label row and its track. These are not
  4px-grid values; they are hand-tuned optical alignment already in production on three sibling
  screens (Outline, Rails, Fins). **New ROCKER controls must reuse these exact values**, not a
  stricter 4/8 grid — a rocker sidebar built on a different micro-grid would visibly disagree
  with the rail sidebar directly below it in the same nav.
- `p-3` (12px) — `TabbedPanel`'s inner content-card padding (default, composed via `cn`). The
  ROCKER viewer panel gets this for free by using `TabbedPanel`; do not override it.
- 1px hairline borders (`border-surf-line`, `border-surf-line-faint`) are not spacing but are
  called out here because they recur at every panel/card/control edge in this phase.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Screen/section title | 18px (`text-lg`) | 800 extrabold | 1.2 (`leading-tight`), `font-display uppercase tracking-architectural` |
| Section heading (collapsible group label) | 12px (`text-xs`) | 800 extrabold | 1.2, `font-display uppercase tracking-architectural` |
| Body / control label / table cell value | 14px (`text-sm`) | 400 regular | 1.5, `font-normal` |
| Fine print / hint / bounds note | 10px (`text-[10px]`) | 400 regular | 1.4 |

Exactly two weights, matching `rail-controls.tsx`'s dominant pattern (`SectionHeading` =
extrabold, `ControlSlider` label = normal): **400 (regular) for values/body, 800 (extrabold)
for uppercase headings/labels.** Do not introduce a third weight (e.g. 700/bold) in new ROCKER
components even though it appears elsewhere in the app (nav links, the "↺ Reset Advanced" link)
— those are pre-existing, out-of-scope call sites, not a pattern to extend.

`tracking-architectural` (`0.15em`) is mandatory on every ALL-CAPS heading/label, per the
project-wide rule recorded in `app/globals.css`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surf-ground` / `--surf-canvas` | Page background; the `main` canvas area surrounding the viewer panel (bg-surf-canvas, matching Outline/Rails/Fins/Volume) |
| Secondary (30%) | `--surf-sidebar` / `--surf-panel` | Controls sidebar (`bg-surf-sidebar`), the `TabbedPanel` content card, the datasheet table's row/header background |
| Accent (10%) | `--surf-accent` (fill) / `--surf-accent-ink` (text/stroke) | Reserved for: (1) `.slider-accent` range fill + thumb on every new rocker/foil slider, (2) the toolbar's "Hide Board Outline" toggle button when `aria-pressed` (matches Outline's Construction-Lines button exactly — bg/border flip to accent, icon flips to `text-surf-on-accent`), (3) draggable construction-line control points on the side-profile viewer (ring + centre dot, same three-part target as `outline-viewer.tsx`'s), (4) the active tab's border in `TabbedPanel` (VIEWER / DATASHEET), (5) the top nav's active-link underline (pre-existing, unchanged) |
| Destructive/warning | `--surf-warning-ink` | Reserved for: inline validation copy under a typed datasheet field when `parseImperial` returns null (invalid entry), and any out-of-range/monotonicity guard note — same `text-[10px] text-surf-warning-ink` treatment `rail-controls.tsx`'s Bottom-Tuck-3 note already uses. **Not** used for anything else — no new "warning" surface color is introduced. |

**Never** use `--surf-accent` as a fill under body text without pairing `--surf-on-accent` for
that text — this codebase has been bitten by that exact bug three times (see
`.planning/quick/260825-rmb-*`); every new accent-filled element in this phase must set its
text/icon to `text-surf-on-accent` in the same conditional expression as the fill class, not a
separate always-on class.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None** — ROCKER is a continuous live editor like Outline/Rails/Fins/Volume, not an action form; there is no page-level submit/CTA button. The two real decision points this phase adds are toggles, not CTAs: **"Hide Board Outline"** (toolbar button, mirrors D-08/Template's Construction-Lines toggle wording) and, on RAILS, **"Use Board's Rocker & Foil Thickness"** (checkbox, default checked/linked — mirrors Volume's `"Calculate Volume Based on Template and Rail Data"` idiom exactly). Persistence stays the nav's existing autosave/Save control, unchanged. |
| Empty state heading | Not applicable — a new board always seeds `DEFAULT_ROCKER_SPEC`/`DEFAULT_FOIL_SPEC` (mirrors `DEFAULT_OUTLINE_SPEC`), so the screen never renders with no values, and D-15 guarantees a reopened pre-Phase-4 board backfills the same defaults silently. There is no zero-data state to design. |
| Empty state body | N/A (see above) |
| Error state | Typed datasheet field, on blur/enter, when `parseImperial` returns `null`: **"Couldn't read '{typed text}' as inches — try a number, a fraction like 2 5/8, or feet and inches like 6'2."** Shown as a `text-[10px] text-surf-warning-ink` line directly under the field; the field itself reverts to the last valid value (formatted via `formatInchesFraction`) rather than staying blank or holding invalid state — same "silently clamp/recover, never throw" posture as `clampFinite` elsewhere in this codebase. |
| Destructive confirmation | **None introduced this phase.** No delete/irreversible action exists on ROCKER or the RAILS override toggle. The closest analog — flipping RAILS' link toggle off to hand-edit thickness, then back on — is fully reversible with no confirmation dialog: turning the toggle back on simply resumes reading the shared value (the manual entry is preserved in state, not discarded, so toggling off again restores it — same `effectiveX`-derived-value pattern as Volume's import toggles, never a sync effect that overwrites data). |

## UI Considerations

Applicable state considerations resolved: 15 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | rocker-foil-typed-entry (form) | ✅ covered | Every field is always pre-filled with the current spec value (formatted via `formatInchesFraction`); there is no blank/unfilled state on load, mirroring every other numeric control in this app. |
| empty | rocker-foil-viewer (media) | ✅ covered | A new board seeds `DEFAULT_ROCKER_SPEC`/`DEFAULT_FOIL_SPEC` before the screen ever renders (same seeding as `DEFAULT_OUTLINE_SPEC`); the drawing is never "no curve yet." |
| empty | rocker-foil-datasheet-table (list-collection) | ✅ covered | Fixed cardinality — always exactly 5 stations, never 0; see zero-one-many row below. |
| loading | rocker-foil-typed-entry, rocker-foil-toolbar, rails-thickness-link-toggle (interactive-control/form) | ✅ covered | All computation is synchronous, pure client-side (`lib/geometry/rocker.ts`/`foil.ts`), no network round trip — there is no loading/in-flight state to design, matching every other design-screen control. |
| error | rocker-foil-typed-entry (form) | ✅ covered | See Copywriting Contract "Error state" row — inline warning-ink copy + revert-to-last-valid, resolved above. |
| error | rocker-foil-viewer (media) | ✅ covered | Fold-back (an invalid, physically-impossible curve) is prevented **by construction** — the monotone Fritsch-Carlson/PCHIP-style spline (RESEARCH.md Pitfall 5) cannot produce a folded curve from any station values a slider or the typed-entry validator can commit, so no "invalid drawing" error state is needed on the viewer itself. |
| error | rails-thickness-link-toggle (interactive-control) | ✅ covered | A toggle cannot itself error; no error state applicable. |
| populated | rocker-foil-viewer (media) | ✅ covered | The only real state: the side profile at whatever station values are current — same treatment as every other board viewer (Outline/Rails/Fins), scaled to fit its panel via the existing `preserveAspectRatio`/fit-scale mechanism. |
| populated | rocker-foil-datasheet-table (list-collection) | ✅ covered | Always renders all 5 stations × 3 columns (width/thickness/rocker) — the "populated" state is the only state (see empty/zero-one-many rows). |
| partial | rocker-foil-typed-entry (form) | ✅ covered | Each station field commits independently on its own blur/enter — there is no multi-field "submit," so no partially-filled-form state exists; a shaper can leave any subset of fields untouched indefinitely with no validation gate blocking the others. |
| partial | rocker-foil-datasheet-table (list-collection) | 🧪 backstop | A pre-Phase-4 saved board reopened under the new snapshot version backfills any missing `rocker`/`foil` fields from `DEFAULT_ROCKER_SPEC`/`DEFAULT_FOIL_SPEC` (D-15) before the table ever renders — needs an explicit `design-snapshot.test.ts` case proving no column ever shows `undefined`/`NaN` for an old row, not just visual inspection. |
| overflow | rocker-foil-datasheet-table (static-content/list-collection) | ✅ covered | Column values are fixed-format imperial fractions (`formatInchesFraction`, e.g. `23 1/2"`), bounded length (~7 chars max); no dynamic truncation/wrap logic is needed — same guarantee every other rail/dimension table in this app already relies on. |
| overflow | summary-rocker-box (static-content, D-04) | 🧪 backstop | The Summary order form's rocker box is a fixed-size reserved area (`RockerTicks` placeholder today); the real curve must fit that box at any extreme station combination (e.g. very high nose lift + very low tail lift) via the same `preserveAspectRatio` fit-to-viewBox technique the side-profile viewer uses, not a fixed-scale drawing that could clip. Needs a visual check at the board-length/rocker extremes the existing `BOARD_LENGTH_RANGE_IN` constants define, not just a mid-range board. |
| overflow | rocker-foil-viewer (static-content, wide/extreme boards) | 🧪 backstop | Mirrors the Outline viewer's own solved problem (fixed vs. growing frame for extreme boards, quick task `260823-h6l`) — the side-profile frame must be sized from the same board-length/width range constants so one frame fits every producible board without per-board resizing; needs the same fixed-frame treatment, not a new one-off. |
| zero-one-many | rocker-foil-datasheet-table (list-collection) | ✅ covered | Station count is fixed at exactly 5 by D-05 (a locked, costly-to-reverse decision) — there is no zero/one/many variability to design for; singular/plural copy is not applicable. |
| long-text | rocker-foil-datasheet-table, rocker-foil-toolbar (static-content/interactive-control) | ✅ covered | Station names ("Nose Tip", "Nose @ 12″", "Center", "Tail @ 12″", "Tail Tip") and toggle labels are fixed, short, English strings authored in this spec — no user-generated or unbounded-length text flows through this screen. |

## Component Notes for the Planner/Executor

Not part of the template's required sections, but recorded here because this phase introduces
genuinely new UI (the first typed-numeric-entry field and the first side-profile viewer in this
app) and the visual contract needs concrete anchoring, not just tokens.

**ROCKER screen shell** (`components/rocker/rocker-editor.tsx`, `app/design/rocker/page.tsx`)
mirrors `outline-editor.tsx` exactly: `aside` sidebar (`bg-surf-sidebar`, `p-10` scrolling
region + dev-only footer) beside a `main` canvas (`bg-surf-canvas`, `p-3`) holding a
`TabbedPanel`. Two tabs: **VIEWER** (the side-profile drawing) and **DATASHEET** (the D-07 full
five-station table) — not one screen cramming both, since the drawing wants full panel height
and the table wants full panel width; a tab switch is cheaper than a split that starves both.

**Toolbar** (inside the VIEWER tab's panel, absolutely positioned top-right over the drawing,
identical box treatment to Outline's four buttons — `border-surf-line bg-surf-ground p-1
rounded-md`, `size-6` icon, `focus-visible:ring-2 ring-surf-accent-ink`): rotate-in-place button
(D-03, reuse `RotateBoardIcon` verbatim) + "Hide Board Outline" toggle (D-08, reuse the
Construction-Lines button's `aria-pressed` accent-swap treatment, icon TBD by executor — pick
from lucide-react, something distinct from `LocateFixedIcon` which Outline already claims for
"show construction").

**Typed datasheet entry** (D-06): shadcn `Input`, narrow/fixed width (~64px), right-aligned
numeric text, `text-sm` — shown *inline in the DATASHEET table's rocker/thickness cells*, not in
a separate form. Displays `formatInchesFraction(value)` when not focused; on focus, shows the
raw editable string; on blur/Enter, runs `parseImperial`; success commits and reformats, failure
shows the Copywriting Contract's error line and reverts. This is the one wholly new interaction
pattern in the app — no existing screen has a typed numeric field wired to geometry state — so
build it as a small reusable component (e.g. `components/rocker/imperial-field.tsx`) rather than
inlining the parse/format/revert logic five times across the table.

**Side-profile viewer** (`components/rocker/rocker-viewer.tsx`): deck-over-bottom construction
(bottom curve = rocker, deck curve = rocker + thickness at each station — correct prior art from
`Rails.dc.html`'s `buildSideProfile`), drawn with the same SVG-`<text>`, snapped-rail callout
grammar as `outline-viewer.tsx`/`fin-viewer.tsx` (per `.planning/sketches/MANIFEST.md`): faint
dashed reference lines only, dimension values on an aligned rail, nothing but faint lines
crossing the drawn curves themselves. Width reference (D-07, read-only, derived from the drawn
outline) renders in the same muted/faint treatment as Outline's own station lines — never
implies it is editable on this screen.

**RAILS override toggle** (D-09/D-10): `Checkbox` + label, exact idiom as
`volume-controls.tsx`'s import toggles (`flex cursor-pointer items-center gap-1.5 text-sm
text-surf-ink-muted font-normal`), placed above the three rail sections' thickness sliders,
default checked. When checked, the per-section thickness sliders read the shared value and
render `disabled` (existing `opacity-40` treatment already used for disabled sliders in
`rail-controls.tsx`); when unchecked, they re-enable for manual entry.
