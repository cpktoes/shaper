# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds no new visual language. Every new surface (sign-in dialog, banner, Save
control, board rack, rack-card menu, rename/delete dialogs) is built from the existing
`surf-*` token contract in `app/globals.css` and the existing card/dialog patterns in
`components/setup/*` and `components/settings-menu.tsx`. Where this document is
prescriptive, it is pinning down *which* existing pattern to reuse and the exact copy —
not inventing new tokens, spacing, or color.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — do not re-run `shadcn init`) |
| Preset | not applicable — see frontmatter |
| Component library | Base UI (shadcn's `base-nova` style is a Base UI preset; some app chrome — e.g. `components/settings-menu.tsx` — is hand-built directly on `@base-ui/react/*` primitives rather than a generated `components/ui/*` wrapper, styled with `surf-*` tokens instead of the shadcn neutral scale) |
| Icon library | lucide-react |
| Font | Inter, loaded via `next/font` as `--font-inter` in `app/layout.tsx`; both `--font-display` and `--font-body` resolve to it (display/body are the same family, distinguished by weight/tracking/case, not typeface) |

**New shadcn components needed this phase** (not yet present in `components/ui/`):
- `dialog` — run `npx shadcn add dialog`. Used for the sign-in/sign-up dialog (D-03), the
  board-name prompt (D-05), and the rename dialog (D-13). Style it identically to the
  existing `alert-dialog` usage in `replace-board-dialog.tsx` (surf-panel surface,
  surf-line-faint border, surf-ink text) — no new chrome.
- `input` — run `npx shadcn add input`. Used for the name-prompt and rename dialogs. No
  raw `<input>` text-entry component exists in `components/ui/` today (the closest
  precedent, `OrderFormField` in `components/summary/order-form.tsx`, is a print-form
  field, not a dialog input — do not reuse it here).

**Do NOT add** a shadcn `dropdown-menu` component for the rack-card menu (D-13's
Rename/Duplicate/Delete affordance). Build it the same way `components/settings-menu.tsx`
builds the nav's gear menu: directly on `@base-ui/react/menu`, styled with `surf-*`
tokens (`bg-surf-panel`, `border-surf-line-faint`, `data-highlighted:bg-surf-well`). This
keeps the one existing menu pattern in the app as the only menu pattern, rather than
introducing a second, differently-themed one.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (e.g. rack-card internal `gap-2`, matching preset cards) |
| md | 16px | Default element spacing |
| lg | 24px | Section padding, grid gaps (`gap-6` between rack/preset cards) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (nav `px-12`) |
| 3xl | 64px | Page-level spacing (`pb-16` page padding) |

Exceptions: **12px** (`p-3`) — the established card/panel inset used by
`PresetCard`, `ContinueBoardCard`, and `TabbedPanel`'s content card. Every new rack card
and its inner thumbnail frame reuses this exact inset; do not introduce a different
padding value for the sake of the 8-point scale. This is a pre-existing, deliberate
exception (see `components/setup/preset-card.tsx`), not a new one created by this phase.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | Regular (400) | 1.5 |
| Label | 12px | Semibold (600) | 1.4 |
| Heading | 20px | Semibold (600) | 1.2 |
| Display | 30px | Extrabold (800) | 1.2 |

Two weights (Regular 400, Semibold 600) cover every new element this phase adds: dialog
body copy, banner text, rack-card metadata, menu items, form labels/errors. The **Display**
row's Extrabold (800) is a pre-existing, app-wide exception (page-level `h1`s like "Shape a
New Board", `font-extrabold`) that this phase's one new heading — the rack section's own
label, if given one — should match rather than redefine. Nav links and card CTA labels
(e.g. "Start Shaping") use `font-bold` (700) with `tracking-architectural uppercase` at
12px; this is the pre-existing "Label" treatment for uppercase eyebrow text specifically —
reuse it verbatim for the rack card's own CTA label and the "In progress — not saved" tag,
rather than the 600-weight Label row above (which is for sentence-case labels, e.g. form
field labels in the new dialogs).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--surf-ground` (#ffffff Daylight/Chalk · #12141a Slate · #050805 Phosphor) | Page background, dialog surface, Dialog overlay content |
| Secondary (30%) | `--surf-canvas` (#dfdcd3 Daylight/Chalk · #1a1d25 Slate · #142414 Phosphor) | Rack card outer frame (identical to `PresetCard`'s `bg-surf-canvas`), sign-in banner background |
| Accent (10%) | `--surf-accent-ink` (#48605c Daylight · #2b424c Chalk · #3490bc Slate · #52ab52 Phosphor) | See reserved-for list below |
| Destructive | `--surf-warning-ink` (#ac3811 Daylight/Chalk · #ff9670 Slate · #a6ffa6 Phosphor — already mapped to shadcn's `--destructive`) | Delete Board button/menu item only |

This app is themed (four named themes in `lib/theme.ts`); no single hex is "the" color for
any role — the hex values above are the Daylight-theme reference point. New UI must be
built against the `surf-*` token/utility names, never a literal hex, exactly like every
existing screen.

**Accent reserved for** (explicit list — nothing else may use it):
- Nav "Sign in" button hover/active text and the signed-in avatar's focus ring
- Nav Save button's filled state (`bg-surf-accent` / `text-surf-on-accent`) — same primary
  filled-button treatment as the site already has no other example of, so this is the
  first primary-filled button in the app; use shadcn `Button` default variant
- Sign-in banner's "Sign In" link text
- Rack card hover/focus ring and border (`hover:border-surf-accent-ink hover:ring-2
  ring-surf-accent-ink`) — identical to `PresetCard`/`ContinueBoardCard`
- Rack card CTA label text ("Open This Board")
- The "Saved" tick's checkmark icon
- Dialog primary action buttons (Sign In, Create Account, Save, Rename)

Rack-card menu items (Rename/Duplicate) use the **secondary** surface for hover
(`data-highlighted:bg-surf-well`), matching `SettingsMenu`'s `ThemeRow` — a menu row
highlight is not a 10%-budget accent moment.

## UI Considerations

Applicable state considerations resolved: 12 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | board-rack (list-collection) | ✅ covered | D-06 resolves this structurally: the rack section never renders when there are zero saved models AND no in-progress board — that view is exactly today's plain preset grid. There is no "empty rack" state to design. |
| loading | board-rack (list-collection) | 🧪 backstop | Home is a Server Component awaiting `listModels()` (RESEARCH.md architecture) — no client skeleton for the normal-speed case. If the query is ever slow enough to be visible, the Suspense fallback is the plain page shell with no rack section (same visual as "empty"), not a spinner. |
| error | board-rack (list-collection) | ✅ covered | If `listModels()` throws, the page renders the plain preset grid (same as signed-out) rather than a broken page — a board-list failure must never block starting a new board. |
| populated | board-rack (list-collection) | ✅ covered | Rack cards reuse `PresetCard`'s exact visual weight (window-frame thumbnail, name, one metadata line, uppercase CTA label) so a saved board reads with the same eye as a preset. |
| overflow | board-rack (list-collection) | ✅ covered | Same `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` wrap as the preset grid — many boards wrap to more rows, never scroll or clip. |
| zero-one-many | board-rack (list-collection) | ✅ covered | Zero+none → rack omitted (see "empty" row). In-progress card (if any) is always first per D-07; saved boards follow, sorted last-touched-first. |
| long-text | board-rack card name (static-content) | ✅ covered | Name truncates to one line (`truncate`), matching `ContinueBoardCard`'s existing `displayName` treatment — never wraps into the metadata line below it. |
| loading | save-button / autosave tick (interactive-control) | ✅ covered | In-flight state reads "Saving…" (ink-muted, no spinner icon) before settling to "Saved" with the accent check glyph. |
| error | save-button / autosave tick (interactive-control) | ✅ covered | Failure shows a quiet inline "Not saved" in warning-ink beside the button, clickable to retry immediately — no interrupting dialog (Claude's Discretion item, per CONTEXT.md). |
| loading / error | sign-in dialog (form) | ✅ covered | Clerk's own `<SignIn>`/`<SignUp>` manage their own in-flight and inline field-error states; the app supplies only the surrounding Dialog chrome, no duplicate copy. |
| long-text | sign-in dialog (form) | 🧪 backstop | Long email addresses in Clerk's own UI are Clerk's rendering responsibility; the wrapping Dialog's width (`max-w-sm`, matching the existing `AlertDialogContent` default) must not clip them — verify at execution with a deliberately long test email. |
| error | name-prompt / rename dialog (form) | ✅ covered | Empty/whitespace-only name is rejected inline ("Board needs a name.") before any Server Action runs, mirroring RESEARCH.md Pattern 2's trim-check. |
| error | delete-confirm dialog (form) | ✅ covered | A failed delete keeps the dialog open with inline "Couldn't delete — try again." rather than silently closing. |
| long-text | rename / name-prompt input (form) | ✅ covered | No character cap in the UI (the DB `text` column is unbounded); long names are handled by rack-card truncation (see the board-rack long-text row above), not by truncating the input itself. |
