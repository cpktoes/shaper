# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this contract:** the one net-new surface in Phase 1 — the setup/entry screen (D-05: `/`
> replaces the current `redirect("/design/outline")`) — plus the nav change it requires (D-06: SHAPER
> wordmark links home). The five existing design screens (Template/Rails/Volume/Fins/Summary) were
> ported in prior quick tasks and already have an established visual language; this contract does not
> restyle them, only extends their conventions to the new screen and states where it deliberately departs.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `b2fA` — style **nova**, baseColor **neutral**, theme **neutral**, radius **default**, font **Geist** (`https://ui.shadcn.com/create?preset=b2fA`) |
| Component library | **base-ui** (`@base-ui/react`) — this preset's primitives are base-ui, not Radix; confirmed from `components/ui/button.tsx`'s `import { Button as ButtonPrimitive } from "@base-ui/react/button"` |
| Icon library | lucide-react |
| Font | Geist Sans (body + heading, `--font-heading` maps to `--font-sans`); Geist Mono loaded but unused in UI copy |

**Two visual languages already coexist in this codebase — this contract keeps them separate on purpose:**

1. **shadcn neutral theme** (`--background`, `--card`, `--primary`, etc. in `app/globals.css`) — the
   default light theme, currently unused by any shipped screen but available for new, non-editor UI.
2. **`outline-*` brand palette** (`--outline-accent` #c98d3a amber, dark `--outline-sidebar-bg` #2b2924,
   parchment `--outline-page-bg` #f7f4ee) — the port's real brand identity, used by the nav bar and all
   five design screens' sidebars/canvases.

The setup screen is new chrome, not a sixth editor screen, so it uses the **shadcn neutral theme** for
its layout (light canvas, white cards) but borrows the **`outline-accent` amber** as its one accent
color, so the brand reads as one product rather than two. Full rationale in the Color section below.

**Nav:** `components/site-nav.tsx` is currently mounted only inside `app/design/layout.tsx`. Per D-06
(wordmark links home) the same dark nav bar (`bg-outline-sidebar-bg`, SHAPER wordmark + 5 tabs) must
also render on `/`, with no tab highlighted while there. Promote `<SiteNav />` to `app/layout.tsx`
(root) rather than duplicating it — the setup screen sits below it, on the light neutral canvas.

## Spacing Scale

Declared values (must be multiples of 4) — applies to the new setup screen's own layout:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding |
| sm | 8px | Compact spacing inside a preset card (thumbnail-to-title gap) |
| md | 16px | Preset card internal padding, gap between card content blocks |
| lg | 24px | Grid gap between preset cards, page horizontal padding on mobile |
| xl | 32px | Page horizontal/vertical padding on desktop, gap above hero heading |
| 2xl | 48px | Gap between hero heading block and preset grid |
| 3xl | 64px | Top-of-page breathing room below the nav bar |

Exceptions: shadcn/base-ui component internals (`Button` heights `h-8`/`h-9` = 32/36px, `Card`
`--card-spacing` = 16px/12px, focus ring offsets) ship at their own fixed values and are **not**
overridden — treat them as inherited, not as new exceptions to justify per-instance. The confirm
dialog's touch targets (Discard/Cancel buttons) use the standard `h-9` (36px) button size, not the
44px minimum, consistent with every other button already shipped in this app.

## Typography

Declared for the new setup screen (existing screens keep their own established sizes — see
Design System note above):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | regular (400) | 1.5 |
| Label | 12px | semibold (600) | 1.4 |
| Heading | 20px | semibold (600) | 1.2 |
| Display | 32px | semibold (600) | 1.15 |

Usage:
- **Display** — the single page hero heading, e.g. "Shape a New Board" (or "Start a New Design")
- **Heading** — preset card titles ("Shortboard", "Fish", "Mid-length", "Longboard") and the
  "Continue Current Board" card title, plus the confirm dialog's heading
- **Body** — preset descriptor copy, dialog body copy, "Continue current board" board-name preview
- **Label** — uppercase tracked eyebrow/meta text (e.g. a "PRESET" or dimension chip on a card),
  matching the existing site's convention of small bold-uppercase micro-labels

Note: shadcn's own `CardTitle`/`Button` primitives ship at `font-medium` (500) internally — that is a
component-internal default, left as-is; only setup-screen-authored heading/label text uses the 600
declared above.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` — oklch(1 0 0), white | Page canvas behind the preset grid |
| Secondary (30%) | `var(--card)` / `var(--muted)` — oklch(1 0 0) / oklch(0.97 0 0), white/near-white | Preset cards, "Continue current board" card, dialog surface |
| Accent (10%) | `var(--outline-accent)` — #c98d3a amber | Reserved for: selected/hover preset card border + ring, the "Start Shaping" and "Continue This Board" action labels/hover states, focus ring on cards |
| Destructive | `var(--destructive)` — oklch(0.577 0.245 27.325), red | Reserved for: the "Discard & Start New" button in the replace-board confirm dialog only |

Accent reserved for: preset-card selected/hover border and focus ring, the "Start Shaping" in-card
action label, the "Continue This Board" CTA, and (already established, unchanged) the active nav tab
underline. Never used for body text, card backgrounds, or informational badges.

The dark nav bar (`--outline-sidebar-bg`) is treated as fixed, existing chrome outside this 60/30/10
split — it is a thin top strip carried over unchanged from the design screens, not new surface area
being designed here.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Each preset card's action label: **"Start Shaping"** (clicking anywhere on the card, per D-04, drops the user into the outline editor with that preset applied — but the card must carry this explicit label/affordance so the action is visible, not just implied by hover) |
| Empty state heading | Not applicable — the preset grid is a fixed 4-card roster (D-01) that is never empty at runtime; the "Continue current board" card is omitted entirely (not shown empty) when there's no board in progress (D-07) |
| Empty state body | Not applicable — see above |
| Error state | Not applicable in Phase 1 — the setup screen and its confirm dialog are pure client-side state with no network calls or form validation. If a future phase adds one, default to: "Something went wrong. Try refreshing the page." |
| Destructive confirmation | Replacing an in-progress board with a new preset (D-07): dialog heading **"Start a new design?"**, body **"This replaces your current board in progress. It hasn't been saved yet — saving arrives in Phase 2."**, confirm button **"Discard & Start New"** (destructive), cancel button **"Keep Editing"** |

Additional fixed copy for this screen:
- Page hero heading: **"Shape a New Board"**
- "Continue current board" card title: **"Continue Current Board"**, action label: **"Continue This Board"**
- Preset descriptors (one line each, Claude-drafted, user-tunable per D-03): e.g. Shortboard —
  "Fast and responsive, for performance surfing"; Fish — "Wide and flat, for small-to-mid days";
  Mid-length — "Easy paddling with room to maneuver"; Longboard — "Smooth glide, nose-to-tail control"

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Probe run 2026-08-19 (post-verification, interactive). 6 elements, 30 applicable considerations:
**28 resolved (explicit), 2 resolved (backstop), 0 unresolved.** User-confirmed decisions marked (U).

**E1 — Preset grid** (list + media + control)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | ✅ covered | Preset roster is a compile-time constant of exactly 4 cards (D-01); the grid can never render with zero cards — no empty state exists |
| loading | ✅ covered | Cards and thumbnails render synchronously client-side; no network fetch, no skeleton/spinner state |
| error | ✅ covered | No async operations or server calls on this screen in Phase 1 — no error path; see Copywriting Contract's Error state row for the future-phase default |
| populated | ✅ covered | Happy path: 4 preset cards in a responsive grid, each showing an outline thumbnail (D-08), the preset name, a one-line descriptor, and the "Start Shaping" action label |
| partial | ✅ covered | Preset specs are complete compile-time constants — a card can never render with missing fields; no partial state exists |
| overflow | ✅ covered | Grid reflows to fewer columns at narrow widths; cards never clip or scroll horizontally |
| zero-one-many | ✅ covered | Always exactly 4 cards — no zero/one/many variance in the roster |
| long-text | 🧪 backstop | Descriptor copy is fixed, team-authored, single-line (<~40 chars) by construction — verification: backstop — verify no descriptor wraps or truncates at the card's minimum supported width |

**E2 — Continue Current Board card** (control + text; user-confirmed contracts)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | ✅ covered | Card is entirely omitted (not rendered) when no board is in progress in the store (D-07) — no placeholder/empty version |
| loading | ✅ covered | (U) Card pops in after client store hydration; no skeleton and no reserved space — the brief absence during the hydration window is accepted |
| error | ✅ covered | Client-only store read; no failure path in Phase 1 |
| populated | ✅ covered | One card: title "Continue Current Board", board-name preview, "Continue This Board" action label |

| overflow | ✅ covered | (U) Board-name preview clamps to one line with ellipsis truncation |
| zero-one-many | ✅ covered | Zero boards → card omitted; one board → exactly one card beside the 4 presets; "many" impossible — the store holds a single current board (D-07) |
| long-text | ✅ covered | (U) Same contract as overflow: user-entered name truncates to one line with ellipsis |
