    New cases in `lib/geometry/units.test.ts`:

    `describe("formatWholeMm")`:
    - `mm(67)` reads `"67"`; `mm(66.6)` reads `"67"`; `mm(66.4)` reads `"66"`.
    - `inchesToMm(2.625)` reads `"67"` — the same value that reads `"6.7"` through `formatCentimetres`.
    - `mm(66.5)` reads `"67"` — a value exactly on the boundary rounds away from zero, matching
      `formatCentimetres`'s tie-break, so the two formatters never disagree about the same value.
    - `mm(-66.5)` reads `"-67"`.
    - `mm(0)` reads `"0"`, with no decimal point and no minus sign.

    `describe("roundToWholeMm")`:
    - `mm(66.6)` snaps to `mm(67)`; `mm(66.4)` snaps to `mm(66)`; an already-whole value is unchanged.
    - The snap agrees with the formatter: for a table of values, `formatWholeMm(roundToWholeMm(v))`
      equals `formatWholeMm(v)`.

    `describe("parseMetric")`:
    - `parseMetric("51.4", "cm")` is `mm(514)`; `parseMetric("67", "mm")` is `mm(67)`.
    - `parseMetric("514 mm", "cm")` is `mm(514)` — an explicit suffix overrides the field's unit.
    - `parseMetric("6.7cm", "mm")` is `mm(67)` — suffix with no space, overriding the other way.
    - Case and spacing are tolerated: `"51.4 CM"`, `" 51.4cm "`, `"51,4"` is **not** accepted
      (a comma decimal separator returns null rather than being guessed at).
    - `parseMetric("-5.1", "cm")` is `mm(-51)` — the sign survives.
    - Null cases, mirroring `parseImperial`: `""`, `"   "`, `"cm"`, `"abc"`, `"5 1/2"` (an imperial
      fraction typed into a metric field), `"5.1.2"`.
    - Round trip: for a table of millimetre values, `parseMetric(formatCentimetres(v), "cm")` lands
      within half a millimetre of `v`, and `parseMetric(formatWholeMm(v), "mm")` within half a
      millimetre of `v` — the display precision and the parse precision agree.
  </behavior>

  <action>
    Add three exports to `lib/geometry/units.ts`, beside the existing imperial ones, each with the
    doc-comment density the file already carries:

    - `formatWholeMm(value: Mm): string` — the **marks** family of D-02: rail band marks, rocker
      heights and the five foil station thicknesses, the numbers a shaper measures with a rule
      rather than quotes as a size. Rounds to the nearest whole millimetre and returns a **bare
      number with no unit suffix**, matching `formatCentimetres`. Apply the same signed epsilon
      nudge `formatInchesFraction` documents, and for the same reason, so a value on a boundary
      cannot land on the wrong side of it from conversion noise — and so this formatter and
      `formatCentimetres` always agree about the same value.
    - `roundToWholeMm(value: Mm): Mm` — the metric counterpart of `roundToSixteenthInch`: a snap on
      the model, not a display nicety, for the sliders Phase 6 will step in whole millimetres.
    - `parseMetric(input: string, fieldUnit: "cm" | "mm"): Mm | null` — D-04. A bare number is read
      as the field's own unit; an explicit `cm` or `mm` suffix (any case, with or without a space)
      overrides it. Trim first; return `null` for empty or whitespace-only input, for a suffix with
      no number, and for anything that does not match cleanly — the same return-null-never-throw
      contract `parseImperial` holds, because the field's commit path reverts to the last good
      value on null. Accept a leading minus and a single decimal point; reject a comma decimal
      separator and reject an imperial fraction, because guessing at either would silently produce
      a wrong number a shaper might cut to.

    Document in `formatWholeMm`'s comment why D-02 splits the two families by what the number *is*
    rather than where it appears: a foil's centre thickness reads in centimetres on a card's
    dimensions line and in whole millimetres in the datasheet column, and both are correct.

    There is no prototype ancestor for the metric side, so there is no golden fixture to extract —
    expected values in the tests are computed from the known conversion (ten millimetres to the
    centimetre) and stated as such in a provenance comment, the same sanctioned exception Phase 4
    used. Do not hand-transcribe a number without saying where it came from.
  </action>
