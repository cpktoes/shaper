# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase touches three surfaces only — the gear-menu chooser, the preset cards, and the rack
cards — per its own scope note: the five design screens (Phase 6) and print output (Phase 7)
stay Imperial and are out of this contract. **Nothing here is a new visual language.** Every row,
card and typographic choice below is an exact reuse of a pattern already shipping in this
codebase (`ThemeRow` in `components/settings-menu.tsx`, `CardMetadataLine` in
`components/setup/board-rack-card.tsx`) — the only genuinely new surface is the preset card's
dimensions line, and even that is a byte-for-byte copy of the rack card's existing line. This
document is prescriptive about the two things CONTEXT.md's D-01..D-16 didn't spell out in pixels:
the exact composed strings for both systems, and where the new preset-card line sits typographically
relative to its neighbours.

Non-interactive session note: every design question CONTEXT.md left open ("Claude's Discretion")
is resolved below with a concrete, defensible default and flagged **[ASSUMPTION]** — the planner
may treat these as locked defaults, not open questions, unless the founder revisits them.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, no gate needed) |
| Preset | `base-nova` (read from `components.json`) |
| Component library | Base UI (per project CLAUDE.md: "shadcn/ui components built on Base UI") — the Units group is built directly on Base UI's `Menu` primitives inside `components/settings-menu.tsx`, exactly like the existing Theme group, not a new `components/ui/*` wrapper |
| Icon library | lucide-react — `Ruler` (confirmed present in the installed `lucide-react` package; not `PencilRuler`, which reads as an editing/drafting icon rather than a measurement one) |
| Font | Inter — `--font-inter`, aliased to `--font-display`/`--font-body` (unchanged; no new font role needed by this phase) |

Theming: four named themes (Daylight/Chalk light, Slate/Phosphor dark) via `lib/theme.ts` +
`app/globals.css`'s three-layer token system. **Every element this phase adds or edits must use
an existing `surf-*` Tailwind utility already present on its sibling element — never a new
literal color.** Concretely: the new Units rows reuse `ThemeRow`'s exact classes verbatim, and
the new preset-card dims line reuses `CardMetadataLine`'s exact classes verbatim. There is no new
color decision to make in this phase. Verify in at least Daylight and one dark theme (Slate)
before calling a plan done, per this codebase's established practice.

## Spacing Scale

No new spacing token is introduced. Every new element in this phase is inserted into a flex
container that already spaces its children:

| Location | Existing gap | New element's spacing |
|----------|-------------|------------------------|
| `preset-card.tsx`'s outer `<button>` (`flex flex-col gap-2`) | `gap-2` (8px) | The new dims-line `<span>` is inserted between the name span and the descriptor span; it inherits the same 8px gap on both sides automatically — no new margin/padding class needed |
| `settings-menu.tsx`'s `Menu.Popup` (`p-1.5`, rows are `Menu.RadioGroup`s stacked with `mt-1.5` between mode headings) | existing | The new Units `Menu.RadioGroup` sits as a sibling block above the existing Theme `Menu.RadioGroup`, inside the same `Menu.Popup`; give it the identical `mt-1.5` top spacing the "Light"/"Dark" mode-heading `div`s already use, so the visual rhythm between the two groups matches the rhythm within the Theme group — **[ASSUMPTION]**: no existing precedent for "space between two top-level radio groups in one popup" exists yet (Theme is currently the only group), so this phase sets it |
| `Menu.RadioItem` row (`ThemeRow`) | `gap-2.5 rounded-md px-2 py-1.5` | The new `UnitsRow` reuses this exact class string unchanged — same padding, same icon gap |

Exceptions: none.

## Typography

No new type size or weight is introduced. Every role below is an exact reuse of an existing,
already-shipping element:

| Role | Size | Weight | Line Height | Reused from |
|------|------|--------|-------------|-------------|
| Menu group label ("Units") | 10px (`text-[10px]`) | 700 bold, uppercase, `tracking-architectural` | 1.2 (default for this size) | `Menu.GroupLabel` — identical classes to the existing "Theme" label, only the text changes |
| Units row label ("Imperial" / "Metric") | 14px (`text-sm`) | 400 regular | 1.4 (`leading-tight` via the row's `flex-1 leading-tight` wrapper) | `ThemeRow`'s label span, reused verbatim as `UnitsRow`'s label span |
| Units row detail (the live example string) | 11px (`text-[11px]`) | 400 regular | 1.4 | `ThemeRow`'s detail span, reused verbatim |
| Preset card dims line | 12px (`text-xs`) | 600 semibold | 1.4 (`leading-[1.4]`) | `CardMetadataLine` in `board-rack-card.tsx`, reused verbatim — this is the one line this phase adds to a screen a shaper actually reads (not a menu), so it must be pixel-identical to the rack card's own line per D-14 ("the two card types now match line for line") |
| Preset card name (unchanged) | 20px (`text-[20px]`) | 600 semibold | 1.2 | existing, untouched |
| Preset card descriptor (unchanged) | 14px (`text-sm`) | 400 regular | 1.5 | existing, untouched |

Note on weight count: this table lists three weights (400, 600, 700) because it is documenting
reuse of three *already-shipping* elements from two different existing components, not proposing
a new type system for this phase. No new weight is introduced; nothing in this phase invents a
size or weight that doesn't already exist on the exact element being mirrored.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None.** The Units picker is a continuous preference toggle exactly like the Theme picker, not an action form — there is no submit/confirm button. The group label reads **"Units"** (mirrors "Theme" — short, plain, matches the existing menu's terse register). Row labels read **"Imperial"** and **"Metric"** (title case, matching "Light"/"Dark"). Existing card CTAs ("Start Shaping", "Open This Board", "Continue This Board") are untouched by this phase. |
| Row detail copy (live example) | Formatted, never hand-typed (D-06), through the same functions the cards use. **Imperial row:** `{formatFeetInches(length)} · {formatInchesFraction(width)} · {formatInchesFraction(thickness)}` — three numbers, no litres, matching D-06's literal example `6'2" · 20 1/4" · 2 5/8"`. **Metric row:** `{formatCentimeters(length)} × {formatCentimeters(width)} × {formatCentimeters(thickness)} cm` — three numbers, unit once at the end, matching D-06's literal example `188.0 × 51.4 × 6.7 cm`. **Reference board [ASSUMPTION]:** the fixed `Shortboard` entry in `BOARD_PRESETS` (`lib/geometry/presets.ts`), run through the same `summarizeDesign()` pipeline the cards use, read at render time — not the illustrative `6'2" × 20 1/4" × 2 5/8"` numbers from the discussion (those were CONTEXT.md's format example, not a literal preset lookup; Shortboard's actual length is 74in/6'2" but its own width and thickness differ, and the row must show its own real computed numbers, not the discussion's placeholder ones). A fixed preset is chosen over the in-progress board per CONTEXT.md's own stated preference ("simplest and keeps the row stable") — a shaper switching units mid-edit should not also see their own board's numbers jump twice (once for the menu example, once for whatever screen is behind it). |
| Empty state | Not applicable. The chooser always has a selection (Imperial is the default, never blank); both cards always render four real numbers via `summarizeDesign()` — there is no zero-data state for either surface this phase touches. |
| Loading state | Not applicable. Every value here (menu detail, card dims line) is computed synchronously from in-memory geometry — no fetch, no skeleton. The one asynchronous piece (D-11's background account write) is invisible by design: the screen has already switched, and a failed write retries quietly with no toast, spinner, or banner ever shown to the shaper — same silent-retry posture as autosave. |
| Error state | Not applicable to this contract. A units pick cannot itself fail visibly (D-11: "a failed write never blocks the switch and never reverts the screen") — there is no error copy to author because there is no error the shaper ever sees. |
| Destructive confirmation | **None.** Switching systems is fully and instantly reversible (D-16) — no dialog, no confirmation, no undo affordance, because there is nothing to undo: the numbers are re-labeled, not rewritten. |

**Not part of this table, noted for completeness:** CLAUDE.md Rule 2's rewording (dropping the
"inches-only" claim) is project-documentation copy, not on-screen UI copy — it is a Phase 5
deliverable per the roadmap but outside a UI-SPEC's scope (no dimension of the checker's six
applies to a markdown rules file). The planner should still track it as a task; it just isn't
specified here.

## Component Notes for the Planner/Executor

Not part of the template's required sections, but recorded because this phase's two new/changed
surfaces are simple enough that the prescriptive detail lives better here than spread across the
tables above.

**Units group in the gear menu** (`components/settings-menu.tsx`): a second
`Menu.RadioGroup` added *above* the existing Theme one, inside the same `Menu.Popup`, same
pattern end to end:

```
<Menu.RadioGroup value={unitsPreference} onValueChange={...}>
  <Menu.GroupLabel className="px-2 pt-1 pb-2 text-[10px] font-bold tracking-architectural text-surf-ink-muted uppercase">
    Units
  </Menu.GroupLabel>
  <UnitsRow value="imperial" label="Imperial" detail={imperialExample} />
  <UnitsRow value="metric" label="Metric" detail={metricExample} />
</Menu.RadioGroup>
{/* existing Theme Menu.RadioGroup follows, unchanged, with mt-1.5 spacing above it if not
    already present between top-level groups */}
```

`UnitsRow` is `ThemeRow` with a fixed `Ruler` icon for both rows instead of a per-mode icon
(D-07: "both rows carry a ruler icon" — unlike Theme, where the icon varies by mode, Units has
only one dimension of variation, the system, so one icon suffices and a second icon would imply
a distinction that doesn't exist). `closeOnClick={false}` on both `Menu.RadioItem`s, matching
every existing `ThemeRow` (D-07). No reassurance line under the group (D-08) — the group ends at
the second row, exactly as terse as Theme.

**Preset card dims line** (`components/setup/preset-card.tsx`): one new `<span>` inserted between
the existing name span and descriptor span:

```
<span className="text-[20px] leading-[1.2] font-semibold text-foreground">{preset.name}</span>
<span className="text-xs leading-[1.4] font-semibold text-surf-ink-muted">{dimsLine}</span>
<span className="text-sm leading-[1.5] text-surf-ink-muted">{preset.descriptor}</span>
```

`dimsLine` is produced by the same formatting logic `CardMetadataLine` already uses in
`board-rack-card.tsx`, run against `summarizeDesign()` of the preset's own outline/rocker/foil/
rails/fins (D-13) rather than a second, divergent computation. Because both card types now need
byte-identical formatting logic for two systems, the planner should extract `CardMetadataLine`
(or an equivalent) into a shared module both `preset-card.tsx` and `board-rack-card.tsx` import,
rather than duplicating the format-and-join logic — this is an implementation decision, not a
new visual contract; the rendered string and its styling are already fully specified by the
Typography and Copywriting tables above.

**Rack card's existing dims line** (`CardMetadataLine`, `board-rack-card.tsx`): no new visual
element — the existing line becomes system-aware. Its classes (`text-xs leading-[1.4]
font-semibold text-surf-ink-muted`) do not change; only the composed string does, per system:

- Imperial (unchanged today): `{formatFeetInches(length)} · {formatInchesFraction(width)} · {formatInchesFraction(thickness)} · {volume.toFixed(1)} L`
- Metric (new): `{formatCentimeters(length)} × {formatCentimeters(width)} × {formatCentimeters(thickness)} cm · {volume.toFixed(1)} L`

Both the preset card's new dims line and the rack card's existing dims line use this same
two-branch composition — one function, two systems, matching D-01/D-02/D-03's cm-with-one-decimal,
dims-not-marks, unit-once-at-the-end rules exactly as CONTEXT.md states them. `formatCentimeters`
is this document's placeholder name for whatever the planner names the new `lib/geometry/units.ts`
export — naming is explicitly left to the planner by CONTEXT.md's "Claude's Discretion" section;
only its input/output contract (an `Mm` value in, a one-decimal bare number string out, no unit
suffix) is fixed here so the composed strings above come out exactly as specified.

**No discoverability hint anywhere on the setup screen** (D-15): neither card gains a "tip" or
affordance pointing at the gear menu. The gear icon itself is unchanged.
