<objective>
Extract one shared slider row and migrate all five control sidebars onto it, in a single pass.

Purpose: this is the first of Phase 5's two folded todos
(`.planning/todos/pending/2026-08-30-extract-shared-sliderrow-across-control-sidebars.md`), folded
here as groundwork for Phase 6, where every slider on the five design screens starts reading the
chosen units system. Today the same label-slider-hints markup is written out five times, and each
file declares its own copy of the helper that reads a value out of the Base UI callback. Phase 6
would have to touch all five copies; after this it touches one component and five call sites, and
each call site still shows its own conversion — which is exactly where the units hook plugs in.

This plan carries no new requirement of its own; it is listed under UNIT-02 as the requirement
whose origin todo folded it into this phase. Nothing a shaper sees should change.

Output: `components/design/slider-row.tsx`, five migrated sidebars, and a drift guard so the
duplication cannot quietly come back.
</objective>

  <action>
    Create `components/design/slider-row.tsx` (a `"use client"` module, beside `design-store.tsx`
    because all five screens share it) exporting two things:

    - `sliderValue(v: number | readonly number[]): number` — the helper currently declared
      identically in all five sidebars, moved here once.
    - `SliderRow` — the union of the three existing local row helpers, so no sidebar loses anything:
      - `label: string` — the label line's text.
      - `displayValue?: string` — when present the label line renders as the label, an em dash with
        spaces around it, then the value; when absent the label is rendered alone (three of the
        five sidebars already fold the value into the label string, and forcing them to split it
        would change wording).
      - `value`, `min`, `max`, `step` — passed straight to the slider.
      - `onValueChange: (value: number) => void` — called with the value already read out of the
        Base UI callback via `sliderValue`. **This prop is the whole point of the extraction**: each
        slider's own conversion (inches to millimetres, a branded degrees value, a plain percentage)
        stays at its call site where a reader can see it, and where Phase 6 will plug in the units
        hook. Document that in the component's doc comment.
      - `disabled?: boolean` — dims the whole row and disables the slider.
      - `leftHint?`, `rightHint?` — the two-ended hint line under the track, rendered only when at
        least one is present.
      - `note?: string` — the warning-coloured line under the hints.
      - `className?: string` — for the flex sizing the paired two-per-line layouts need, composed
        with the disabled dimming through `cn`.
      - `density?: "default" | "tight"` — the label's bottom margin. Default matches the four
        sidebars that use the wider gap; `tight` preserves the FINS sidebar's slightly closer
        spacing. This exists so the migration changes nothing visually; do not normalise the two.

      The rendered markup, classes and element order must be copied from the existing helpers
      verbatim — the label div, the slider with its accent class, the hint row with its two spans,
      and the note div — so every screen looks byte-identical afterwards.

    Then migrate the three sidebars that already have a local row helper, deleting each local
    declaration and each local copy of the value helper, and importing the shared ones instead:

    - **TEMPLATE (`outline-controls.tsx`)** — its local helper is the closest match; the migration
      is an import swap plus passing its flex sizing through `className`. Every one of its call
      sites keeps its exact props. Its disabled behaviour, its hints, its note line and its
      clamped-depth warning must all still work; the todo names those explicitly as what the
      extraction has to preserve.
    - **RAILS (`rail-controls.tsx`)** — swap its two call sites to the shared component, renaming
      its hint props to the shared names and leaving its labels as they are (the value is already
      in the label string, so no `displayValue` is passed). Its disabled wrapper had no flex sizing;
      pass no `className` so it stays that way. Leave its four remaining standalone sliders for
      task 2.
    - **FINS (`fin-controls.tsx`)** — swap its six call sites, passing `density="tight"` so its
      label spacing is unchanged, and leaving its hint props mapped to the shared names. It passes
      no disabled and no note, which the shared component already treats as optional. Leave its two
      remaining standalone sliders for task 2.

    Do not touch any slider's range, step, clamping or conversion. Do not consolidate the
    `clampFinite` helper — that is a separate duplication and out of scope here.
  </action>
