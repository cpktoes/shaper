<assumption_delta_decision>
**Detector:** `assumption-delta scan 05` returned `detected: true` — two signals, `pluralization`
on "fallback" and `chosen` on "chosen".

**The noun that is now primary:** the **chosen units system**. Before this phase the app had one
hard-coded display system (inches and litres); after it, a display system is a *value* that every
label site asks for.

**Decision: `promote`.** `UnitsSystem` is declared in `lib/geometry/units.ts` — the units boundary
itself — and Imperial is demoted from "the way the app renders" to one of two variants of that
type. Every display site takes a `UnitsSystem` argument rather than defaulting to inches with a
metric branch bolted alongside. Rationale: adding Metric alongside a still-privileged Imperial
would leave Imperial as the only system a site is guaranteed to handle, and Phase 6's ~300 call
sites would inherit that asymmetry.

**Companion invariant test (accepted):** `lib/geometry/summary-line.test.ts` iterates the exported
`UNITS_SYSTEMS` array rather than naming the two systems by hand, and asserts every system
produces a non-empty line whose numbers all came from `units.ts`. A future phase that adds a
system, or quietly drops a branch, fails that test instead of silently falling back to Imperial.
</assumption_delta_decision>

    **`lib/geometry/units.ts`** — add, beside the imperial functions: `export type UnitsSystem =
    "imperial" | "metric"`, `export const UNITS_SYSTEMS: readonly UnitsSystem[] = ["imperial",
    "metric"]`, `MM_PER_CM = 10`, `mmToCentimetres(value: Mm): number`,
    `centimetresToMm(value: number): Mm`, and `formatCentimetres(value: Mm): string`.
    `formatCentimetres` returns a **bare number with exactly one decimal and no unit suffix** —
    `"188.0"`, not `"188.0 cm"` — because the unit is composed once at the end of a line (D-03).
    Apply the same signed epsilon nudge (`1e-9`, negated for negative values) that
    `formatInchesFraction` documents, before `toFixed(1)`, for the same reason: a value that
    round-tripped through inches can land a few ULPs on the wrong side of a rounding boundary.
    Document `UnitsSystem` as the type that names the app's two measuring systems, and note that
    Imperial is one variant of it rather than a privileged default.

    **`lib/geometry/summary-line.ts`** (new, pure — no React, no browser, no database, per Rule 1)
    — the one place a `DesignSummary` becomes the text on a card or a menu row:
    - `formatSummaryLine(summary: DesignSummary, system: UnitsSystem): string`. Imperial branch
      composes exactly the string `CardMetadataLine` renders today —
      `formatFeetInches(length)`, `formatInchesFraction(widePointWidth)`,
      `formatInchesFraction(centerThickness)` and `volumeLitres.toFixed(1)` followed by a space and
      `L`, joined by a space-middot-space separator. Metric branch composes
      `formatCentimetres(length)`, `formatCentimetres(widePointWidth)` and
      `formatCentimetres(centerThickness)` joined by a space-multiplication-sign-space separator,
      then a space and `cm`, then the same middot separator and the same litres part (D-01, D-02
      dims family, D-03). Use the real `×` (U+00D7) and `·` (U+00B7) characters, matching the
      existing file.
    - `formatDimsExample(summary, system)` — the same three dimensions with the litres part
      omitted, for the D-06 menu rows.
    - `presetSummary(preset: BoardPreset): DesignSummary` — calls `summarizeDesign` with the

      coupling in the doc comment and point at the source-contract test that guards it, so the
      numbers a card quotes are the numbers a click actually produces (D-13).

    **`lib/units-preference.ts`** (new, DOM-free, mirroring `lib/theme.ts`) — the preference
    boundary. `UNITS_STORAGE_KEY = "shaper-units"`, `UNITS_COOKIE_NAME = "shaper-units"`,
    `UNITS_COOKIE_MAX_AGE_SECONDS = 31_536_000`, `DEFAULT_UNITS_SYSTEM: UnitsSystem = "imperial"`.
    The one place this diverges from theme: `parseUnitsPreference(value: unknown): UnitsSystem |
    null` returns **null, not a default**, for an absent or unrecognised value — "nothing chosen
    yet" has to be representable everywhere the preference lives (D-10), and the rendering default
    is applied by the caller via `resolveUnitsSystem(preference: UnitsSystem | null): UnitsSystem`.
    Treat every stored value as untrusted input: `parseUnitsPreference` is an allow-list against
    the two members of `UNITS_SYSTEMS` and nothing else; it never interprets, evaluates or trusts
    what it is handed. `unitsCookieString(system): string` returns the `document.cookie` assignment
    string with `Path=/`, `Max-Age`, and `SameSite=Lax` (no `Secure`, so it works on
    `http://localhost:3000`; no `HttpOnly`, because the browser is the writer and the value is a
    display preference carrying nothing sensitive). `readUnitsCookie(cookieHeader: string | null |
    undefined): UnitsSystem | null` splits on `;`, finds the named cookie, decodes it and runs it
    through `parseUnitsPreference`.

    Also declare the handoff contract here, pure and tested, because it is the rule UNIT-04 turns
    on: `interface UnitsHandoff { system: UnitsSystem; adoptIntoBrowser: UnitsSystem | null;
    promoteToAccount: UnitsSystem | null }` and `decideUnitsHandoff(input: { signedIn: boolean;
    account: UnitsSystem | null; browser: UnitsSystem | null }): UnitsHandoff`. The rule, per D-09
    and D-10: an account value always wins and the browser adopts it; an empty account plus an
    explicit browser pick promotes the browser's pick to the account; neither present means
    Imperial with **nothing written anywhere**. `promoteToAccount` is never non-null when `account`
    is non-null — that single condition is what stops a browser from overwriting a real choice made
    on another device.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → server render | The `shaper-units` cookie is written by client JavaScript and read by `app/layout.tsx` at render time. Its value is fully attacker-controlled for that attacker's own session. |
| browser storage → client render | `localStorage["shaper-units"]` is hand-editable and shared with any script on the origin. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | `readUnitsCookie` / `parseUnitsPreference` in `lib/units-preference.ts` | low | mitigate | Allow-list against the two members of `UNITS_SYSTEMS`; anything else returns `null` and the caller renders Imperial. The value is never evaluated, never used to build a query, and never rendered as markup — it only selects which pure formatter runs. Pinned by the junk-value cases in `lib/units-preference.test.ts`. |
| T-05-02 | Tampering | `localStorage["shaper-units"]` read in `components/units-provider.tsx` | low | mitigate | Same allow-list, inside a try/catch so a throwing or blocked storage degrades to Imperial rather than breaking the page. |
| T-05-03 | Information disclosure | the units cookie itself | low | accept | The cookie carries one of two public words describing how a shaper likes numbers written. It holds no identity, no session and no board data, so it is deliberately not `HttpOnly` (the browser must write it) and not `Secure` (so local development over http works). |
| T-05-04 | Denial of service | `app/layout.tsx` reading `cookies()` on every route | low | accept | Reading a cookie makes every route dynamically rendered. No package-legitimacy checkpoint is required because no package manager runs. |
