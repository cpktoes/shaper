<objective>
Make the board itself the control under a thumb.

A shaper presses a point on the drawing and it starts moving at once, the same way a mouse press
does today. The hit zones grow to a finger's width on a touch screen, and because bigger zones can
start to overlap on a short wide board, the point nearest the finger wins rather than whichever
circle happened to be drawn last. While the finger is down, a small card appears just above it
reading the same words and numbers as the sliders that point drives — `Width — 19 1/4"` and
`Offset — 2"` for the widepoint — so a shaper can see the number while their finger covers the
board. It goes the moment the finger lifts, and a mouse never sees it. And a long press can no
longer bring up iOS's text-selection popup in the middle of a drag.

On a desktop this changes nothing. The one delegated pick is the drag-start path for every pointer
type, and at the desktop's 15-pixel circles — which never overlap — it returns exactly the point
under the cursor. That is proved by a test rather than argued.

Purpose: PHON-04, the last piece of a shaper being able to shape a board on a phone; and closing the
phase's own paperwork now that Playwright is installed.
Output: both viewers rewired, the readout chip, a real touch-drag test, and an updated CLAUDE.md.
</objective>

<assumption_delta_decision surface="drag start">
**The noun that is now primary: one delegated nearest-point pick, not five per-circle press
handlers.**

Until this plan the app had exactly one input modality on the drawings — a mouse — and each drag
point owned its own transparent circle with its own `onPointerDown`. That was correct while circles
never overlapped. From here there are two modalities, and on a touch screen the circles can meet.

**Decision: promote.** The delegated pick becomes the single drag-start path for every pointer type.
Per-circle press handlers are removed rather than kept alongside for the mouse.

Rationale, and why not `add-alongside`: two drag-start paths would mean the desktop and the phone
could drift apart silently, and the one thing PHON-05 asks for is that they cannot. At the desktop's
15px radius no two circles overlap on any board in range (measured in 09-06), so nearest-wins
reduces to "the circle you are inside" — identical to today's behaviour, by construction rather
than by a preserved second branch. 09-06's desktop-invariant test asserts exactly that for all five
outline points and all four rocker handles, and `e2e/desktop-regression.spec.ts` re-proves the real
mouse drag end to end.
</assumption_delta_decision>

| Boundary | Description |
|----------|-------------|
| pointer coordinates -> which spec field a gesture changes | The drag-start path now decides this in app code rather than leaving it to browser hit-testing |

| test tooling -> the shipped bundle | CDP and Playwright code must stay outside the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-20 | Tampering | Synthetic or injected pointer events driving the drag | low | accept | This is a client-rendered board editor with no server-trusted state derived from pointer coordinates. A manipulated drag can only mis-set the shaper's own local board fields, which the existing clamp and quantise logic in the solvers already bounds — unchanged by this plan. |
| T-09-21 | Information Disclosure | Injection through the readout chip's text | medium | mitigate | The chip is SVG `<text>` children composed with template literals from the app's own fixed label strings and formatted numbers; no markup is built from a string and no raw HTML is injected. An acceptance criterion greps both viewers for a raw-HTML sink and finds none, continuing the posture already recorded for these two files. |
| T-09-22 | Tampering | A stale readout showing a value the board does not hold | medium | mitigate | The chip reads the spec the solver produced rather than the raw pointer position, so a clamped point reads its clamped value; the behaviour list makes that an explicit test case, and the chip unmounts on pointer cancel. |
| T-09-23 | Tampering | Test-only CDP code reaching the app bundle | medium | mitigate | The CDP call lives only in `e2e/touch-drag.spec.ts`; `e2e/` is outside every import path under `app/`, `components/` and `lib/`, and 09-01's criterion already greps that nothing there imports `@playwright/test`. |
| T-09-24 | Denial of Service | A NaN or out-of-range pointer coordinate from a corrupt saved design | low | mitigate | The pick returns null on a NaN distance (tested in 09-06), so no drag starts and the board is untouched. |
