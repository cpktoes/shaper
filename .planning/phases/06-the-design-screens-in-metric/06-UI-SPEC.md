# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase introduces **no new visual language**. Every element below reuses a pattern already
shipping in this codebase — `SliderRow`, `ImperialField`, `CalloutChip`/`OutputRail`, the rail/
rocker/fin/volume tables — made system-aware. The one genuinely new component is a typed
centimetre field (D-08) that is the exact structural sibling of `ImperialField`, built to the same
contract. Nothing here proposes a new colour, a new type size, or a new spacing token.

This document extends `.planning/phases/05-the-units-chooser/05-UI-SPEC.md` (the copywriting
composition rule — bare formatter output, unit added by the caller, two branches on `UnitsSystem`)
to the ~300 display sites CONTEXT.md's D-01 table names across the five design screens. **Every
resolution below is Phase 6 CONTEXT.md's own decision (D-01..D-12) restated in pixels and exact
strings**, or — where CONTEXT.md left it to "Claude's Discretion" — a concrete default flagged
**[ASSUMPTION]**, non-interactive-session style, exactly as Phase 5's UI-SPEC did.

support; Metric text is styled identically to the Imperial text it replaces at the same call site.
Verify in at least Daylight and one dark theme (Slate) per this codebase's established practice.

| Destructive/warning | `--surf-warning-ink` | Unchanged reservation: the Deck Profile clamp note (`SliderRow`'s `note` prop) and, newly, every typed-field error line (D-04's metric parser reverting bad input) — the exact same role `ImperialField`'s error line already plays, never a new warning surface |

No new accent surface, no new warning surface. Unit suffixes ("cm", "mm") are never their own
colour or weight — they sit in the same text run as the number they follow, same colour, same
weight, matching how the inch mark (`"`) already behaves today.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None new.** This phase converts existing sliders, fields, tables and callouts to read a second system; it adds no button, no submit, no new action. Every existing screen CTA (Import Template Values checkbox, Override button, View Full Sized, etc.) is untouched. |
| Empty state | **Not applicable.** Every slider, field, table cell and callout on the five design screens is driven by an already-populated `DesignState` field (outline/rocker/rails/fins/volume specs all carry real defaults from board creation onward) — there is no zero-data render for anything this phase touches, in either system. |
| Loading state | **Not applicable.** Every value is computed synchronously from in-memory geometry through `lib/geometry/units.ts`'s pure formatters — no fetch, no skeleton, no async gap between choosing a system and seeing it rendered (mirrors Phase 5's D-11/D-12 posture; `useUnits()` is already flash-free). |

| Error state — cm-domain typed field (D-08's Board Length field, the only standalone cm field) | `Couldn't read '{typed}' as centimetres — try a decimal like 188.0, or millimetres like 1880 mm.` — reuses D-08's own literal example values (`188`/`1880 mm`), so the error text and the worked example in CONTEXT.md agree. |

## Component Notes for the Planner/Executor

Prescriptive detail per CONTEXT.md's canonical refs, organized by the screens the phase notes list.

### The metric typed field (D-08, D-12)

Naming is the planner's call (a `MetricField` sibling of `ImperialField`, or one system-aware
`MeasureField` — CONTEXT.md leaves this open). The **visible contract** is fixed here regardless of
name:

- **Two render modes**, chosen by the caller, not by the field itself:
  - **Standalone** (D-08's three Board Length sites): blurred display reads the full string with
    unit — `188.0 cm` — reusing `ImperialField`'s exact `Input` classes (`h-7 w-16 min-w-16 max-w-16
    rounded-md border border-surf-line bg-surf-ground px-1.5 text-right text-sm text-surf-ink`). On
    focus, raw is seeded from that same suffixed string (`"188.0 cm"`), matching `ImperialField`'s
    own focus behaviour — `parseMetric`'s suffix-override already accepts a trailing `cm`/`mm` on
    the raw text, so nothing new is needed in the parser.
  - **Bare / in-table** (ROCKER datasheet Thickness/Rocker typed cells): blurred display reads the
    bare number only — `67` — because the table's own column header already carries the unit
    (`Thickness (mm)`). Add a boolean prop (e.g. `bare`) rather than a second component; the error
    line's copy is unaffected by which mode is active — it always names the unit in prose.
- **Snap and clamp**: every commit runs `parseMetric` → clamp to the caller's D-06 metric bounds →
  `roundToWholeMm` (mm fields) or the cm field's own whole-mm snap-then-cm-format (D-08: "snapped to
  whole mm") → `onCommit` → reformat. Exactly `ImperialField`'s commit pipeline, metric functions
  substituted for imperial ones.
- **Error line**: reuses `ImperialField`'s exact classes (`mt-0.5 w-24 text-right text-[10px]
  text-surf-warning-ink`); copy per the Copywriting Contract table above.

### Board Length control, three sites (D-08)

`outline-controls.tsx`, `fin-controls.tsx`, `volume-controls.tsx` each keep their existing label row
(`"Board Length — {value}"`, unchanged position/classes) and existing `Slider` underneath. Only the
middle row changes per system:

- **Imperial** (unchanged): the two `Select`s (feet, inches), `mb-2 flex gap-2`.
- **Metric**: one metric typed field (standalone mode) in the same `mb-2` row, sized to its own
  content rather than `flex-1 flex-1` — a single field does not need to split the row width the way
  two Selects did.

Slider bounds/step switch with the system (D-05, D-06): 1 cm step, bounds `153–304 cm` (outline/
volume) or `122–365 cm` (fins), each computed by the shared metric-bounds helper from the existing
inch constants — never a second hand-typed range.

### The five sidebars' sliders (D-05, D-06, D-07)

Every `SliderRow` call site (and the remaining hand-rolled pairs named in `slider-row.test.ts`'s
allowlist) gains a metric branch at its own call site — CLAUDE.md Rule 2's "no component converts
on its own" applies: the `value`/`min`/`max`/`step` handed to `SliderRow`/`Slider` are computed at
the call site from `useUnits()`, exactly the seam `SliderRow`'s own doc comment already describes.
Metric step is 1 mm for every non-length slider, 1 cm for length (D-05). Metric bounds are each
inch range's D-06 inward rounding — a single tested helper in `lib/geometry/units.ts` produces every
one of them; no screen hand-types a metric range constant.

Percent and degree sliders (Nose Angle, Fullness, Tail Rail %, Deck Profile %, Smoothness, Flatness,
Board Type, cant angles) are **untouched** — same label, same bounds, same step, in both systems
(D-01's "unchanged in both systems" list).

### ROCKER datasheet (`rocker-datasheet.tsx`) — D-03, D-10, D-12

- Column headers: station names gain the D-03 honest conversion — `Nose @ 30.5 cm` (never `@ 30
  cm`), formatted through `formatCentimetres` on the `MEASURE_STATION_MM` constant, not hand-typed.
- Row labels (first column): `Width (cm)`, `Thickness (mm)`, `Rocker (mm)` in Metric; unchanged
  bare `Width`/`Thickness`/`Rocker` in Imperial.
- Width row cells: bare `formatCentimetres` output (dims family, D-01).
- Thickness/Rocker typed cells: the metric field's **bare** mode (unit lives in the row label, not
  the cell).
- Derived cells (Nose/Tail @ 12→30.5cm, Center): bare `formatWholeMm` output, unchanged read-only
  styling.

### RAILS (`rail-controls.tsx`, `rail-data-table.tsx`, `rail-section-plot.tsx`) — D-01, D-10, D-11

- Per-section thickness sliders, Corner Cut, Bottom Tuck 3: mm-family sliders per D-05/D-06.
- `rail-data-table.tsx`: each section's column header (`Deck`, `Bottom`, `Rail`, …) gains ` (mm)`
  in Metric — **[ASSUMPTION]**: CONTEXT.md's "Claude's Discretion" left the exact placement (per
  column vs. the group heading) open; per-column suffix was chosen because D-10's literal phrasing
  ("gets `(mm)` on its headers", plural) matches the multiple section-title columns more directly
  than the single blank corner cell, and it costs nothing extra since every table already scrolls
  horizontally at a fixed `min-w`. Cells stay bare (`formatCell` reads `formatWholeMm` output).
- `rail-section-plot.tsx`: the grid pitch changes from the current 1-inch spacing (`Math.floor`
  inch loop) to a 10 mm pitch in Metric (D-11) — this is a real change to the tick-generation loop,
  not just a label swap; the planner should parameterize `xGridMin`/`yGridMax`'s step by system
  rather than assuming whole units. Tick labels stay bare numbers (`0, 10, 20…`) except **one tick
  per axis** gains the `mm` suffix — **[ASSUMPTION]**: the first non-zero tick outward from the
  origin on each axis (e.g. the x-axis's first tick reads `10 mm`, the y-axis's first tick reads
  `10 mm`, every other tick on that axis stays bare) — chosen because it is the tick nearest where a
  shaper's eye starts reading outward from the board's corner, and it keeps every other label
  uncluttered. Imperial keeps its current whole-inch grid with no unit shown anywhere (unchanged).

### FINS (`fin-controls.tsx`, `fin-viewer.tsx`, `fin-data-panel.tsx`, `toe-aim-table-modal.tsx`) — D-01, D-02, D-03, D-09

- Tail Width `@ 12"` sidebar label and slider: becomes `Tail Width @ 30.5 cm` (D-03). Per D-01's
  table, fin tail width at the station is a **cm**-family value ("fins tail width `@ 30.5 cm`"
  appears in the cm row of D-01's table), so the value itself reads in cm to one decimal (`36.8
  cm`, never a stripped whole number per Phase 5 D-01) — only the station name uses the honest
  `30.5 cm` conversion.
- `BaseLengthField` (`fin-controls.tsx`): editing-mode `type="number"` input switches to an mm-domain
  number (whole mm, step 1, D-06 bounds `64–190`); the label above is unchanged text, the blurred
  display reads `{formatWholeMm} mm` + `" standard"` when un-overridden, matching today's `{inches}"
  standard` shape exactly.
- `fin-data-panel.tsx` summary line and `toe-aim-table-modal.tsx` title: composed strings per the
  Copywriting Contract's Fixed Strings table above — both follow the D-09 own-unit-per-value rule
  (`188.0 cm · 36.8 cm tail`, never a single trailing unit for two different numbers).
- `toe-aim-table-modal.tsx` headings: literal `(in)` → `(cm)` in Metric (D-10); the table's own
  numeric cells come from `lib/geometry/fins.ts`'s `toeAimTableFor` — the planner should make that
  view system-aware (still returning pre-formatted display strings) rather than reformatting in the

- Fin placement callouts (`fin-viewer.tsx`): toe-in and off-rail read mm-family (D-01); lateral
  fin-off-tail positions read cm-family — composed the same way `outline-viewer.tsx`'s callouts are

### VOLUME (`volume-controls.tsx`, `volume-calculation-card.tsx`) — D-01, D-04

- Board Length (D-08's third site), Board Width, Center Thickness sliders: all **cm-family** here
  specifically (D-01's table: "The VOLUME screen's Board Length / Board Width / Center Thickness
  sliders — the three headline dims, so centre thickness reads `6.7 cm` here") — note this is the
  one place centre thickness reads cm rather than mm, because it is being quoted as a size input,
  not a foil-derived mark; the same physical value reads `67 mm` on the volume card's own
  cross-section rows below (mark family) and `6.7 cm` on this screen's own slider (dims family) —
  D-01's explicit worked example.
- `VolumeCalculationCard`: area line → `{cm²}`, cubic supporting line → `({cm³})`, per the Fixed
  Strings table; the three cross-section thickness rows and the weighted-thickness row are
  mark-family (`formatWholeMm`), per D-04/D-01. New `squareMmToSquareCentimetres` / cm³ conversions
  land beside `squareMmToSquareInches` in `lib/geometry/units.ts` — never a component-level `/ 100`.
  Number styling (decimal places, no thousands separator) matches today's `toFixed` conventions
  exactly — **[ASSUMPTION]**: CONTEXT.md left "number styling of the area/volume lines" to
  discretion; matching the existing imperial `toFixed(1)`/`toFixed(2)` precision keeps the two
  branches visually parity, e.g. `7964 cm²` (whole, matching `1234.5 sq in`'s one-decimal precision
  would read `7964.0 cm²` — since a cm² value this large has no meaningful tenths a shaper would
  cut to, a whole-number cm² display is chosen; litres precision is unchanged, `toFixed(1)`/
  `toFixed(2)` for cm³ following the existing `cu in` line's whole-number style).
- Litres figure itself: **byte-identical in both systems** (SCRN-05) — no change anywhere.
