<objective>
The shaper reported it plainly: "the print button here results in a very poorly laid out print
screen." Printing the actual-size rail today puts the check bar, the caveat line and the left three
inches of the drawing off the edge of the paper, because the dialog carries its on-screen centring
onto the page. This plan puts the whole dialog on the page and keeps what prints at true size.

Purpose: RAIL-04 and D-15. A drawing a shaper cuts foam to is only worth printing if all of it
lands on the paper at the size it claims. Half a rail at true size is worse than no rail.

Output: the print path for the View Full Sized dialog, fixed in three places — the centring reset,
a page shaped to fit an 8.69 in drawing, and the sign-in banner kept off the sheet.
</objective>

  <action>
    Two changes, both inside the existing print path. Neither touches `components/ui/dialog.tsx`:
    the shared dialog primitive centres every other dialog in the app correctly, and this is a
    rails-print problem.

    **(a) Reset the centring the print rule missed.** In `app/design/rails/actual-size.css`, extend
    the existing `[data-view-full-sized-dialog]` rule inside `@media print` with
    `translate: none !important`. Tailwind v4 compiles `-translate-x-1/2 -translate-y-1/2` to the CSS
    `translate` property, not to `transform`, so the rule's existing `transform: none !important`
    never reached it and the now-statically-positioned popup kept an offset of half its own width and
    half its own height. Record that reason in a comment beside the declaration — the next person to
    read this rule will otherwise see two lines that look like the same reset written twice.

    In the same rule, drop the popup's screen-only furniture for print: its padding to zero, its ring
    and any box shadow off, its corner radius flat, and its background plain white. On paper the
    printable width is the scarce resource and every millimetre of it belongs to the drawing, not to
    a dialog's rounded card. Leave the header, footer, tab strip and close button alone — they are
    already hidden by the rules above.

    **(b) Give the drawing a page it fits without being shrunk.** The true-size rail is 8.69 in wide
    for the default board — wider than portrait Letter or A4's printable width — and Chrome answers
    an over-wide page by scaling the entire page down (measured at 82%), which no print-dialog
    setting turns off. So while the dialog is open, the page must be landscape: 10.37 in of printable
    width on Letter and 11.06 in on A4 at an 8 mm margin, both comfortably clear of 8.69 in.

    `@page` cannot be scoped by a selector, so it cannot be written into `actual-size.css` without
    making every rails-screen print landscape — which would break the closed-dialog no-op contract
    (WR-01) that file's head comment sets out. Render it from the component instead: inside
    `DialogContent`, render a plain `style` element whose content is a single `@page` block asking
    for landscape orientation and an 8 mm margin. Base UI mounts the popup only while the dialog is
    open, so the rule exists in the document exactly while the dialog does and disappears with it.

    Give that element no `href` and no stylesheet-precedence prop: React 19 hoists a stylesheet
    carrying those into the document head and leaves it there after unmount, which would silently
    make every later print of the rails screen landscape. It must be an ordinary in-place style
    element that unmounts with the dialog. If the rule turns out not to apply from the popup's
    position in the document, the sanctioned alternative is an effect keyed to the dialog's `open`
    state that appends the same element to `document.head` and removes it on cleanup — same
    lifetime, same single rule, no other behaviour.

    Explain both changes in the file comments the way this repo already does: what a shaper gets
    (a printed rail they can lay on foam), not which property won the cascade.
  </action>
