# Shaper

A web app for designing surfboards. Users set overall dimensions, then shape an outline
curve, rail contour, foil and fin placement — with rail-band dimensions, fin placement and
volume **calculated** from real shaping formulas rather than hand-drawn. Designs are saved
as named models (saving lands in Phase 2 — see `.planning/ROADMAP.md`).

**Users are shapers and surfers, not developers.** Explain every change in plain English:
what it does to the board or the screen, not which component re-renders. That applies to
answers, commit messages and summaries alike.

## Stack

- Next.js 16 (App Router) + React 19 + TypeScript (strict mode)
- Tailwind CSS v4, shadcn/ui components built on Base UI, lucide-react icons
- Vitest for unit tests — `lib/**/*.test.ts`, node environment
- Deployed on Vercel from `main` → https://shaper-coral.vercel.app

Prescribed but **not installed yet**: Clerk auth and Neon Postgres via Drizzle (Phase 2),
Playwright (Phase 3). Board state currently lives in React context only and resets on
reload.

## Commands

```bash
npm run dev     # dev server on localhost:3000
npm test        # vitest run — all geometry suites must stay green
npm run build   # run from the main checkout; Turbopack won't resolve next in a worktree
npm run lint
npm run golden  # regenerate geometry fixtures from the prototype in reference/
```

## Rule 1 — geometry math lives in `lib/geometry/`, pure and tested

The calculators *are* the product: a shaper has to trust these numbers enough to cut foam
to them. So every formula belongs in `lib/geometry/` — `board.ts` (types), `outline.ts`,
`rail-bands.ts`, `fins.ts`, `volume.ts`, `presets.ts`, `units.ts`.

- No React, browser API or database imports in those files, so the math can be verified in
  isolation from the UI.
- Every exported function gets unit tests. Never inline a formula in a component.
- Expected values come from `lib/geometry/__fixtures__/*-golden.json`, generated by
  `scripts/extract-prototype-*-golden.mjs` executing the original prototype's own
  functions. Never hand-transcribe an expected number — regenerate the fixture.

## Rule 2 — inches and litres on screen, metric in the data

Shapers think and talk in inches and litres, so that is what the UI shows. Everything
stored or computed is metric, using the branded `Mm` / `Degrees` / `Litres` types.

Every conversion of a *design value* — in from a control, out to a label — goes through
`lib/geometry/units.ts`, including imperial-fraction formatting. Don't reach for 25.4
anywhere else. (`components/summary/use-print-fit.ts` has its own copy on purpose: it
scales paper sizes, not board dimensions.)

## Layout

- `app/design/{outline,rails,fins,volume,summary}/` — the five design screens
- `components/design/design-store.tsx` — the shared board-design state
- `components/{outline,rails,fins,volume,summary}/` — per-screen UI
- `reference/project/` — the original Claude Design prototype; source of truth for formulas
- `.planning/` — GSD roadmap, phase plans and quick-task log
